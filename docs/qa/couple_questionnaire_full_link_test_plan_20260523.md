### 1.1 测试分层

| 层级 | 覆盖目标 | 本次新增/更新 |

| 静态契约检查 | 不依赖 DB/HTTP 运行时，验证接口、状态、权限、发送记录、通知跳转、版本快照、失败态是否存在 | 新增 `tests/qa/couple_questionnaire_flow_contract_checks.js`，当前复跑 15/15 通过；此前暴露的 3 个 GAP 已由成员补齐或同步，并转为回归守护；后台分页运行时风险移至第 4.1 节跟踪 |

### 1.2 质量门禁建议

- P0 必过：任务创建唯一、服务人员权限隔离、发送记录/通知、用户归属校验、单次提交/重复提交不覆盖、版本快照可追溯、小程序详情失败可恢复。
- P1 必过：发送失败可重试并记录失败原因、过期/撤回规则一致、OpenAPI/状态机/SQL/前端枚举同步。
- 上线前必须至少执行：`node tests/qa/couple_questionnaire_flow_contract_checks.js`、`node tests/qa/p0_p1_p2_contract_checks.js`、后台 type-check/build、小程序 type-check/build 或开发者工具预览。

## 6. 上线前人工验收清单（预发/真实小程序）

- [ ] 准备服务人员 S、用户 U、订单 O；S 发布 v1 问卷，记录 `version_no`。
- [ ] O 支付成功进入待服务后，后台任务列表出现唯一任务，字段含订单、用户、服务人员、版本、发送状态。
- [ ] 自动/手动发送后，站内通知出现在 U 的消息中心，点击直达 `/packages/pages/couple_questionnaire/detail?id=...`。
- [ ] 小程序订单详情出现“新人问卷待填写”卡片，点击进入同一任务。
- [ ] 小程序新人问卷列表可看到任务，并支持全部/待填写/已填写筛选。
- [ ] 断网/接口 500/登录失效/无效 id 打开详情，页面有错误态、重试和返回路径。
- [ ] 留空必填项提交失败，提示具体题目；填写合法答案后提交成功。
- [ ] 快速双击提交或重复 POST，不新增第二条答案、不覆盖第一次答案。
- [ ] 提交后重新打开详情，答案只读、提交按钮消失；后台任务详情可看到答案和题目快照。
- [ ] 发布 v2 后再打开 v1 已创建/已发送任务，按最终产品口径验证题目不被意外污染。
- [ ] 过期任务不可提交；若支持撤回，撤回后用户不可提交且显示原因。
- [ ] 模拟发送失败，后台展示失败状态/失败原因/下次重试时间；重试成功后状态恢复已推送。
- [ ] 服务人员 S2 不能查看或发送 S1 的任务；管理员可查看全量。
- [ ] 微信订阅消息授权拒绝不阻断用户填写主流程；如使用微信订阅模板，验证真机收到/未收到时的兜底入口。
