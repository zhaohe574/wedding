# 三端治理路线图

## P0 验收

- 状态机与 API 契约：支付回调、订单状态、档期锁、问卷任务状态必须有共享契约和静态检查。
- 后端关键链路：订单、支付、活动报名、退款和档期占用必须能通过 `npm run qa:contracts` 回归。

## P1 验收

- CRM P1 验收：客户、跟进、顾问、流失预警四条链路必须保持前后端接口闭环。
- Admin 页面壳一致性：核心后台列表页统一接入页面壳、搜索区和内容区结构。
- PC 展示优化：PC 端保持品牌展示和联系导流定位，不扩展预约下单和支付链路。

## P2 验收

- 移动端组件治理：统一反馈工具、清理孤儿组件、避免新增直接散落的交互提示。
- 质量入口：根目录 `qa:contracts` 是三端治理的固定验收入口，GitHub Actions 不直接绕过根级命令。
