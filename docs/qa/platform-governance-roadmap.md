# 三端治理路线图与验收清单

## P0：一致性与质量入口

### Admin 页面壳一致性

- 核心业务页必须使用 `admin-page-shell`，筛选区进入 `#search`，统计区进入 `#stats`，表格与主体内容使用 `admin-page-section`。
- 第一批强制范围：订单、档期、财务、售后、人员、CRM 四个核心页。
- 未迁移页面必须在后续清单中说明豁免原因，不允许新增核心业务页继续使用裸 `el-card` 作为页面根结构。

### PC 展示优化

- PC 端保持企业展示定位，不新增预约、订单、支付链路。
- 全局 `Element Plus` 主色跟随黑金展示主题，禁止回退到脚手架蓝色。
- 首页首屏必须提供展示型行动入口，落到联系信息、案例展示或后台可配置联系组件。

### 自动化测试入口

- 根目录 `npm run qa:contracts` 统一执行核心可靠性、问卷全链路和三端治理静态合同。
- CI 只能调用根级 QA 命令，避免工作流与本地命令分叉。
- 失败输出必须能直接定位缺失文件、缺失字段或不符合约束的页面。

## P1：移动端、CRM、状态机与契约

### 移动端组件治理

- 页面结构优先沿用 `PageShell`、`BaseNavbar`、`BaseCard`、`BaseButton`、`EmptyState` 和自定义 tabbar。
- 统一 toast/modal 入口为 `uniapp/src/utils/feedback.ts`，后续优先迁移订单、支付、售后、问卷、CRM 相关入口，避免页面内继续散落 `uni.showToast` / `uni.showModal`。
- `BasePicker` 当前未被真实页面引用，本轮已按孤儿组件清理；后续如需通用选择器，应基于真实表单场景重新设计。

### CRM P1 验收

- 客户管理覆盖客户状态、意向等级、来源渠道、顾问分配、转移原因、问卷任务跳转。
- 跟进记录覆盖跟进方式、结果、意向变化、下次跟进时间、重要标记和顾问权限范围。
- 顾问管理覆盖最大客户数、当前负载、活跃客户数、状态切换、客户数校准和删除前约束。
- 流失预警覆盖定时生成、待处理推送、处理/忽略、风险等级、未跟进天数和企业微信提醒。

### 状态机与 API 契约

- 订单、档期、支付、退款、问卷、CRM 客户跟进状态必须在文档、模型常量和静态合同检查中保持一致。
- `docs/contracts/openapi-core.yaml` 作为核心接口契约入口，新增字段或错误语义时同步更新。
- 不先强改数据库字段；先用文档和合同检查固化行为，再按缺口补索引或迁移。

## P2：文档与持续质量

- `CLAUDE.md` 保持“项目事实、运行命令、质量门禁、业务边界、禁改目录、常见排障”结构。
- 发布验收包必须包含三端核心流程截图、命令输出、合同检查结果和已知风险。
- 每次新增业务模块时，同步补充页面壳、接口契约、状态机和 QA 合同检查。
