## 1. 现状代码审查（7 大核心缺陷）

在重构前对旧版 `newuniapp/src/packages/pkg-user/pages/activity/activity.vue` 与后端 `ActivityRegistrationService.php`、数据表 `like.sql` 逐行比对，发现以下阻断级缺陷：

1. **字段名与时间格式严重错位**：
   - 旧前端读取 `d.start_time / d.end_time / d.activity_time / d.city_name / d.address` 并直接 `string.slice(5, 10)`。
   - 后端 `la_dynamic` 实际只返回 **Unix 秒级时间戳** `activity_start_time` 与地点 `location`，且根本没有 `end_time` 字段。导致日期格显示 `NaN`/异常切片、倒计时失效、「已结束」永远判定为 `false`。
2. **分段筛选完全失效**：
   - 模板 `v-for="r in rest"`（始终渲染 `list` 除去置顶的一条），计算属性 `shown` 从未被模板消费，点「待参加 / 待支付 / 已结束」视觉上不会切换任何列表。
3. **状态标签把正常票误标为「未申请」**：
   - `ActivityRegistration::getCancelStatusText(0)` 返回 `'未申请'`，旧代码 `if (String(r.cancel_status_desc || ''))` 把所有未取消的正常报名都渲染成了灰底「未申请」标签。
4. **置顶「即将参加」卡状态溢出**：
   - `nextUp` 只过滤了 `!isFinished(r) && !isPendingPay(r)`，导致「已取消（3）」「取消审核中（2）」「退款处理中（4）」「退款失败（5）」全部能挤进置顶深墨卡。
5. **入场码完全虚构**：
   - 前端依次尝试读取 `r.entry_code || r.checkin_code || r.ticket_no`，数据库 `la_activity_registration` 没有任何码字段，弹窗永远显示 `—`，现场无法核销。
6. **取消与退款闭环断裂**：
   - 只有 `pending_pay` 卡片有「取消」按钮且硬编码 `reason: '用户主动取消'`；已报名（`status=1`）和退款失败（`status=5`）无取消入口；`cancel_reject_reason` 和 `latest_refund` 进度从未展示；且待支付记录取消在旧后端也要走人工审核。
7. **缺少报名详情承载与分页/回页刷新**：
   - 点待支付卡直接拉起微信支付（容易误触），点其他卡直接跳 `feed-detail`，没有地方看联系人、报名编号、支付金额、取消/退款记录；且缺少 `onReachBottom` 分页与 `onShow` 回页同步；旧链接 `/packages/pages/activity_registration/detail?id=xxx` 的 `id` 参数也被丢弃。

## 2. 全栈扩展与接口契约

### 2.1 数据库迁移（`server/database/migrations/20261122_activity_checkin_and_endtime.sql`）

1. `la_dynamic` 新增：
   - `activity_end_time int(10) unsigned NOT NULL DEFAULT '0' COMMENT '活动结束时间'`（为 `0` 时后端按 `activity_start_time + 86400` 兜底判定已结束）
2. `la_activity_registration` 新增：
   - `checkin_code varchar(16) NOT NULL DEFAULT '' COMMENT '8位唯一入场核销码'`（字符集 `23456789ABCDEFGHJKLMNPQRSTUVWXYZ`，去除 `0/O/1/I/L` 易混淆字符）
   - `checkin_status tinyint(3) unsigned NOT NULL DEFAULT '0' COMMENT '0=未签到, 1=已签到'`
   - `checkin_time int(10) unsigned NOT NULL DEFAULT '0' COMMENT '签到核销时间戳'`
   - `checkin_operator_type tinyint(3) unsigned NOT NULL DEFAULT '0' COMMENT '0=无, 1=管理员, 2=服务人员'`
   - `checkin_operator_id int(10) unsigned NOT NULL DEFAULT '0' COMMENT '核销操作人ID'`
   - 索引：`idx_checkin_code(checkin_code)`、`idx_checkin_status(checkin_status)`
3. 存量回填与后台 RBAC 登记：
   - 存量 `registration_status = 1 AND checkin_code = ''` 自动回填唯一 8 位核销码。
   - `la_system_menu` 幂等登记 `growth.dynamic/activityCheckinPreview` 与 `growth.dynamic/activityCheckin`。

### 2.2 取消与退款业务规则（`ActivityRegistrationService::applyCancel`）

| 当前报名状态 | 条件 | 取消模式 | 后端动作 |
| :--- | :--- | :--- | :--- |
| `0` 待支付 | 随时（未过期） | **直取消** (`direct`) | 无需理由，未付流水置失败，立即释放票种库存与活动名额，状态置 `3 已取消` |
| `1` 已报名（免费票） | `checkin_status = 0` 且活动未开始 | **直取消** (`direct`) | 无需理由，立即释放库存与名额，状态置 `3 已取消` |
| `1` 已报名（付费票） | `checkin_status = 0` 且活动未开始 | **申请审核** (`audit`) | 必须填写 `reason`，状态置 `2 取消审核中`，生成 `ActivityRefund(0 待审核)` |
| `1` 已报名 | `checkin_status = 1` 或已过活动开始时间 | **不可取消** (`none`) | 返回 `can_cancel = 0` 与具体拦截提示 |
| `5` 退款失败 | 随时 | **申请审核** (`audit`) | 必须填写 `reason`，允许重新提交审核退款 |

### 2.3 API 列表与核销端点

- **用户端 `GET /api/dynamic/activityRegistrations`**：
  - `status_group`：`all`（全部）｜`upcoming`（待参加：已报名且未结束）｜`pending_pay`（待支付）｜`history`（历史记录：已结束 + 取消/退款态）；兼容旧枚举 `registered` / `cancel_refund`。
  - 保留 ThinkPHP 分页结构（`data` / `total` / `current_page` / `last_page` / `per_page`），追加：
    - `counts`: `{ all, upcoming, pending_pay, history }`
    - `next_up`: 最近一场已报名且未结束的活动记录（跨分页置顶展示）
  - 单条记录扩展：`checkin_code`、`checkin_status`、`checkin_status_desc`、`checkin_time`、`pay_deadline_time`、`pay_remain_seconds`、`activity_start_time`、`activity_end_time`、`activity_location`、`activity_cover`、`is_activity_ended`、`can_cancel`、`cancel_mode`、`cancel_disabled_reason`。
- **用户端 `POST /api/dynamic/activityCancelApply`**：`reason` 仅在 `audit` 模式下必填，`direct` 模式可省略。
- **Admin 端**：`GET /growth.dynamic/activityCheckinPreview`、`POST /growth.dynamic/activityCheckin`。
- **Staff 端（服务人员）**：`GET /api/staff_center/activityCheckinPreview`、`POST /api/staff_center/activityCheckin`（验证 `StaffCenterLogic::getStaffId($userId) > 0`）。
