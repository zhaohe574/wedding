# 人员详情页 UI 重设计方案

> 范围：UI 规划、高保真预览与落地实施记录（2026-11-10 已实施）。
> 依据：`la_staff` 轮播配置、`la_staff_banner` 轮播条目、`la_staff.long_detail` 长图详情，以及 `newuniapp/src/packages/pkg-catalog/pages/staff-detail/staff-detail.vue` 现状。
> 目标：让「可配置高度的轮播」和「后台装修的长图详情」在同一页里各自成立，且不破坏现有三页签与吸底预约。

---

## 0. 一句话结论

把现在「一张固定 615rpx 头图 + 姓名压在图上」改成：

**可配置高度的轮播舞台 → 上浮身份卡 → 三页签 → 文末无缝长图详情 → 吸底预约**

轮播高度只由后台 `banner_mode + banner_small_height + banner_large_height` 决定；长图详情严格按后台 `long_detail` 的块顺序渲染，图片块全宽无间距，文本块走正文栏宽。

---

## 1. 后台配置盘点

### 1.1 全局轮播配置（`la_staff`）

| 字段 | 类型 / 默认 | 后台文案 | 对应展示形态 | 约束与兜底 |
|---|---|---|---|---|
| `banner_mode` | tinyint，默认 `1` | 展示模式：小图 / 大图 | `1` = 初始小图，可展开；`2` = 固定大图，不展开 | 非 `1/2` → 按 `1` 处理 |
| `banner_small_height` | int，默认 `400` | 小图初始高度（200–800rpx） | 小图模式下的初始舞台高度 | ≤0 或缺失 → `400`；渲染下限 `280rpx`（低于此值指示器与展开按钮会挤进导航区） |
| `banner_large_height` | int，默认 `600`，后台最小 300 | 小图模式的「展开后高度」/ 大图模式的「固定高度」 | 展开态或大图态的舞台高度 | ≤0 → `600`；`large ≤ small` 时不出现展开入口，等同固定高度；渲染上限 `960rpx` 且不超过视口 `58%` |
| `banner_indicator_style` | tinyint，默认 `1` | 指示器：圆点 / 数字 / 进度条 / 长条形 / 无 | 5 种指示器形态 | 不在 `0–4` → `1`；只有 1 张时全部隐藏 |
| `banner_autoplay` | tinyint，默认 `1` | 自动轮播 | 是否自动切换 | 只有 1 张或含视频时按 §4.4 降级 |
| `banner_interval` | int，默认 `3000` | 轮播间隔（1000–10000ms） | 自动切换节奏，也是进度条的动画时长 | <1000 → `3000` |

### 1.2 轮播条目（`la_staff_banner`）

| 字段 | 取值 | 展示形态 | 约束 |
|---|---|---|---|
| `type` | `1` 图片 / `2` 视频 | 图片直接铺满舞台；视频显示封面 + 播放键 | 未知类型跳过该条 |
| `file_url` | 图片或视频地址 | 图片作为画面；视频作为播放源 | 图片空 → 跳过；全部为空 → 走 §4.6 兜底 |
| `cover_url` | 视频封面 | 视频未播放时的画面 | 为空 → 用 `file_url` 首帧不可靠时改用人员 `cover/avatar` |
| `is_autoplay` | `0/1` | 视频进入该页时是否静音自动播放 | 仅对当前激活的视频页生效，离开即暂停 |
| `sort` | int | 升序排列 | 同 `sort` 按 `id` 升序，保证顺序稳定 |

### 1.3 长图详情（`long_detail`）

后台是「块编辑器」，存 JSON 数组，只有两种块：

```json
[
  { "id": "1", "type": "text", "content": "……", "style": { "align": "left", "fontSize": "md", "color": "#1E2432", "bold": false } },
  { "id": "2", "type": "image", "images": ["https://…/1.jpg", "https://…/2.jpg"] }
]
```

| 块 | 字段 | 展示形态 | 约束 |
|---|---|---|---|
| 图片块 | `images[]` | 按数组顺序**首尾无间距**连续铺满整宽 | 单块内不插间距、不裁切、不加圆角 |
| 文本块 | `content` | 正文段落，按 42rpx 栏宽排版 | 最长 3000 字 |
| 文本样式 | `style.align` | `left / center / right` | 非三值 → `left` |
| 文本样式 | `style.fontSize` | `sm / md / lg` | 非三值 → `md` |
| 文本样式 | `style.color` | 6 色板 | 非法值 → `#1E2432` |
| 文本样式 | `style.bold` | 加粗 | 布尔 |

后台编辑器明确写了「图片会按顺序无间距展示」，这是长图详情的设计前提，前台不能自作主张加卡片、加圆角、加间距。

### 1.4 现状与契约缺口（设计落地前必须补齐）

| 问题 | 现状 | 影响 | 设计侧要求 |
|---|---|---|---|
| v2 聚合丢字段 | `/v2/staff/detail` 的 `banner` 只有 `small_height / large_height / list` | 指示器样式、自动轮播、间隔、`banner_mode`、`long_detail` 全拿不到 | 详情页若继续走 v2，需补 `mode / indicator_style / autoplay / interval / long_detail`；否则轮播与长图只能走 v1 |
| 轮播字段名不一致 | 页面 `heroImage` 读 `first.image / first.url`，接口实际是 `file_url / cover_url` | 有轮播数据时第 1 张也落不到 hero，最终退到 `cover/avatar` | 轮播统一读 `type / file_url / cover_url` |
| 长图旧数据 | `optimizeLongDetailContent` 只处理 JSON；非 JSON 原样返回 | 历史纯文本/HTML 会整段不渲染或误渲染 | 非 JSON 按纯文本分段兜底；HTML 需白名单清洗或降级为纯文本 |
| 剩余档数缺失 | 详情接口只有 `schedule_available` + `message`，无 `schedule_remaining` | 无法区分「可约」与「仅 1 档」 | 首版只做三态；要显示「仅 1 档」需补字段 |
| 高度单位 | 后台配置是 rpx，设计基准 750 | 大屏上 `600rpx` 会变成 600px，吞掉整屏 | 渲染时按 §2.2 加视口上限 |

## 2. 配置到展示形态的映射

### 2.1 两种模式

```
小图模式（banner_mode = 1）                大图模式（banner_mode = 2）

┌──────────────────────────┐              ┌──────────────────────────┐
│                          │              │                          │
│   轮播舞台 small_height   │              │                          │
│                          │              │                          │
├──────────────────────────┤  ← 展开      │   轮播舞台 large_height   │
│                          │              │      （固定，不展开）      │
│   展开后 large_height     │              │                          │
│                          │              │                          │
└──────────────────────────┘              └──────────────────────────┘
```

- 小图模式是「先给页面留一口气，想看大图再展开」；适合首屏还想露出身份卡与页签的情况。
- 大图模式是「以影像为主」；适合作品本身很强、详情页愿意让图片占首屏一半以上。
- 两种模式共用同一套指示器、身份卡、页签，切换配置不会改变页面结构，只改变舞台高度和一个展开入口。

### 2.2 高度规则

后台给的是 750 设计宽下的 rpx；前台不能直接当像素用。

```
raw   = mode === 2 ? large_height : small_height
base  = clamp(raw, 280, 960)                     // rpx
px    = base * viewportWidth / 750               // 转当前屏宽
final = min(px, viewportHeight * 0.58)           // 视口上限
```

| 屏宽 | `small=400` | `large=600` | `large=800` | 说明 |
|---|---|---|---|---|
| 320 | 171px | 256px | 341px | 320×640 下 800rpx 仍低于 58vh（371px） |
| 375 | 200px | 300px | 400px | 标准档 |
| 390 | 208px | 312px | 416px | 预览基准 |
| 430 | 229px | 344px | 459px | 大屏自然放大 |
| 750（平板） | 400px | 600px → 触顶 58vh | 800px → 触顶 58vh | 必须有上限，否则 800rpx 会变 800px |

**为什么下限是 280rpx**：后台允许 `small_height = 200`，但 200rpx 在 390 屏上只有 104px。指示器需要距底约 30px、展开按钮高 26px，再加身份卡上浮 21px，控件会直接挤进 88px 的导航区。280rpx（约 146px）是「指示器、展开按钮、身份卡」三者互不打架的最低值，而不是随意定的审美值。

**为什么上限是 960rpx + 58vh**：`large_height` 后台只设了最小值、没有最大值。没有上限时，运营填 1200 就能让首屏只剩轮播图。58vh 保证首屏至少露出身份卡的上半部分，形成「下面还有内容」的暗示。

### 2.3 指示器 5 态

| 配置 | 形态 | 位置 | 细节 | 数量规则 |
|---|---|---|---|---|
| `1` 圆点 | 圆点组 | 左下 32rpx / 底 60rpx | 未选 8rpx、白 45%；选中拉长成 22rpx 胶囊、白 95% | 5 张以内用圆点；>5 张仍可用，但更推荐数字 |
| `2` 数字 | `02 / 05` | 左下 24rpx / 底 52rpx | serif 22rpx，字距 2rpx；带 24% 墨色胶囊底 + 细白边，白字 96%；斜杠白 45% | 任意数量；视频页显示播放小标 |
| `3` 进度条 | 分段进度条 | 左下 32rpx / 底 58rpx | 每段 36×4rpx、间距 8rpx；轨道白 32%，已播白 95%；当前段按 `interval` 匀速填满 | 段数 = 图片数；超过 8 张时每段缩到 24rpx |
| `4` 长条形 | 单条连续轨道 | 左下 32rpx / 底 58rpx | 轨道 120×4rpx，白色填充按 `interval` 从 0 到 100%，切换即重置 | 只表达「当前这张还剩多久」，不表达总数 |
| `0` 无 | 不渲染 | — | 仍保留读屏文案「第 2 张，共 5 张」 | — |

**统一约束**：所有指示器都落在左下角、同一基线，右侧留给「展开/收起」。这样运营切换样式时，页面不会因为指示器变宽而挤压按钮。

### 2.4 视频条目

- 默认显示 `cover_url` + 中央 96rpx 播放键（半透明墨色圆 + 白三角）。
- 点击播放：进入全屏播放器，**不在轮播位内直接播放**。原因是详情页轮播高度只有 200–400px，内嵌播放会把控件压得没法用。
- `is_autoplay=1` 只表示「滑到这一页时静音循环播放」，且必须同时满足：页面在前台、用户没有手动暂停、没在拖动。默认仍建议运营关闭，避免婚礼现场视频突然出声。
- 视频页不参与 `banner_autoplay` 的自动翻页计时，播完停在当前页，避免用户刚要看就被翻走。

### 2.5 缺省与降级

| 场景 | 处理 |
|---|---|
| `banners = []` | 有 `cover`：全宽铺；只有 `avatar`：暖米底 + 居中 208rpx 方图（方头像直接 aspectFill 全宽会只剩胸口）；隐藏指示器与展开入口；高度按当前模式取 `small/large` |
| 只有 1 张 | 不自动轮播、不显示指示器；小图模式仍可展开（展开的是同一张图） |
| 某张图片加载失败 | 该页从轮播序列移除并重排索引；全部失败 → 走单图兜底；不显示破图 |
| 视频封面缺失 | 用人员 `cover/avatar` 作为封面；仍无 → 该页移除 |
| 配置值非法 | 按 §1.1 的兜底值渲染，不白屏、不报错 |
| 轮播接口为空但 `long_detail` 有内容 | 轮播走兜底，长图照常渲染；两者互不阻塞 |

### 3.3 为什么把身份信息从图上移到卡里

现状是 615rpx 的 hero，姓名、职级、评分、标签全部压在图片底部。这个做法在 615rpx 时成立，但在 `small_height = 400rpx` 时：

- 400rpx ≈ 208px，减去 44px 导航，只剩 164px；
- 姓名块本身约 96px，再加底部 46rpx 内边距，图片实际可见不到 80px；
- 婚礼照片的高光区多在画面中部，姓名压上去后既看不清脸，也读不清字。

移到身份卡后：

- 舞台只负责「看」，卡只负责「读」，两者不再互相挤压；
- 图片可以用更轻的遮罩，保留婚礼现场的高光与暖调；
- 姓名、评分、可约状态在暖白底上对比度稳定，不再受图片明暗影响；
- 身份卡上浮 40rpx，仍然保持「图片托着人」的层次，不会变成普通列表头。

## 4. 轮播区设计

### 4.1 舞台与安全区

- 全宽 100%，无左右边距、无圆角；底部被身份卡压住 40rpx，形成自然的「插进卡片」效果。
- 顶部导航区叠加 180rpx 渐变：`rgba(14,12,10,.42) → transparent`，保证白色返回/分享图标在浅色照片上也能看清。
- 底部 160rpx 渐变：`transparent → rgba(14,12,10,.52)`，托住指示器与展开按钮。
- 渐变只压到 42% 墨色，不压到全黑；婚礼照片的暖调是内容的一部分，不能被压成灰。

### 4.2 高度适配

- 高度走 §2.2 公式，**不在页面里写死 615rpx**。
- 小图模式初始值 = `banner_small_height`；展开值 = `banner_large_height`。
- 大图模式固定 `banner_large_height`，不渲染展开按钮。
- 图片 `mode="aspectFill"`，焦点 `center 42%`：婚礼场景的主体（新人、花亭、舞台）通常略高于画面中心，42% 比 50% 更不容易切到头。
- 舞台背景用 `--c-ink`，图片未铺满时不会露出白边。

### 4.3 展开 / 收起

| 项 | 规则 |
|---|---|
| 入口 | 右下角胶囊按钮：`展开 ⌄` / `收起 ⌃`，高 52rpx，半透明墨底 + 白字，距右 24rpx、距底 60rpx |
| 出现条件 | `banner_mode = 1` 且 `large_height > small_height` |
| 触发 | 单击；不做上滑手势，避免和页面滚动冲突 |
| 动效 | 高度 260ms `cubic-bezier(.22,.61,.36,1)`；图片同步缩放，不淡入淡出 |
| 滚动位置 | 展开/收起时保持页面 `scrollTop` 不变，让卡片自然下移/上移；不自动滚到顶 |
| 状态保持 | 只在本次浏览内保持；退出详情页再进恢复收起态 |
| 与轮播关系 | 展开后保留当前索引，不回到第 1 张 |

**为什么不做「自动展开」**：自动展开会让首屏高度在 1 秒内变化，用户刚准备点页签，内容就往下跳。展开必须是用户主动动作。

### 4.4 指示器与自动轮播

- 指示器位置固定在左下，尺寸见 §2.3；不跟随图片内容变化。数字样式加 24% 墨色胶囊底，保证在白色婚纱、天空、浅色花艺上仍然可读；圆点与进度条依赖底部 160rpx 渐变托底。
- `autoplay = 0`：不自动切换，指示器仍显示当前索引。
- `autoplay = 1`：按 `interval` 切换；用户拖动时暂停，松手 1 个间隔后恢复；页面隐藏时暂停。
- 视频页：不自动翻页；视频播放期间暂停自动轮播。
- 只有 1 张：隐藏指示器与自动轮播。
- 读屏文案始终提供「第 N 张，共 M 张」，不依赖视觉指示器。

### 4.5 图片 / 视频规格

| 项 | 要求 |
|---|---|
| 比例 | 不强制；按舞台 `aspectFill` 裁切，建议输出 16:10–5:3 横图 |
| 分辨率 | 宽 ≥1200px；单张 ≤500KB；JPEG/WebP；sRGB |
| 构图 | 主体（人脸/新人）在画面 35–60% 高度；左右各留 8% 安全区，避免被裁 |
| 视频 | MP4/H.264；封面 16:10；时长 ≤60s；单个 ≤20MB |
| 加载 | 首张立即加载；其余懒加载；当前页 preload 下一张；失败按 §2.5 移除 |
| 占位 | 舞台底色 `--c-ink`；图片 200ms 淡入；不出现白闪 |

### 4.6 无轮播时的兜底

```
有 cover → 单张 cover 全宽，高度按当前模式
无 cover → avatar 居中 208rpx 方图，暖米底
无 avatar → 暖米底 + 居中姓氏首字（serif 96rpx）+ 一行「暂未上传照片」
```

兜底态不显示指示器、不显示展开按钮；身份卡照常上浮。avatar 兜底时导航改用深色图标（见实施记录）。

## 5. 身份卡

### 5.1 信息顺序

| 层级 | 字段 | 样式 | 规则 |
|---|---|---|---|
| 1 | 角色 · 城市 | 18rpx serif，字距 2rpx，`--c-brand-text` | 缺城市只写角色；都缺写「婚礼人」 |
| 2 | 姓名 + 职级 | 姓名 46rpx / 600 / `--c-ink`；职级 18rpx 描边标签 | 姓名最多 1 行省略；无职级不占位 |
| 3 | 评分 · 场次 · 年限 | 22rpx `--c-ink-3`，分隔线 1rpx | 只渲染真实字段；全缺则整行不显示 |
| 4 | 可约状态 | 22rpx，绿/琥珀/中性点 + 文案 | 仅当入口带 `date` 时显示；无 date 整行不显示 |

**为什么把可约状态放进身份卡**：用户从查档期页带着日期进来，最关心的不是「他有多好」，而是「我选的那天他有没有空」。状态放在姓名下面，第一屏就能回答，不用去吸底栏找备注。

### 5.2 卡片规格

- 背景 `--c-surface`，顶部圆角 `--r-lg`（40rpx），底部不圆角（与页面连成一体）。
- 上浮 40rpx；内边距 36rpx 42rpx 30rpx。
- 与舞台之间不加阴影；靠圆角和 1rpx 顶部内描边分层。
- 若显示可约状态，状态行上方加 1rpx `--c-line` 分隔，行高 56rpx。
- 卡片不放入口按钮（收藏/分享/咨询），避免和吸底栏抢动作。

### 5.3 可约状态文案

| 状态 | 点 | 文案 | 数据来源 |
|---|---|---|---|
| 可约 | 绿 `--c-success` | `11月11日 周三 · 可约` | `schedule_available = true` |
| 已满 | 空心 `--c-ink-3` | `11月11日 周三 · 当日已满` | `schedule_available = false` |
| 未知 | 虚线空点 | `11月11日 周三 · 档期待确认` | 字段缺失 / 请求失败 |
| 仅 1 档（可选增强） | 琥珀 `--c-warning` | `11月11日 周三 · 仅 1 档` | 需详情接口补 `schedule_remaining` |

> 当前 `/staff/detail` 与 `/v2/staff/detail` 只返回 `schedule_available` 布尔值和 `message`，没有剩余档数。因此首版只做「可约 / 已满 / 待确认」三态；`仅 1 档` 等接口补齐 `schedule_remaining` 后再启用，避免前端硬造「紧张感」。

## 6. 页签与详情面板

### 6.1 页签

- 沿用现有三页签：详情 / 作品 / 评价，高 88rpx。
- 吸顶后底色改为 `rgba(250,246,238,.94)` + 8px 背景模糊，底部 1rpx `--c-line`；不加深色阴影。
- 选中：文字 24rpx / 600 / `--c-ink`，下方 42×4rpx 圆角短线；未选 `--c-ink-3`。
- 计数：serif 18rpx，选中时 `--c-brand-text`。
- 长图详情不单独开第四个页签，原因见 §12。

### 6.2 详情面板顺序

| 顺序 | 模块 | 目的 | 缺失时 |
|---|---|---|---|
| 1 | 介绍段落 | 先给「这个人是谁」 | 整段隐藏，不显示空态占位 |
| 2 | 数据行（场次/评分/好评/年限） | 用事实建立信任 | 缺哪项少哪项 |
| 3 | 规格 2×2（风格/语言/城市/年限） | 快速扫读硬条件 | 整块隐藏 |
| 4 | 服务包含 | 把套餐 desc 拆成清单 | 整块隐藏 |
| 5 | 长图详情 | 作者自己的表达 | 整块隐藏 |
| 6 | 尾注 + 继续看作品 | 收束长内容，给出下一步 | 恒显示 |

**为什么长图放在结构化信息之后**：长图是「作者想说的」，不是「用户要先查的」。先给场次、评分、风格、服务包含，用户 10 秒内能判断要不要继续；长图放在后面，愿意看的人往下看，不愿意看的人可以直接点「作品」或「预约」。

### 6.3 间距节奏

- 面板左右 42rpx；模块之间 32rpx；带分隔线的模块上方 32rpx / 下方 28rpx。
- 介绍段落行高 1.75；段间 18rpx。
- 数据行与规格表之间 24rpx；规格表两列，列间距 27rpx、行间距 18rpx。
- 服务包含每行 10rpx 上下 padding，图标 24rpx。

## 7. 长图详情

### 7.1 渲染顺序

严格按 `long_detail` 数组顺序，不重排、不合并文本、不丢弃空文本块以外的内容。

```
文本块 → 文本块 → 图片块（多图）→ 文本块 → 图片块 …
```

### 7.2 图片块规则

| 项 | 规则 |
|---|---|
| 宽度 | 100%（相对页面容器）；左右各负 42rpx 抵消面板内边距，做到真正全宽 |
| 高度 | `mode="widthFix"`，按原图比例自适应；不裁切、不拉伸 |
| 间距 | 同一图片块内 `gap: 0`；相邻两个图片块之间也 `gap: 0`，视觉上合并为一条长图 |
| 圆角 | 0；长图不是卡片，加圆角会切断连续画面 |
| 边框/阴影 | 无 |
| 背景 | `--c-surface-2` 占位；加载完成 200ms 淡入 |
| 失败 | 该图替换为同比例暖米占位 + 小字「图片加载失败」；不阻断后续图片 |
| 点击 | 打开原生图片预览，从当前图开始，支持左右滑 |

**为什么必须全宽**：后台编辑器的说明就是「首尾无间距连续展示」。运营上传的往往是一张 750×3000 的完整长图，或者一组无缝拼接的分镜；如果前台加 42rpx 边距或 24rpx 间距，接缝会立刻暴露，长图就散了。

### 7.3 文本块规则

| 样式 | 映射 | 说明 |
|---|---|---|
| `fontSize: sm` | 26rpx / 行高 1.75 | 注释型文字 |
| `fontSize: md` | 30rpx / 行高 1.75 | 默认正文 |
| `fontSize: lg` | 34rpx / 行高 1.7 | 段落标题或强调 |
| `bold: true` | 600 | 只加粗，不换字体 |
| `align` | left / center / right | 居中用于引语；右对齐少用，保留但提示 |
| `color` | 后台 6 色板 | 原样应用，不擅自改色 |

**文本栏宽**：左右 42rpx；≥600px 容器下最大 516px，居中。文本块不跟着图片全宽，否则一行 40 个字，读不下去。

**颜色与可读性**：后台色板里 `#7F7B78`、`#E85A4F`、`#C98A4A` 在暖白底上的对比度不足 4.5:1。设计上不修改作者选色（会破坏装修意图），但建议：

- 这三色只用于短句、引语、编号，不用于长段落；
- 编辑器增加「对比度偏低」提示；
- 正文默认色收敛为 `#1E2432` / `#3D3D3D` 两档。

### 7.4 与上下文的衔接

```
服务包含最后一行
        │ 32rpx
   ─────── 更多介绍 ───────       ← 48rpx 高，细线 + 20rpx 字，低存在感
        │ 24rpx
  ┌─────────────────────────┐
  │ 40rpx 渐变（bg → 透明）  │      ← 压在首图上，消除硬切
  ├─────────────────────────┤
  │                         │
  │      图片块（全宽）      │
  │                         │
  ├─────────────────────────┤      ← 0 间距
  │      图片块（全宽）      │
  └─────────────────────────┘
        │ 32rpx
     文本块（42rpx 栏宽）
        │ 32rpx
  ┌─────────────────────────┐
  │      图片块（全宽）      │
  └─────────────────────────┘
        │ 48rpx
  以上图文由老师提供，最终以服务确认单为准
        │ 24rpx
      [ 继续看作品 → ]
```

- **进入**：章节标记用「细线 + 小字」，不用大标题，避免和长图里作者自己的标题打架。
- **首图过渡**：40rpx 渐变从页面底色到透明，压在首图顶部；比直接硬切柔和，也不会损失图片内容。
- **块间**：文本→图片 32rpx；图片→文本 32rpx；图片→图片 0。
- **结束**：最后一张图后 48rpx 暖白留白，接 18rpx 来源说明，再接一个文字型「继续看作品 →」，把用户从长图里接回页签。
- **超长内容**：不做「展开更多」截断。长图是作者主动装修的详情，截断会让运营的内容白做；但提供尾部的页签出口，避免用户困在长图里。

### 7.5 长图内容规范（给运营）

| 项 | 建议 |
|---|---|
| 画布宽 | 750px（2 倍图 1500px），与小程序设计宽一致 |
| 单张高度 | ≤2400px；更长的内容拆成多张，按顺序上传 |
| 格式 | JPEG q85 / WebP；单张 ≤500KB；sRGB |
| 文字安全区 | 左右各 48px，上下各 40px；避免被裁 |
| 字体 | 与页面一致的黑体；标题 48–64px，正文 28–32px |
| 颜色 | 底色用暖白/米色，正文深墨；不要用纯白底，会在页面里「挖一个洞」 |
| 接缝 | 多图拼接时，上一张底边与下一张顶边颜色必须一致，否则全宽展示会露缝 |

## 12. 设计取舍

| # | 取舍 | 理由 | 代价 |
|---|---|---|---|
| 1 | 身份信息从图上移到上浮卡 | 400rpx 小图下压字会同时毁掉脸和字；卡上对比度稳定 | 首屏图片不再是「带名字的海报」，品牌感弱一点；用上浮 40rpx 和 serif 角色行补回层次 |
| 2 | 展开必须手动，不自动 | 自动改变首屏高度会让用户正在看的内容跳走 | 运营想要「大图第一眼」时，需要用户多点一下；大图模式可直接配置 |
| 3 | 长图不单独开页签 | 第四页签在无长图时是空的；且长图属于「详情」的一部分 | 长图在详情最底部，触达路径变长；用章节标记和尾部「继续看作品」补偿 |
| 4 | 长图图片全宽、零间距 | 后台明确要求「首尾无间距」；长图接缝必须无缝 | 与 42rpx 文本栏宽形成跳变；用 32rpx 块间距和渐变过渡缓冲 |
| 5 | 高度加 280rpx 下限 / 960rpx + 58vh 上限 | 后台配置范围过宽（small 200–800，large 无上限），不设边界会出现「一条缝」或「整屏图」 | 运营填 200 时实际显示 280，需要在后台文案里说明「最小渲染 280rpx」 |
| 6 | 指示器统一放左下 | 切换 5 种样式时布局不跳；右下固定留给展开按钮 | 数字样式不能放右下（常见做法），但换来一致性 |
| 7 | 视频不在轮播位内播放 | 200–400px 高的舞台放视频控件不可用 | 多一次全屏跳转；用封面 + 播放键明确预期 |
| 8 | 长图作者色值原样保留 | 擅自改色会破坏运营装修意图 | 部分色值对比度不足；通过编辑器提示和字号下限缓解，不前台强改 |
| 9 | 不做长图截断 | 长图是作者主动上传的完整内容，截断会让运营白做 | 页面可能很长；用尾部出口和吸底栏保证随时可预约 |

### 13.2 验收清单

**轮播**

- [ ] `banner_mode=1`：初始高度 = `small_height`，有「展开」；展开后 = `large_height`，有「收起」。

## 17. 预约链路与步骤页修订（2026-11-10 19:40）

### 17.1 金额 0 的三个根因

1. **上下文没有兜底**：`staff-detail` 只从上一页 query 读 `date/region`，列表页会带，但分享、搜索、扫码通常只带 `id`。日期为空、地区为空时，`/order/preview` 直接拒绝（“请选择服务省份”），订单页没有可展示的金额。
2. **v2 报价读错层级**：`OrderLogic::previewOrder()` 返回 `{ success, data: { items, service_amount, total_amount, ... } }`，`V2Logic::bookingPreview()` 却直接从根层取 `total_amount / items`，导致**所有 v2 报价恒为 0**（即使 v1 报价正常）。这是确认页显示 `¥0.00` 的直接原因。
3. **锁档错误误分类**：`doLock` 把 `code === 0` 一律当成“别人先锁”，而请求层会把 5xx/“系统繁忙”也映射成 code 0，于是服务端异常时用户被从确认页踢回上一步。
