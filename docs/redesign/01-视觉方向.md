## 1. 整体视觉方向

### 1.1 方向命名与设计理念

**方向命名：素笺契约（Quiet Ledger）**

**一句设计理念**：
> 把浪漫留给照片，把秩序留给界面——用纸感暖白、明确边界与可读的文字层级，让每一次档期确认与金额核对，都像签一份看得清楚的文书。

「素笺」指 `--c-bg #f8f6f0` 的暖白纸感底与 `1rpx` 描边构成的纸张边界；「契约」指这套界面服务的是**有金额、有日期、有责任人、有状态机**的履约关系，而不是一张婚礼海报。香槟金在其中的角色是骑缝线 / 印章，不是主色。

### 1.2 五个关键词

| 关键词 | 可判定的含义 |
|---|---|
| **纸感** | 页面底与卡片几乎无明度差（1.08:1），层级由 1rpx 描边 + 圆角 + 留白建立，不靠阴影和渐变。 |
| **边界清晰** | 可交互控件边界一律 `--c-control-border`（≥3:1）；装饰分隔线与控件边界物理隔离，不混用变量。 |
| **层级可读** | 标题层级由「字重 + 字号 + 上留白」三者中至少两者共同建立，禁止只靠放大字号。 |
| **金色克制** | 金色单屏像素面积 ≤2%，不承载任何文字、不作控件边界、不作正文色；只做选中标记、区块起首、品牌印章。 |
| **状态可信** | 状态 = 语义色 + 形状（点/图标）+ 中文状态词，三者同时存在；颜色永不单独编码状态。 |

### 1.3 为什么婚庆服务需要这个方向（业务论证，不依赖形容词）

1. **决策密度高、单笔金额大**。预约页同屏并存婚期、地区、人员、套餐、加项、实时报价；订单详情同屏并存状态头、金额三段、多个可执行动作。装饰性视觉元素（渐变 hero、大面积金块、花体标题）会直接挤占信息带宽。用户需要的是"能扫读的表格感"，而不是"氛围感"。
2. **长周期、多角色共用同一对象**。新人、服务人员、后台在同一个订单上协作，周期可达数月。「待付款 / 待审 / 已锁档 / 尾款待收」等状态必须跨 42 页语义一致，因此状态编码要形状化、文字化，不能靠一套只有设计者记得住的红绿浅底。
3. **低频、高 stakes、无学习预算**。用户一年使用数次，没有时间理解自定义控件语言。黑底主按钮、白底描边卡片、常驻字段标签、88rpx 热区是无需解释的通用约定；任何"创意控件"都是转化率成本。
4. **情感应由内容承载，不应由界面框架承载**。真实作品照片与人员照片才是浪漫来源。界面再叠金色渐变、花体字、钻石图标，会与内容争抢并显廉价——存量端 `uniapp` 的 3572 处 hex 硬编码、20+ 字号档、字重 900 泛滥就是可复核的反面证据。
5. **使用环境是门店与婚礼现场**。户外强光、单手操作、低端机、320px 窄屏是常态。对比度（正文 ≥4.5:1）、控件边界（≥3:1）、中文物理字号下限（12px）、触控热区（≥88rpx）比任何"氛围"都优先。

### 1.4 与现状的差异点

| 维度 | 现状（基线实测） | 本方向 | 差异本质 |
|---|---|---|---|
| 系统成熟度 | 「一张被严格遵守的颜色表」：2056 处 `var(--)`、13 处 hex，但只有 500 一档字重 | 「能自我约束的设计系统」：色 / 字 / 间距 / 圆角 / 图标 / 状态 / 组件七套规格互相咬合 | 从**色值正确**升级到**层级与状态可读** |
| 信息层级 | 标题仅靠字号区分，6 档字号中 24rpx 占 34.9%；行高 1/1.4/1.5/1.6/1.7 五档混用 | 400/500/600 三档字重 + 四级文字 + 4 档行高 + 字距规则 | 从**扁平**升级到**有节奏** |
| 状态表达 | 浅底标签对页面底 1.03–1.09:1，边界不可辨；24rpx 小字；仅靠颜色 | 1rpx 同色调描边 + 状态点/图标 + 中文状态词 + 600 字重 | 从**色块**升级到**可辨识编码** |
| 金色用法 | 区块标题 6rpx 竖条每屏可多处；`card--selected` 用 `--c-brand` 作描边（2.43:1，实为违规） | 金色单点、面积 ≤2%；选中描边改 `--c-brand-text`（5.34:1） | 从**装饰散布**升级到**标点式强调** |
| 组件一致性 | 各页私有 `.picker` / `.row` / `.loadmore__text` / `.steps`；同页两套失败 UI | 15 类组件统一可视规格表，状态变体逐项列明 | 从**页面自治**升级到**规格可验收** |
| 容器分层 | `--c-surface` 对 `--c-bg` 仅 1.08:1，靠描边但仍混用 `shadow-card` 的历史惯性 | 明度差不参与分层，描边是唯一容器语言；阴影只给浮层 | 从**双重分层**升级到**单一语言** |

### 1.5 品牌调性：延续什么 / 升级什么

| 延续（不得改动） | 升级（本轮要做） |
|---|---|
| 暖白 `#f8f6f0` / 深墨 `#181614` / 香槟金 `#c6a15b` 三色关系 | 金色从「到处点缀」收敛为「单屏标点」，并给出面积与禁用清单 |
| 香槟金只作装饰、禁作正文（2.25:1 对米白） | 补齐 gold 四级的语义角色，明确哪一级可以承载文字、哪一级只能作底 |
| 主 CTA 黑底白字（18.05:1）；不做暗黑模式 | `gold` 变体补 1rpx `--c-brand-text` 描边，满足 D4 门禁但仍不启用为默认主 CTA |
| 卡片 1rpx 描边不用阴影；`--shadow-card: none` | 卡片默认圆角由 28rpx 回正到 20rpx；`selected` 描边色值修正 |
| 装饰线与控件边界分离（`--c-line` vs `--c-control-border`） | 增加虚线规则、列表分隔线缩进规则、1rpx 描边与浮层阴影的分层表 |
| 6 档字号 / 5 档圆角 / 7 档间距 / 6 值图标 / 3 档动效时长 | 给每档语义命名、字重/行高/字距、窄屏兜底、可直接抄用的组合表 |
| 不引入新 UI 框架、不画空态插画、颜色不接受运行时下发 | 图标语义命名表 + 三阶段过渡策略；空/错/结果页的图标与文案规格 |
| 10 个基础组件不并行造第三套 | 15 类组件规格表覆盖缺口（Steps / LoadMore / Toast / Sheet / ResultPage / Chip），供 Phase 2/3 按规格补件 |

### 1.6 三条不可违背的视觉原则（可逐条判定）

**原则一 · 金色只做标点，不做句子。**
`--c-brand` 及其衍生色在单屏内的着色像素面积 ≤2%；不得承载任何文字（对米白 2.25:1、白字压金 2.43:1，均不达 4.5:1）；不得作输入框 / ghost 按钮 / 选中卡片 / chip 的边界（不达 3:1）；不得作正文、金额、状态色。允许位置仅有：区块标题起首竖条（≤2 处/屏）、选中态勾形图标、hero 内装饰线、品牌印章、深色容器内的强调。需要金色文字时用 `--c-brand-text`（对白 5.34:1）。

**原则二 · 任何信息不得只靠单一编码。**
- 状态：语义色 + 形状（状态点或 24rpx 图标）+ 中文状态词，三者缺一不可。
- 层级：字重 / 字号 / 上留白三者中至少两者同时变化，禁止只放大字号。
- 控件可辨识：`--c-control-border` ≥3:1 边界 + ≥88rpx 热区 + 按下态，三者同时具备。
- 错误：边框色 + 错误文案 + 字段定位，禁止只用红色。

**原则三 · 可读性优先于装饰，冲突时删装饰。**
中文物理字号 ≥12px（窄屏兜底见 §3.5）；常规文字 ≥4.5:1；大字与非文字控件边界 ≥3:1；卡片只用 1rpx 描边分层。任何装饰元素与上述阈值冲突时，删除装饰，不得降低可读性来保装饰。订单、支付、审核相关页面禁用一切装饰性动效。

### 1.7 明确避免什么（降低返工的反模式清单）

- 避免大红、粉色、玫红、酒红渐变等"婚庆模板默认值"；避免金属质感、烫金渐变、光晕、投影金边。
- 避免中文花体 / 衬线标题 / 艺术字；避免 `font-weight: 700/800/900/bold`（存量端 900 泛滥即返工点）。
- 避免花朵、钻石、戒指、爱心等装饰图标充当业务菜单图标（业务动作必须可辨识）。
- 避免卡片内再叠卡片；避免靠加深底色或加阴影制造容器层级。
- 避免 560rpx 级 hero 占去 320px 窄屏近半屏；避免把主入口挤到折线下。
- 避免只用红绿区分状态；避免把错误态伪装成空态（`uniapp` 存量问题，新端防回归）。
- 避免数字滚动、视差、页面入场遮罩、骨架块带边框或阴影。
- 避免运行时下发颜色 / 节日皮肤改单个变量；避免暗黑反色（等于重做一套五态浅底与插画底色）。
- 避免页面里写裸 `font-size` / 裸 hex / 私建间距值（如 160rpx、200rpx）。

### 2.3 neutral 4.48:1 的事实更正与加固

- **事实**：4.48:1 是**阶段一修复前** `#716b62` 对 `#f0ece4` 的实测值；`tokens.css:45` 现已是 `#6b655c`，实测 **4.89:1 已达标**。基线 §4.2 与任务书沿用了旧数值，本规范予以更正，避免重复施工。
- **仍需加固的理由**：① 4.89 距 4.5 仅 0.39 余量；② `status-tag` 使用 24rpx（375px 下 12px、**320px 下仅 10.24px**），小字对对比度余量更敏感；③ 户外强光、低端机屏幕、弱视用户下 0.39 余量不足以稳定；④ 阶段一计划中的"4 处局部替换"只治标。

### 2.4 浅底状态标签可读性的真实问题与修复

**问题重定义**：五态前景对各自浅底 5.22–5.67:1 **全部达标**，"可读性"缺陷不在文字对比度，而在三处：

1. **标签块与页面底无边界**：`--c-success-bg` 等浅底对 `--c-bg` 仅 1.03–1.09:1，标签在米白页面底上"融进去"，用户无法判断这是一枚状态标签还是一块背景。
2. **小字 + 单字重**：`status-tag` 固定 `--fs-xs` 24rpx / 500 字重，320px 窄屏 10.24px。
3. **仅靠颜色编码**：无形状、无状态词约束，红绿色弱用户与打印/截图场景无法辨识。

**修复规格（四件同时做）**：

| 措施 | 具体值 | 作用 |
|---|---|---|
| ① 同色调描边 | `1rpx solid var(--c-{tone}-border)`，五色值见 §2.1.5 | 界定标签块，与页面底分离；不引入灰边、不脏色 |
| ② 形状编码 | 前置直径 `10rpx` 实心圆点（色 = tone 前景）或 `24rpx` 语义图标；点与文字间距 `--sp-1` 8rpx | 不依赖颜色即可区分 |
| ③ 文字编码 | 标签文案必须含中文状态词（如「待付款」「已锁档」「支付失败」），禁止只写「成功 / 失败」或只写符号 | 朗读、截图、色弱可辨识 |
| ④ 字重与窄屏 | 字重 `600`；`--fs-xs` 窄屏 px 下限兜底（§3.5） | 提升小字笔画密度与窄屏可读性 |

**禁止**：用 `--c-line` / `--c-line-strong` 给标签描边（暖灰配绿色标签会脏）；用 `opacity` 降低浅底；标签承载可点击动作（若可点，边界必须用 `--c-control-border` 且热区 ≥88rpx）。

### 2.7 关于「深色 / 浅色双皮肤」的口径

本系统**只提供一套浅色品牌主题**（`--c-bg` 暖白 + `--c-surface` 白），**不做可切换的暗黑模式**，理由已在第十章成立：暗黑不是反色，五态 `-bg` 需整套重配、深墨主 CTA 需重定义、空态图标与 hero 底色需重画，等于再做一套系统；且运行时主题死链路刚被清理，不应复活。

但系统内存在**局部深墨反白语境**，需按同一套规格约束，避免各自发挥：

| 深墨语境 | 背景 | 文字 | 允许元素 |
|---|---|---|---|
| 主 CTA（`ink` 按钮） | `--c-ink #181614` | `--c-ink-inverse #ffffff`（18.05:1） | 文字、`u-loading` 反白 |
| Toast / 浮层提示 | `--c-toast-bg rgba(24,22,20,.92)` | `--c-on-dark #ffffff` / `--c-on-dark-2 rgba(255,255,255,.72)` | 状态图标 32rpx、≤2 行文案 |
| 深色 hero（若使用图片叠深罩） | `rgba(24,22,20,.45)` 叠图 | `--c-on-dark` / `--c-on-dark-2` | 标题、副标题；**禁止**在深底上用 `--c-brand` 作文字 |
| 金底（gold 按钮 / 品牌印章） | `--c-brand` / `--c-brand-soft` | `--c-on-brand #181614` | 深墨字；**禁止**白字 |

规则：深墨语境内不使用任何 `-bg` 浅底状态色；状态在深底上一律用「反白文字 + 形状」表达；深墨语境内金色面积同样受 ≤2% 约束。

## 3. 字体层级

### 3.1 字号变量名的事实更正与语义角色映射

**变量名以 `tokens.css:67-73` 为准**：`--fs-xs 24 / --fs-md 28 / --fs-lg 32 / --fs-xl 38 / --fs-2xl 48 / --fs-number 64`（rpx）。任务书与基线表格中的 `sm / md / lg / xl` 是**数值简写**，其中 `sm` 并不存在、也没有 `--fs-number` 之外的 `number` 别名。

**不新增字号变量**（保持 6 档纪律、避免 169 处调用点改名）。下表左侧「语义角色」是设计侧口径，供评审与文档使用；前端继续消费现有变量名。7 个语义角色压缩到 6 档：**Display 与 H1 共用 `--fs-2xl`，靠字重与字距区分**，这是刻意的克制，不新增第 7 档。

> **v2 校正 2026-11-08｜字号分两层并存，6 档纪律不变**
>
> v2 24 屏对齐 390px 精细排印稿后，`tokens.css:102-128` 已登记 19 档排印值（`--fs-15`…`--fs-69`）。为避免"规范说没有、代码里在用"的分叉，明确两层分工：
>
> | 层 | 档位 | 用途 | 约束 |
> |---|---|---|---|
> | **语义档（6 档）** | `--fs-xs/md/lg/xl/2xl/number` | **默认**，一切中文内容 | **中文句子不得低于 `--fs-md`（28rpx）**——本条为硬线，不因排印档存在而放松 |
> | **排印档（19 档）** | `--fs-15`…`--fs-69` | 局部微调：数字、英文、单位、短标签中的非中文部分 | **不得承载中文句子**；不得用于错误文案与关键状态词；不得用于表单 label 与正文 |
>
> 判定口诀：**先问"这段是不是中文句子"**——是 → 走语义档且 ≥ `--fs-md`；否（数字 / 英文 / 单位 / 单字标签）→ 可用排印档。
> 依据：排印档为纯 rpx，无 `max()` 下限保护，320px 窄屏下 `--fs-20` 约 8.5px，中文不可读。

| 语义角色 | 变量名 | rpx | 375px | 字重 | 行高 | 字距 | 典型用法 | 禁止用法 |
|---|---|---|---|---|---|---|---|---|
| **Display** | `--fs-2xl` | 48 | 24px | `--fw-semibold 600` | `--lh-tight 1.25` | `-0.01em` | 首页主标语、支付结果金额旁的状态标题、空态主标题（≤12 字） | 禁止用于列表、正文、按钮 |
| **H1**（页面标题） | `--fs-2xl` | 48 | 24px | `--fw-medium 500` | `--lh-tight 1.25` | `0` | 页面级主标题（详情姓名、结果页标题） | 禁止一屏出现 2 个以上 |
| **H2**（区块 / 金额摘要） | `--fs-xl` | 38 | 19px | `--fw-semibold 600` | `--lh-tight 1.25` | `0` | 区块大标题、订单「合计」标签、结果页副标题 | 禁止用于卡片内小标题 |
| **H3**（卡片 / 小标题） | `--fs-lg` | 32 | 16px | `--fw-semibold 600` | `--lh-tight 1.25` | `0.01em` | 卡片标题、`section-header` 标题、导航标题、按钮 lg、表单分组标题 | 禁止用于正文段落 |

| **Number**（金额） | `--fs-number` | 64 | 32px | `--fw-semibold 600` | `--lh-none 1` | `-0.01em` | 仅 `price` 组件 `xl` 档（支付结果大金额） | 禁止任何页面直接引用；禁止用于非金额数字 |

> **层级判定**：H1→H2→H3 必须同时变化「字号 + 字重」中的两项或「字号 + 上留白」；Body→Caption 靠字色（L1→L2）与行高，不靠再降字号。禁止出现"同字号只换颜色就叫标题"的做法。

### 3.2 字重策略（解决「全站只有 500、标题层级扁平」）

**三档字重，禁用其余所有值**：

| 变量 | 值 | 用途 | 典型数量占比目标 |
|---|---|---|---|
| `--fw-regular` | `400` | 正文、输入、说明、列表次要信息 | 约 60% |
| `--fw-medium` | `500` | 按钮文字、卡片主信息、Meta、tabBar 选中、H1 | 约 30% |
| `--fw-semibold` | `600` | H2 / H3 / Display / Number / 状态标签文字 / 空态主文案 | 约 10% |

**明确禁用**：`700` / `800` / `900` / `bold` / `bolder` / `lighter`。存量端 `uniapp` 的 900 泛滥即迁移时的重点清理项。

**为什么是 600 而不是 700**：① 700 在 Android 微信（Noto Sans CJK / Roboto 回退）常触发**合成粗体（faux bold）**，笔画糊、字宽跳变，导致 320px 窄屏折行位置变化；600 在 iOS PingFang SC 上有真实 Semibold 字形，在 Android 上多数回落为 Medium 而非合成加粗，跨端更稳。② 本系统的层级由「字重 + 字号 + 留白」共同建立，600 已足够拉开与 400 正文的差距，无需 700。

**小程序字体渲染限制（必须写进实施说明）**：

1. 小程序 `font-weight` 依赖系统字体，**不加载自定义字重族**；`--font-sans` 里的 `PingFang SC`（iOS）有 Regular/Medium/Semibold，`Microsoft YaHei`（部分 Android / 开发者工具）与 Noto Sans CJK 字重覆盖不全。
2. 微信 `<text>` 支持 `font-weight`，但 **WebView 与 Skyline 渲染的字重映射可能不同**；同一字重在 iOS / Android 真机需各验一次。
3. `font-weight` 变化会改变中文字符 advance，**可能影响两行截断与金额基线**；因此 600 只用于单行标题 / 数字，不用于长段落。
4. **兜底规则**：若真机发现 600 出现合成粗体发虚或字宽跳变，降级为 `500` + 标题字号上调一档 + 上留白增加 `--sp-2`，**不得改用 700**。
5. 不引入 WebFont / `wx.loadFontFace`（主包体积与首屏成本不划算，且破坏系统字体一致性）；`--font-sans` 保持现有字体栈不变。

### 3.3 行高收敛（解决「1 / 1.4 / 1.5 / 1.6 / 1.7 五档混用」）

| 变量 | 值 | 适用 | 禁止 |
|---|---|---|---|
| `--lh-none` | `1` | 单行按钮文字、tabBar 文字、状态标签、金额、角标 | 禁止用于任何 ≥2 行文本 |
| `--lh-tight` | `1.25` | Display / H1 / H2 / H3 标题 | 禁止用于正文段落 |
| `--lh-body` | `1.55` | 正文、列表、表单错误与提示、Toast 多行 | — |
| `--lh-loose` | `1.7` | 协议 / 关于 / 长说明 / 文章详情（≥5 行连续文本） | 禁止用于列表与卡片 |

`page` 基础 `line-height` 由 `1.6` 调整为 `--lh-body 1.55`；原有 `1.4` / `1.5` / `1.7` / `1` 四处混用按上表归位。

### 3.4 字距规则

| 场景 | `letter-spacing` | 理由 |
|---|---|---|
| 中文正文 / 中文辅助 | `0` | 中文自带字身留白，加字距会散 |
| H3 / Meta 小字 | `0.01em` | 提升 12px 小字笔画辨识 |
| Display / H1 大字 | `-0.01em` | 大字收紧，避免标题松垮 |
| 金额数字 / 数字串 | `-0.01em` + `font-variant-numeric: tabular-nums` | 等宽数字保证表格与金额基线对齐；小程序 iOS 生效、Android 部分生效，**兜底靠右对齐 + 固定 2 位小数** |
| 纯拉丁 / 日期数字 | `0.02em` | 与中文混排时的呼吸感 |

### 3.5 中文最小可读下限与 320px 窄屏换算

**硬下限：中文物理字号 ≥12px。** 11px 及以下中文笔画粘连；`uniapp` 存量端 22rpx（11px）是明确反例。数字 / 拉丁 / 角标可放宽到 10px，但不得承载语义。

uni-app / 微信小程序：`750rpx = 屏宽`，故 `1rpx = 屏宽 / 750`。**rpx 是相对单位，会随屏宽等比缩小**，这是本次最容易被忽略的可读性风险。

| 档位 | rpx | 320px（1rpx=0.4267px） | 375px（0.5px） | 390px（0.52px） | 430px（0.5733px） | 320px 是否达 12px |
|---|---|---|---|---|---|---|
| `--fs-xs` | 24 | **10.24px** | 12.00px | 12.48px | 13.76px | **否** |
| `--fs-md` | 28 | **11.95px** | 14.00px | 14.56px | 16.05px | **否（差 0.05）** |
| `--fs-lg` | 32 | 13.65px | 16.00px | 16.64px | 18.35px | 是 |
| `--fs-xl` | 38 | 16.21px | 19.00px | 19.76px | 21.79px | 是 |
| `--fs-2xl` | 48 | 20.48px | 24.00px | 24.96px | 27.52px | 是 |
| `--fs-number` | 64 | 27.31px | 32.00px | 33.28px | 36.69px | 是 |
| 图标 24 / 32 / 40 / 48 / 96 / 144rpx | — | 10.24 / 13.65 / 17.07 / 20.48 / 40.96 / 61.44px | 12 / 16 / 20 / 24 / 48 / 72px | — | — | 24rpx 档仅 10.24px，仅作内联小箭头 |

**结论**：在 320px 窄屏上，**6 档里有 2 档跌破中文 12px 下限**。这不是"设计稿看着还行"的问题，是可复核的量化缺陷。

**裁决（三选一，推荐 A）**：

- **方案 A（推荐）· px 下限保护，零页面改动**：在 `tokens.css` 写 `--fs-xs: max(24rpx, 12px); --fs-md: max(28rpx, 14px);`。375px 及以上两值与现状**完全等价**（截图比对误差 0）；320px 时取 12px / 14px 不再缩水。价值：仅 2 行 token 变更，全站 124 处 `--fs-xs` 与所有正文自动受益。
  - **前端验证项**：微信小程序 WebView / Skyline 对 `max()` 内 `rpx` 与 `px` 混合求值的支持需在真机确认；若不支持，走降级方案 B。
- **方案 B（降级）· 窄屏媒体查询**：`@media (max-width: 340px) { page { --fs-xs: 12px; --fs-md: 14px; } }`。效果等价，代价是引入一段媒体查询。
- **方案 C（不推荐）· 语义收窄**：规定 `--fs-xs` 只用于数字 / 拉丁 / 角标、中文最低 `--fs-md`，但 `--fs-md` 在 320px 仍只有 11.95px，**没有真正解决下限**，只能作为 A/B 之外的补充纪律。

**配套纪律（无论采用哪个方案）**：
1. `--fs-xs` 永不承载中文句子、错误文案、关键状态词；中文辅助说明最低 `--fs-md`（Caption 档）。
2. 截图回归以 **375px 基准屏**判定字号误差 = 0；**320px 只做溢出、遮挡、可读性检查**，不按像素比对。
3. 微信「字体放大」设置下不承诺固定版式，但不得出现关键内容遮挡（沿用基线 §5 与第十章 14.2 X03）。

### 3.6 金额数字的排版规则

**数据层与展示层分工（现状已成立，必须保持）**：

| 层 | 职责 | 规则 |
|---|---|---|
| `shared/utils/format.ts` `formatMoney` | 纯数字字符串 | 唯一格式化入口；页面禁止 `toFixed` / 自行拼 `¥` / 自行加千分位 |
| `price` 组件 | 拆整数 / 小数、渲染 `¥` 与后缀 | 调用处只传 `size="sm\|md\|lg\|xl"`、`prec`、`color`，**禁止传裸字号**（阶段二已做到 0 处） |
| 页面 | 传业务数值与语义 | 禁止写任何字号、颜色字面值 |

**逐条规则**：

1. **千分位（现状缺口）**：`formatMoney` 的 `thousand` 默认 `false`（`format.ts:23-24`），`price.vue:57` 只传 `decimals`，**当前全站金额无千分位**。婚礼客单价常为 5–6 位整数（`128800.00` 无分隔极难扫读）。裁决：`price` 调用改为 `formatMoney(content, { decimals, thousand: true })`；`request/normalize.ts` 与 6 个页面的直接 `formatMoney(v)` 调用若用于展示，统一补 `{ thousand: true }`。**纯数值传参、不展示的字符串不加千分位**（避免破坏接口契约）。
2. **小数位**：`prec` 默认 `2`。现状 `price.vue:60-61` 会去掉小数末尾 0（`1.50 → 1.5`、`1.00 → 1`）。裁决分档：
   - **列表内嵌价 / 人员起价（sm、md）**：可去尾零，保持现有视觉（`¥3,800`、`¥3,800.5`）。
   - **合计 / 应付 / 实收 / 待收 / 支付结果（lg、xl）**：**必须保留 2 位小数**（`¥128,800.00`）。财务口径要求明细与合计精度一致，`.5` 会显得不正式。落地方式：`price` 增加 `trimZeros?: boolean`（默认 `true` 保持现状，合计类显式传 `false`）——属组件 API 建议，不改业务逻辑。
3. **`¥` 符号基线**：`¥` 由组件 `prefix` 渲染，与整数字号**基线对齐**（`price.vue:83` 已用 `align-items: baseline`，保持）；`¥` 色 `--c-ink-2`，与整数间距 `2–4rpx`，整组 `white-space: nowrap` 不换行。`¥` 字号按档位取主数字字号的 ~0.5 倍：sm `20rpx` / md `24rpx` / lg `28rpx` / xl `32rpx`（现状统一 24rpx，xl 档比例仅 0.375 偏小）。
4. **小数部分**：字号为主数字的 ~0.62 倍（sm 20 / md 24 / lg 30 / xl 40rpx），与整数**同基线、同字重**，颜色与主数字一致（现状 `--c-ink-2` 的 prefix/suffix 才是次级色，正确）。
5. **字重与字距**：主数字 `600`（现状 `500`，金额需权重），`letter-spacing: -0.01em`，`font-variant-numeric: tabular-nums`；Android 不生效时靠**右对齐 + 固定 2 位小数**兜底。
6. **字色**：默认 `--c-ink`；原价 / 划线价用 `--c-ink-3` + `line-through`，**不再叠 `opacity: .6`**（现状 `price--through` 用 opacity 会把 4.60:1 拉到不达标）；优惠 / 待付款金额用 `--c-danger`，但须同时有中文状态词。
7. **窄屏溢出**：`xl`（64rpx）在 320px 为 27.31px，`¥1,234,567.00` 会溢出。规则：`xl` 档仅用于 **≤6 位整数**（`999,999.99` 以内）的金额；超出自动降为 `lg`（48rpx）。金额行右侧预留 `--sp-4` 32rpx，不与状态标签抢位。
8. **对齐**：金额一律**右对齐**（列表行、订单三段金额、报价摘要）；金额与状态标签同一行时，标签左、金额右，中间最小间距 `--sp-3` 24rpx，金额**不换行**。
9. **千分位与小数在浅底上**：金额文字不得放在 `--c-brand-bg` / `--c-hero-bg` 等浅底上用 `--c-ink-3`；L3 色值修复后（§2.5）方可使用。

### 3.7 新增排版 token（写入 `tokens.css` 的建议块见附录 A）

`--fw-regular/medium/semibold`、`--lh-none/tight/body/loose`、`--fs-xs`/`--fs-md` 的 px 下限保护。不新增字号档、不改 `--font-sans`。

### 4.1 7 档间距的语义化命名与用途

### 5.3 `--c-line` vs `--c-control-border` 严格分界表

判定口径：**该边界是否属于"用户可点/可输入/可改变状态"的控件？** 是 → `--c-control-border`；否 → `--c-line` / `--c-line-strong`。

| 元素 | 变量 | 理由 |
|---|---|---|
| 卡片描边（含 clickable） | `--c-line` | 卡片整体可点时，边界由「按下态 + 右箭头」表达，不靠边界色；选中态另见 §7.4 |
| 列表行分隔、区块分隔、时间线 | `--c-line` | 纯装饰 |
| 导航下边框、tabBar 上边框、吸底栏上边框 | `--c-line` | 纯装饰 |
| 输入框底线 / picker 行 / 表单行底线 | `--c-control-border` | 可输入控件 |
| ghost 按钮边框 | `--c-control-border` | 可点控件（3.83:1） |
| 筛选 chip 未选中边框 | `--c-control-border` | 可点控件 |
| checkbox / radio / switch 轨道 | `--c-control-border` | 可改变状态 |
| 卡片 `selected` 描边 | **`--c-brand-text`** | 选中是状态反馈，需 ≥3:1；`--c-brand` 2.43:1 违规（现状缺陷） |
| 状态标签描边 | `--c-{tone}-border` | 信息展示，装饰边界 |
| 骨架块、空态图标 | 无描边 | — |
| `--c-line-strong` | 弱装饰专用 | 阶段一曾误用作输入框/ghost 边界（1.59:1），已修，**禁止回退** |

> 一句话：`--c-line` 是**纸的折痕**，`--c-control-border` 是**控件的轮廓**。二者不得混用，也不得用同一个变量"兼顾"。

### 5.4 列表分隔线缩进规则

| 场景 | 缩进 |

| 通栏列表（无卡片，页面底 `--c-bg` 上） | 左右各缩进 `--sp-4` 32rpx，即分隔线从内容左缘起、到右缘止；**不贯穿整屏** |

### 6.2 线宽 / 风格约定与现状资产核实

**现状核实**：**v2 校正 2026-11-08**——原记录为"`app-tabbar.vue` 已用 `vk-uview-ui` 的 `u-icon`"，现已过时：业务代码 `<u-icon>` **全量清零**，统一消费 `tn-icon`（图鸟，`@tuniao/tnui-vue3-uniapp`），实测 `<tn-icon>` 约 155 处；`vk-uview-ui` 仅剩 `u-parse`（3 处富文本）与 4 处待迁的 `u-loading`。`static/images/tabbar/` 下 6 张 PNG（`home`/`home_s`/`news`/`news_s`/`user`/`user_s`）**已零引用**，列入废弃清单。全项目**无 SVG**。

**约定**：

1. **线宽不可调**：iconfont 字形把线宽固化在字体里，CSS 无法修改。因此风格统一只能靠两条纪律，不靠"调 stroke-width"。
2. **图标源唯一：`tn-icon`（图鸟）**。**v2 校正 2026-11-08**：原文为"继续用 `vk-uview-ui` iconfont、禁止引入 tn-icon"，已被 v2 落地推翻——业务代码 `<u-icon>` 已清零、全量迁至 `tn-icon`（24 屏与 25 个遗留页均如此）。现口径：**统一消费 `tn-icon`**，禁止再引入第三套图标字体 / 图标 PNG 包；`vk-uview-ui` 仅保留 `u-parse`（3 处富文本）作为过渡依赖。
3. **线性与面性不混排**：导航与操作类一律**线性**（`home`、**`left`**、`calendar`）；状态与结果类一律**面性 / 填充**（`-fill`、`empty-*`、**`success-circle-fill`**）；同一屏内同类图标必须同风格同尺寸。**v2 校正 2026-11-08**：图标名以代码既有用法为准——`arrow-right` → **`right`**、`arrow-left` → **`left`**、`arrow-down` → **`down-arrow`**、`checkmark-circle-fill` → **`success-circle-fill`**；Toast / 结果页 error 态用 **`close-fill`**（面性）。⚠️ `right`（\e7de）与 `right-arrow`（\e74e）是**两个不同字形**，不要当成同一名字的两种写法。
4. **选中态配对**：凡有选中态的图标必须用同一字形的 `-fill` 版本（tabBar 已正确实现），禁止用"换颜色"代替换字形。
5. **颜色**：图标色只取语义变量（`--c-ink` / `--c-ink-2` / `--c-ink-3` / `--c-brand-text` / 五态前景）；**禁止 `--c-brand` 作图标主色**（2.25:1 不可辨识）、禁止 `--c-line-strong` 作图标主色（1.59:1，阶段二已从空态图标改掉）。
6. **空态不画插画**：用 `tn-icon` 的 `empty-*` 字形，按语境传 `empty-icon`。**v2 校正 2026-11-08**：tn-icon 的 `empty-*` 可用集共 **14 个**——`empty-address` / `empty-cart` / `empty-comment` / `empty-coupon` / `empty-data` / `empty-favor` / `empty-history` / `empty-list` / `empty-message` / `empty-network` / `empty-order` / `empty-page` / `empty-permission` / `empty-search`。**迁移映射**：`empty-wifi`（uView 有、tn 无）→ **`empty-network`**；`empty-news`（uView 有、tn 无）→ **`empty-message`**。传不存在的名字会静默渲染空白，不报错。

| **P3（长期，非本轮）** | 只有当"线宽必须可编程控制"成为硬需求时，才评估 SVG symbol + `currentColor` 方案，并同时评估小程序渲染差异、主包体积与 42 页回归成本 | 本轮**明确不引入 SVG**：6 值纪律 + iconfont 已够用，引入 SVG 会新增一套资产与渲染路径，收益不抵成本 |

**为什么本轮不引 SVG**：① 现有 92 处 `u-icon` 已收敛，字形够用；② 小程序对 SVG 的支持路径（base64 / image / 组件内联）与 Web 不同，会引入新的跨端差异；③ 线宽需求在本系统是伪需求（靠尺寸与风格纪律已能统一）；④ 用户明确不引入新 UI 框架，图标资产也不应无谓扩张。

| 组合 | 规格 |

### 6.6 禁用场景

- 禁止花朵 / 钻石 / 戒指 / 爱心等装饰图标充当业务菜单图标（业务动作必须可辨识）。
- 禁止纯图标承载关键动作而无文字或 `aria-label`（支付、删除、退款、提交）。
- 禁止状态只靠图标或颜色表达（必须配中文状态词）。
- 禁止 `--c-brand` / `--c-line-strong` 作图标主色；禁止图标尺寸超出 6 值；禁止 `:size` 按 px 语义传值。
- 禁止线性与面性图标在同一组里混排；禁止选中态只换颜色不换 `-fill` 字形。
- 禁止 tabBar 回退到 PNG；禁止为单个页面临时塞一张图标 PNG。
- 禁止给空态画插画或生成图片；禁止用虚构案例图替代真实作品图。
- 禁止图标带阴影、渐变、外发光或容器色块（结果页的圆形 `--c-*-bg` 底除外，且只用 1rpx 同色描边）。

#### §7.11-T1 组件契约陷阱：`tn-loading` 不传 `:show` 会整块不渲染

**不是"注意事项"，是契约陷阱——违反它不会报错、不会告警、测试用例也能过，但功能对用户失效。**

```ts
// @tuniao/tnui-vue3-uniapp/components/loading/src/loading.ts:12
show: Boolean,            // Vue Boolean prop，缺省 false
// components/loading/src/loading.vue:28
<view v-if="show" ...>    // 整块不渲染，不是渲染空容器
```

**后果**：`<tn-loading mode="circle" :size="32" />` 渲染出**零个节点**。加载中时用户看到纯空白，连骨架都没有。

**已踩实例**：`feed-detail.vue:167` 评论加载态——`commentLoading === true` 且评论未返回时，用户看到空白。

**硬要求**：所有 `tn-loading` 必须显式传 `:show="true"`（或用变量控制显隐），**不得依赖默认值**。由 4 处 `u-loading` 迁移时必须同时补。

> 同类 Boolean 型 prop 陷阱：`tn-popup` 的 `v-model:open`、`tn-modal` 的 `v-model` 同理——Boolean 缺省 false + 模板 `v-if`，漏传即静默不渲染。**验收时按"产物是否有节点"判定，不按"代码是否写了组件"判定。**

## 8. 动效

### 8.1 3 档时长与缓动

| 变量 | 值 | 缓动 | 适用场景 | 禁止 |
|---|---|---|---|---|
| `--dur-fast` | `150ms` | `--ease-out cubic-bezier(.2,0,0,1)` | 按下态 / hover、颜色与 opacity 过渡、Toast 退出、tabBar 切换 | 禁止用于面板开合 |
| `--dur-base` | `240ms` | `--ease-out` | 抽屉 / Dialog 开合、状态切换、骨架→内容、导航透明→实底、Toast 进入 | 禁止用于整页转场 |
| `--dur-slow` | `360ms` | `--ease-out` | 整页转场、抽屉大幅位移 | 订单 / 支付 / 审核页面禁用 |
| `--ease-in`（新增） | `cubic-bezier(.4,0,1,1)` | — | 所有**退出**动效（与 ease-out 配对） | 禁止用于进入 |

**循环动效白名单**（不套用三档，需单独登记）：骨架 shimmer `1.2s ease-in-out infinite`（现状 1.4s）、`u-loading`、支付结果 pending spinner。除此之外**禁止任何无限循环动效**。

### 8.2 按下态反馈

| 元素 | 反馈 | 时长 |
|---|---|---|
| 全站可点 `view` | `hover-class="is-pressed"` → `opacity: .72`（现状 88 处，保持） | `--dur-fast` |
| `base-button` | `opacity: .82`；`ghost` / `text` 改用 `--c-surface-2` 底 | `--dur-fast` |
| `tabBar` 项 | 背景 `--c-surface-2`，`hover-stay-time: 80` | `--dur-fast` |
| 卡片 clickable / chip / 列表行 / picker 行 | 统一 `is-pressed` opacity .72 | `--dur-fast` |
| 遮罩层 / `@tap.stop` 容器 | **不加**按下态 | — |

规则：反馈幅度不超过 0.72–0.85 opacity；**禁止 `transform: scale()` 制造按压感**（小程序文字会模糊，Dialog 的 0.04 缩放是唯一例外）；按下态不得改变元素尺寸、边框宽度或布局；禁用态与 loading 态不响应按下。

### 8.3 页面转场与状态切换的克制原则

1. **页面转场只用系统默认**（`navigateTo` / `switchTab`），不自定义入场遮罩、视差、共享元素动画。订单、支付、审核页面禁用一切装饰性动效。
2. **状态切换只解释三种变化**：展开/收起、选中/未选、加载/完成。骨架→内容用 240ms opacity；错误→正常**不做动画**（直接替换，避免抖动）；列表刷新不整体抖动。
3. **动效不承载信息**：金额不做数字滚动；不虚构"正在完成"的进度；支付结果必须以服务端可信结果为准，动画不得暗示成功。
4. **减少动态效果**：尊重 `prefers-reduced-motion`，所有动效降为 0ms，骨架改静态色块，但**静态状态必须完整保留**（不能靠动画消失来表达状态）。
5. **性能**：动效只走 `opacity` / `transform`，不触发重排；首屏之外作品图延迟加载；上传 / 导出用真实进度或明确阶段。
