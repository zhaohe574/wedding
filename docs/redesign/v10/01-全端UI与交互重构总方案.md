## §0 总览与设计决策契约

### 0.1 一句话结论

当前小程序的「骨架」已经完成过一轮工程化（Token 语义化、三态外观、136 个页面头部统一、深色模式零 JS 首帧），**短板不在变量，而在质感与节奏**：

- 卡片靠 `1rpx` 描边分层，`--shadow-card` 恒为 `none`（`tokens.css:241 / 321 / 401 / 476`，4 处声明），全局没有任何暖调软阴影；
- 全站 369 处点击反馈是 `hover-class="is-pressed"` 的 `opacity: .82`（`globals.scss:70-72`），没有按压形变、没有回弹、没有触感分级；
- 31 个共享组件里没有 `snap-sheet`、没有 `useCountUp`、没有 `like-burst`、没有 `haptics.ts`；`uni.vibrateShort` 全站仅 1 处业务调用（`page-shell.vue:416`，下拉刷新越阈值）；
- 首页是「Hero + 数据条 + 2×2 机械网格 + 横滑 + 深色卡 + 时间轴」的稳定但平铺的节奏，四宫格 `grid-template-columns: repeat(2, 1fr)`（`index.vue:1032-1038`）是全站最典型的「连续相同网格」；
- 「我的」页黑金倒计时卡明确写着「筹备进度百分比后端无字段，进度条不画」（`user.vue:55`），这是本方案唯一需要动后端的真实业务缺口。

v10 的目标不是换一套配色，而是**把「工程正确」升级为「有物理质感的正确」**：暖调多层阴影替代硬描边、液态 Tab 与弹簧按压替代透明度闪烁、真实筹备进度替代空卡、可拖拽磁吸抽屉替代 26 处底部弹层。

### 0.5 验收口径（全案统一）

1. **零裸值增量**：新增样式不得出现 `#hex`、裸 `font-size` / `border-radius` / `font-weight: 700`；沿用 `redesign-zero-check.mjs` 口径。
2. **可访问性**：正文与背景 ≥ 4.5:1；交互控件边界 ≥ 3:1；状态必须「颜色 + 形状 + 中文词」三重编码。
3. **动效红线**：只动画 `transform` / `opacity`；单次入场 ≤ 600ms；`prefers-reduced-motion: reduce` 下所有装饰动效关闭、功能位移动画降为瞬时。
4. **数据红线**：任何数字必须有接口来源；取不到就隐藏区块或显示「—」，禁止写死样例值。
5. **构建门禁**：`type-check` / `build:mp-weixin` / `validate:dist` / `decorate:check` / `admin type-check` 全绿。

## §2 Design Token 与全局基础层升级规范

### 2.1 暖调多层柔和阴影 Token（浅色）

## §3 物理质感微交互与触觉系统设计

### 3.0 统一动效参数

```css
/* tokens.css 新增 */
--ease-spring: cubic-bezier(0.34, 1.56, 0.64, 1);  /* 过冲回弹 */
--ease-spring-soft: cubic-bezier(0.22, 1.2, 0.36, 1);
--dur-press: 120ms;
--dur-release: 420ms;
--dur-stagger: 100ms;
--stagger-max: 600ms;
```

**性能红线（微信真机）：**

1. 只动画 `transform` / `opacity` / `filter`（`filter` 仅限静态毛玻璃，不参与逐帧）。
2. 滚动相关计算走 `scroll-view` 的 `@scroll`，**节流 16ms 且只在跨阈值时写响应式**（`index.vue:508-525` 已是正确范式，直接复用）。
3. 视差/聚焦缩放优先用 **WXS 响应事件**（`src/wxs/` 新增）或纯 CSS `scroll-timeline` 降级方案；不支持时用 `@scroll` 节流。
4. 列表入场动画只加在首屏可见的 6–8 项，其余不做（避免长列表 setData 抖动）。
5. 所有动画节点加 `will-change: transform` 仅在动画期间（`animationstart` 加、`animationend` 删），不常驻。

### 3.1 按压弹簧回弹（`base-button` / `base-card` / `.press-spring`）

**机制（两段式真实阻尼过冲，解决「单段 transition 过冲仅 0.5% 看不出来、快点压不到 96%」的痛点）**：
1. **按下阶段**：90ms `ease-out` 压实至 `scale(0.96)`；快速轻点保底驻留 `≥ 75ms`，确保人眼与触感同时感知到下压；
2. **松手阶段**：触发 `@keyframes spring-release`（`440ms`）：`0% scale(0.96) → 42% scale(1.032) → 72% scale(0.993) → 100% scale(1)`，先略超原尺寸（`103.2%`）再温柔收稳到 `100%`；若手指中途变为滑动取消（`@touchcancel`），仅平滑复位，不播回弹。

```css
.press-spring {
    transform-origin: center center;
    will-change: transform;
}
.press-spring.is-pressing {
    transform: scale(0.96);
    transition: transform 90ms var(--ease-out);
}
.press-spring.is-rebound {
    animation: spring-release 440ms cubic-bezier(0.22, 1, 0.36, 1) both;
}
@keyframes spring-release {
    0%   { transform: scale(0.96); }
    42%  { transform: scale(1.032); }
    72%  { transform: scale(0.993); }
    100% { transform: scale(1); }
}
```

小程序落地：`base-button` / `base-card` 通过轻量状态机封装（`@touchstart` / `@touchend` / `@touchcancel`）切换 `is-pressing` / `is-rebound`，`prefers-reduced-motion: reduce` 下跳过变形直接响应。

**适用**：`base-button`（ink/gold/ghost）、独立可点详情卡（`base-card[clickable]`）、Tab、服务人像卡、媒体点击区。
**不适用**：整屏容器、滚动容器、输入框；**复合列表卡（如动态卡片、含底栏操作区的订单卡）严禁把缩放挂在包含操作按钮的最外层根容器上**，必须把内容点击区与点赞/评论/操作栏拆开，且子按钮显式声明 `hover-stop-propagation="true"` 与 `@touchstart.stop`，防止点点赞时整张卡跟着晃动。

### 3.2 液态 Tab 滑块（`app-tabbar` + 页面分段 Tab）

**机制**：胶囊内放一个绝对定位的 `tabbar__thumb`，宽度 = 1/4，`transform: translateX(index * 100%)`；切换时先 `scaleX(1.08)` 再回 `1`，形成「水滴拉长」。

### 3.4 等高骨架屏 + 双态暖调 Shimmer（`base-skeleton`）

**机制**：

**等高校验**：每个使用骨架的页面，骨架与真实内容的外层 `min-height` 必须相同；M1 在 `base-skeleton` 内提供 `height` prop，页面显式传设计稿高度。

### 3.5 点赞烟花微粒（新建 `<like-burst>`）

**结构**：`src/components/like-burst/like-burst.vue`，绝对定位 12 个 `<view class="spark">`，每个 `--a`（角度）、`--d`（距离 28–44rpx）、`--s`（尺寸 6–10rpx）、`--delay`（0–40ms）。

```css
.spark {
    animation: burst 560ms var(--ease-out) forwards;
    animation-delay: var(--delay);
    opacity: 0;
}
@keyframes burst {
    0% { opacity: 0; transform: translate3d(0,0,0) scale(.4); }
    18% { opacity: 1; }
    100% {
        opacity: 0;
        transform: translate3d(calc(cos(var(--a)) * var(--d)), calc(sin(var(--a)) * var(--d)), 0) scale(.2);

}
```

> 小程序 WCSS 不支持 `cos()/sin()`（基础库视版本），因此**预计算 12 组 `translate3d` 值**写成 12 个 class（`.spark--1` … `.spark--12`），运行时只切 class，不写内联函数。

**交互**：点按 → `like-burst` 播放 560ms → 图标 `scale(1.18)` 回弹 → 数字 +1（同时 `haptics.light()`）。
**克制**：每个点赞按钮 600ms 内只播一次；取消点赞不播。

### 3.7 数字滚动递增（新建 `<rolling-number>` + `src/composables/useCountUp.ts`）

核心数值（数据条、备婚倒计时天数、进度百分比、工作台三项指标与产能占比）优先采用**纵向滚轮式渐减速组件 `src/components/rolling-number/rolling-number.vue`**，避免纯 `setData` 逐帧替换文字造成的小数字跳变、急刹车与帧抖动：

- **滚轮结构**：按格式化字符拆位，数字位渲染 2 圈 `0–9` 纵向数字带（`.roll-reel`），外层裁剪盒固定 `height: 1.16em; overflow: hidden;`，上下加柔和渐变遮罩；符号位（`,` / `.` / `%`）静态占位。
- **渐减速曲线与错峰**：使用长尾指数渐减速曲线 `cubic-bezier(0.12, 0.96, 0.22, 1)`，单次位移 `transform: translate3d(0, -steps * 1.16em, 0)`；高位先落停（`1080ms`）、低位多转一圈顺次缓停（步进 `+150ms`、延迟 `+45ms`，末位 ≤ `1680ms`），彻底消除末尾生硬急刹。
- **微信真机性能**：整次滚动仅触发 **1 次** `transform` 过渡，全程走 GPU 合成层，零逐帧 `setData` 开销；无 DOM 滚轮场景再回退 `useCountUp(target, { duration, decimals })`。

```ts
// 回退方案：纯文本插值（如 Canvas / 非滚轮场景），同样走缓动曲线
export function useCountUp(target: Ref<number>, opts?: { duration?: number; decimals?: number }) {
    const display = ref(0)
    let raf = 0
    const run = () => {
        const from = display.value
        const to = Number(target.value) || 0
        const start = Date.now()
        const dur = opts?.duration ?? 1100
        const tick = () => {
            const p = Math.min(1, (Date.now() - start) / dur)
            // easeOutQuint：末尾长尾减速，避免急刹
            const eased = 1 - Math.pow(1 - p, 5)
            display.value = from + (to - from) * eased
            if (p < 1) raf = requestAnimationFrame(tick)
            else display.value = to
        }
        raf = requestAnimationFrame(tick)
    }
    onMounted(run)
    watch(target, run)
    onUnmounted(() => cancelAnimationFrame(raf))
    return display
}
```

**约束**：
- 只用于「首次进入/数据到位」一次，不用于每秒倒计时（倒计时用真实秒数直接渲染，避免抖动）。
- 显示层加 `.t-num` 锁定等宽数字，并且外层**固定字符宽度**（根据目标位数预留 `ch`），防止数字展开把布局顶开。
- `prefers-reduced-motion: reduce` 下直接渲染最终纯文本，不做滚轮过渡。

### 3.8 视差滚动（首页 Hero 与人员详情头图）

**机制**：Hero 图片容器 `height: heroHeight`，图片 `height: 120%`、`top: -10%`；滚动时 `translate3d(0, scrollTop * 0.35, 0)`，文字层 `translate3d(0, scrollTop * 0.12, 0)` + `opacity: 1 - scrollTop/heroHeight`。

**微信实现**：
- 优先 WXS：`src/wxs/parallax.wxs` 在 `scroll-view` 的 `bindscroll` 里直接 `setStyle`，**不经过 setData**。
- 降级：`@scroll` 节流 16ms，只在 `scrollTop` 变化 > 4px 时写一次。
- `prefers-reduced-motion` 或低端机（`getDeviceInfo().benchmarkLevel < 10`）关闭视差，图片静态。

**人员详情头图**：`staff-detail` 的 `cover` 同样处理，但位移系数 0.22（比首页克制）。

### 3.9 横向卡片滚动聚焦缩放（首页推荐位与作品横滑）

**机制**：`scroll-view scroll-x` + 卡片 `transform: scale()`；以容器中心为基准，距离中心越远缩放越小（1 → 0.88），并轻微降透明度（1 → 0.92）。

```
scale = 1 - min(0.12, abs(cardCenter - viewCenter) / viewWidth * 0.24)
```

**微信实现**：
- `scroll-view` 的 `throttle` 已默认；用 `@scroll` 拿到 `scrollLeft`，节流 16ms。
- 卡片宽度固定（如 156px），中心位置可算，无需 `createSelectorQuery`（避免每帧查询节点）。
- 只对首屏可见的 3–5 张卡做，超出不处理。
- `scroll-snap-type: x mandatory` + `scroll-snap-align: center` 让松手后自动吸附。

### 3.10 可拖拽半屏↔全屏磁吸底部抽屉（新建 `<snap-sheet>`）

**结构**：`src/components/snap-sheet/snap-sheet.vue`

```text
<view class="sheet-mask" />
<view class="sheet" :style="{ transform: `translate3d(0, ${y}px, 0)` }">
    <view class="sheet__handle" />
    <view class="sheet__head"><slot name="head" /></view>
    <scroll-view class="sheet__body" scroll-y><slot /></scroll-view>
    <view class="sheet__foot"><slot name="foot" /></view>
</view>
```

**三档磁吸**（均指 `translateY` 百分比，相对抽屉自身高度）：`closed`（`100%`）、`half`（`52%`，可视约 48% 屏高）、`full`（`6%`，顶部留出状态栏与胶囊）。
**手势**：
1. `touchstart` 记录 `startY` 与当前档位；
2. `touchmove` 计算 `dy`，`y = baseY + dy`，向上拖动时加阻尼（`dy * 0.9`），顶部越界 `y < 8%` 时 `dy * 0.35`；
3. `touchend` 用「位移 + 速度」双阈值判定：位移 > 25% 屏高或速度 > 0.5px/ms → 切换档位，否则回弹；
4. 抽屉内容滚动到顶且继续下拉时，才把手势交还给抽屉（否则让 `scroll-view` 自己滚）。

**性能**：只改 `transform`；拖拽中 `transition: none`，松手恢复 `transition: transform 320ms var(--ease-spring-soft)`。
**迁移清单**：26 处 `open-direction="bottom"` 的 `tn-popup`（见 §1.4.5），M4/M5 按「筛选类 / 操作类 / 确认类」分批替换；确认类（删除、支付）保留 `tn-popup` 居中弹窗，不改成抽屉。

### 3.11 轻触觉反馈分级表（新建 `src/utils/haptics.ts`）

```ts
type HapticLevel = 'light' | 'medium' | 'heavy'

const enabled = { value: true }

export function setHapticsEnabled(v: boolean) { enabled.value = v }

export function haptic(level: HapticLevel = 'light') {
    if (!enabled.value) return
    try {
        // 微信 type 仅支持 light/medium/heavy；H5 静默失败
        uni.vibrateShort({ type: level } as any)
    } catch {}
}
```

| 级别 | 场景 | 频率 |
|---|---|---|
| `light` | Tab 切换、筛选选中、点赞、勾选、日历选日 | 每次，但同控件 300ms 节流 |
| `medium` | 提交订单、支付成功、删除确认、抽屉吸附到全屏 | 每次 |
| `heavy` | 支付失败、档期锁定失败、危险操作二次确认 | 少量，仅错误/不可逆 |

**设置项**：`pkg-user/pages/settings/settings.vue` 增加「触感反馈」开关，持久化到 `storage`，默认开。
**降级**：`uni.vibrateShort` 在部分安卓机型无效，必须 `try/catch`，且**不能作为唯一反馈**（视觉反馈始终存在）。

#### 黑金总控卡的真实数据设计（关键）

**现状字段链：**

- `V2Logic::me()`（`server/app/api/logic/V2Logic.php:71-135`）返回 `wedding`：`date` / `days_remaining` / `venue` / `order_sn`；
- 数据来自 `UserLogic::weddingDate()`（`server/app/api/logic/UserLogic.php:522-584`），只查 `la_order` 的 `service_date / order_sn / service_address / contact_name`；
- `MeResponse`（`shared/contracts/dto.ts:306-325`）与 `WeddingInfo`（`288-293`）无进度字段；
- 前端因此不画进度条（`user.vue:55`）。

**新增聚合设计（不改现有 `weddingDate` 语义）：**

1. **新增** `server/app/api/logic/WeddingProgressLogic.php`
   - `public static function summary(int $userId): array`
   - **纯函数拆分**：`public static function buildMilestones(array $order, bool $questionnaireDone, bool $hasReview, string $today): array` 不碰 DB，只做字段判定与百分比；`summary()` 只负责查订单/问卷/评价三处并调用它。这样 `tests/unit/WeddingProgressTest.php` 可零 DB 断言 6 种百分比与 5 个节点状态。
   - 复用 `UserLogic::weddingDate()` 找到「当前婚期订单」：`pay_status = PAY_STATUS_PAID(1)` 且 `order_status ∈ {2 待服务, 3 服务中}` 且 `service_date >= today`，按 `service_date asc` 取第一条（与 `UserLogic.php:536-544` 完全同口径，抽成公共查询避免漂移）。
   - 里程碑只认真实表字段：

| # | 里程碑 | 判定（真实字段） | 数据来源 |
|---|---|---|---|
| 1 | 锁定档期 | `order.pay_status = 1` 且（`deposit_paid = 1` 或 `paid_amount >= total_amount`） | `la_order.deposit_paid` / `paid_amount` / `total_amount` / `pay_status`（`Order.php:69-72`） |
| 2 | 完成新人问卷 | 存在 `order_id` 对应问卷任务且 `status = 1 (SUBMITTED)` | `la_couple_questionnaire_task.status`（`CoupleQuestionnaireTask.php:22-26`） |
| 3 | 尾款结清 | `balance_paid = 1` 或 `balance_amount = 0` 且 `paid_amount >= total_amount` | `la_order.balance_paid` / `balance_amount` / `paid_amount` |
| 4 | 婚礼当天 | `service_date <= today` 且 `order_status >= 3` | `la_order.service_date` / `order_status`（`Order.php:55-66`） |
| 5 | 服务完成 | `order_status ∈ {4 已完成, 5 已评价}` 或存在 `la_review.order_id` 记录 | `la_order.order_status`；`la_review.order_id`（`Review.php:123`） |

   - **百分比**：`percent = round(doneCount / 5 * 100)`，**不做时间插值、不按天数估算**。未达成就是未达成，避免「假进度」。
   - **当前节点**：`current_key` = 第一个未完成里程碑；前端据此高亮。
   - **返回 DTO（新增，不动旧字段）：**

```php
'wedding' => [
    // ... 现有 date / days_remaining / venue / order_sn 原样保留
    'progress' => [
        'percent'      => 60,          // 0–100，真实完成数/5
        'done_count'   => 3,
        'total_count'  => 5,
        'current_key'  => 'balance',
        'milestones'   => [
            ['key' => 'deposit',      'label' => '锁定档期', 'done' => true,  'date_text' => '2026.09.12'],
            ['key' => 'questionnaire','label' => '新人问卷', 'done' => true,  'date_text' => '2026.09.20'],
            ['key' => 'balance',      'label' => '尾款结清', 'done' => false, 'date_text' => ''],
            ['key' => 'wedding_day',  'label' => '婚礼当天', 'done' => false, 'date_text' => '2026.12.20'],
            ['key' => 'completed',    'label' => '服务完成', 'done' => false, 'date_text' => ''],
        ],
    ],
]
```

   - `date_text` 只在该里程碑**已完成**或**有确定日期**时返回；`balance` 未完成时为空字符串，前端不显示日期。
2. **修改** `server/app/api/logic/V2Logic.php` 的 `me()`：新增一行
   `$progress = self::safe('wedding_progress', static fn () => WeddingProgressLogic::summary($userId), []);`
   并合入 `wedding.progress`。`safe()` 已存在（`V2Logic.php:30` 附近的分段容错），失败只降级该块。
3. **契约**：`shared/contracts/dto.ts` 的 `WeddingInfo` 增加可选 `progress?: WeddingProgress`；新增 `WeddingProgress` / `WeddingMilestone` 接口。字段可选，老接口不受影响。
4. **是否需要迁移**：**不需要**。5 个里程碑全部由既有列推导：`la_order.deposit_paid`、`balance_paid`、`balance_amount`、`paid_amount`、`order_status`、`service_date`、`pay_status`；`la_couple_questionnaire_task.order_id/status`；`la_review.order_id`。M2 只新增 Logic 与 DTO，不动表结构。
5. **性能**：`me()` 已聚合 5 个子查询；新增进度最多再查 2 次（问卷任务 `count`、评价 `count`），均走 `order_id` 索引；用 `safe()` 包裹，失败不阻断。若后续 QPS 压力大，可在 `la_order` 上加 `(user_id, pay_status, service_date)` 复合索引（**可选**，非必需）。
6. **接口边界**：不新增公开路由；`/api/v2/me` 一次返回。若「我的」页需要下拉刷新进度，直接重拉 `/api/v2/me`（现有 `onShow` 已做）。

## §6 风险、回滚与边界

| 风险 | 影响 | 缓解 |
|---|---|---|
| `backdrop-filter` 在部分安卓微信不生效 | 磨砂数据条退化为半透明底 | 提供 `@supports` 降级：`background: rgba(var(--c-surface-rgb), .94)` |
| `scroll-timeline` / WXS 视差兼容性 | 首页视差失效 | 统一走 `@scroll` 节流降级；低端机关闭 |
| 阴影过多导致滚动掉帧 | 长列表卡顿 | 列表项只用 `--shadow-card`（3 层），不用 `--shadow-card-hover`；hover 仅桌面 H5 |
| `snap-sheet` 与页面滚动抢手势 | 抽屉拖不动/页面误滚 | 抽屉打开时 `page-shell` 锁滚动（现有 `lockViewport`）；抽屉内 `scroll-view` 到顶才交还手势 |
| 进度接口拖慢 `/v2/me` | 个人中心首屏变慢 | `safe()` 并行/降级；进度查询最多 2 次 count，均有索引 |
| 装修新字段导致老数据异常 | 首页白屏 | `normalize*` 给默认值；`parseDecoratePage` 已有跳过与上报 |
| 全量替换弹层回归面大 | 交互不一致 | 按 M4/M5 分批，确认类不换；每批保留旧组件直到验收 |

**回滚策略：**
- Token 与组件层：`tokens.css` / `globals.scss` 单文件回滚即可恢复全局观感；
- 页面层：按批次独立提交（阶段二执行时），单页可单独 revert；
- 契约层：新字段全部可选 + 默认值，服务端先上、前端后上，回滚前端不影响接口。
