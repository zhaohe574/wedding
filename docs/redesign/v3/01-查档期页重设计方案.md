# 查档期页 UI 重设计方案（v3 · 档期册）

> 适用工程：`newuniapp/`（uni-app + Vue3 + TS + 微信小程序）
> 页面：`pages/query/query`（一级 Tab3）
> 版本：v3 · 2026-11-10
> 配套预览：`docs/redesign/v3/02-查档期页UI预览.html`

---

## 0. 一句话结论

把「查档期」从一张**条件表单**改成一张**以日期为主角的档期卡**：月历直接回答「哪天有档期」，选中日期后在卡内给出「可约人数 + 唯一 CTA」，地区/类型/风格/搜索收进同一张卡的底部；主页面仍然**不请求人员列表、不出现人员卡**，真正的可约人员仍在 `staff-list` 二级页。

三个关键变化：

| # | 变化 | 解决的问题 |
|---|---|---|
| 1 | 日期从「请选择」一行升级为**内联月历**，取消独立日期弹窗 | 查档期的第一决策是日子，不该先点开一个弹窗 |
| 2 | 新增**当月档期概览**（每日可约状态 + 选中日可约人数），只请求聚合数据 | 现在页面无法回答「这天到底有没有档期」，必须跳列表才知道 |
| 3 | 条件、状态、CTA 收进**同一张卡**，条件改为单行 chips | 纵向 5 行筛选 + 近期吉日卡把首屏占满，且日期与结果割裂 |

### 0.1 核心信息清单

| 核心信息 | 页面位置 | 回答什么问题 | 数据来源 |
|---|---|---|---|
| **档期日历** | 卡片主体，7 列 × 5/6 行 | 这个月哪几天有档期、哪几天是吉日 | `schedule.monthCalendar` + 聚合档期 |
| **可预约状态** | 日历格底部圆点 + 已选日状态行 | 这天有几位老师可约 / 是否已满 / 是否未知 | 聚合档期 `available_count` |
| **年月快切** | 月份标题 + `down-arrow` 原生 month picker；`‹` `›` `本月` | 快速跳到指定年月；默认最早可订日 | 前端视图 / `monthCalendar` |
| **可订规则** | 提前期锁定 + 图例右侧注记 | 今天与提前 3 天内不可选，最早能订哪天 | `la_schedule_rule.advance_days` |
| **查询条件** | 卡内单行 chips | 在哪个城市、什么类型、什么风格下查 | `region` / `category` / `tags` |
| **唯一行动** | 卡底 ink CTA | 看可约人员 / 换相邻日 / 先选地区 | 由状态驱动 |

## 1. 现状与目标

### 1.1 现状（`pages/query/query.vue`）

- 页面职责是「条件构建器」：婚礼日期、服务地区、服务类型、风格偏好、关键词，四项弹窗 + 一个「查询」按钮。
- **不请求 `/staff/lists`**，因此没有 loading / 空态 / 错误态，页面不随网络抖动；这是 v2 拆分最大的收益。
- 但代价是：日期只是一行「请选择」，用户看不到任何档期信息；真正的「这天有没有人」要到二级页才出现。
- 日期弹窗是自绘月历，只承载「选一个日期」，不承载「看档期」；`getMonthCalendar`（含吉日、农历、节假日）**从未接线**。
- 近期吉日 chips 与日期弹窗里的吉日 chips 信息重复，都是为了在「没有月历」的前提下补一点日期感知。

### 1.2 设计目标

1. **日期优先**：打开页面先看到月历，最早可订日/已选日清楚，月份可翻。今天与提前期内日期默认不可选。
2. **一屏回答**：选中日期后，在同一张卡里回答「有没有档期、有几位、下一步做什么」。
3. **状态可信**：有档期、无档期、加载中、空数据、加载失败、未选地区，六种情况都有明确视觉与文案；**未知绝不伪装成 0 或已满**。
4. **不越边界**：主页面不出人员列表、不出分页/排序、不做收藏；可约人数只做聚合概览，不承载人员卡。
5. **与项目一致**：只用 `tokens.css` 的颜色/字号/圆角/间距；复用 `page-shell`、`status-tag`、`base-button`、`base-skeleton`、`base-empty`、四个既有 sheet。

### 1.3 不做什么

| 不做 | 原因 |
|---|---|
| 本页出人员卡 / 分页 / 排序 / 收藏 | 列表仍在 `staff-list`，避免复制 588 行列表逻辑 |
| 单人档期日历 | 那是 `staff-detail` / `booking` 的语境，不是全站查档期 |
| 编造「每日剩余名额」 | 后端只有 `remaining`（单人单日剩余档数），没有「某天全站还剩几人」 |
| 用金色表示可约 | 金色在本项目里是品牌/吉日，不是成功语义；会与吉日标记打架 |
| 用红色表示已满 | 红色是必填/错误；「已满」是正常业务状态 |
| 吸底 CTA | tabbar 是 `fixed z-index:100`，吸底会被压住并吃掉屏高（v2 已论证） |
| 新增第 2 套图标 / 第 7 个圆角 | 全站只用一个 `tn-icon` 图标族、6 档圆角 |

### 2.4 复用清单

| 组件 | 用法 |
|---|---|
| `page-shell` | `tabbar` / `current="/pages/query/query"` / `title="查档期"` / `show-back=false`；标题居中（默认） |
| `base-button` | CTA：`variant="ink" size="lg" block`；加载态 `loading` |
| `status-tag` | 「吉日」`tone="primary" size="sm" dot=false`；「仅 1 位」`tone="warning"` |
| `base-skeleton` | 首次加载的日历骨架（或自绘格子骨架，见 §6） |
| `base-empty` | 整月加载失败时的区块级错误（`fixed=false`） |
| `tn-popup` | 地区/类型/风格三个 sheet 原样保留 |
| `tn-icon` | 仅用现有图标：`calendar`、`search`、`close`、`right`、`down-arrow` |

### 2.5 三条实现铁律

1. 页面不写裸色值/裸字号；所有样式走 `var(--*)`。
2. 卡片不加阴影、不加渐变；浮层才允许 `--shadow-float`。
3. 任何状态文案都必须能独立读懂，不依赖颜色。

## 4. 核心信息与视觉编码

### 4.1 档期日历

**日历回答什么**：在当前「服务地区 + 服务类型」语境下，每一天有多少位老师可接单。它是**聚合视图**，不是某一位老师的档期；单人日历仍在老师详情/预约页。

| 格子状态 | 视觉 | 语义 | 可点 |
|---|---|---|---|
| 普通 | 日号 `--c-ink` | 该日无特殊标记 | 是 |
| 可约 | 日号 + 底部 8rpx 实心绿点 | `available_count > 0` | 是 |
| 紧张 | 日号 + 底部 8rpx 琥珀点 | `available_count === 1`（或 ≤ 阈值） | 是 |
| 已满 | 日号 `--c-ink-3` + 删除线 + 8rpx 空心点 | `available_count === 0`，**已知** | 是（看状态、找相邻日） |
| 未知 | 日号正常、无点 | 没有该日数据 | 是（选中后显示「待更新」） |
| 吉日 | 日号右上 8rpx 金点 | `is_lucky_day === 1` | 叠加在以上任意状态 |
| 提前期 / 今天 | 整格 45% 透明；今天底部「今」，无点 | `today <= date < minSelectable` | 否 |
| 今天（允许当日订） | 日号 1rpx ink 内描边圆 | `date === today && today >= minSelectable` | 是 |
| 已选 | 72rpx ink 实心圆 + 白字 | 当前查看日期 | — |
| 已过 | 整格 35% 透明 | `date < today` | 否 |

**关键细节**

- `minSelectable = today + advance_days`（全局 `la_schedule_rule.staff_id=0`，默认 3 天）。今天到 `minSelectable - 1` 为提前期：45% 透明、无点、不可点；今天格底部显示「今」字，**不再用今天圆环**（圆环会被误读为可选）。
- 图例右侧显示「最早可订 11.13」，只在当前月含提前期锁定时出现；切到整月都可订的月份时不显示，避免无意义注记。
- 「本月」= 回到当前月并选中最早可订日，不是选中今天；今天在任何情况下都不作为默认选中项。
- 默认选中最早可订日；若该日已满，自动顺延到下一个可约日（最多顺延 7 天），没有则停在最早可订日并显示已满。
- 今天（配置允许当日订）+ 选中：ink 实心圆外再加 1rpx ink 外环（中间留 2rpx 面色），两种状态同时可读。
- 选中 + 可约：状态点移到 ink 圆内底部，改为浅绿 `#A9C0AC`，保证「选中」不吞掉「可约」；选中 + 仅 1 位用浅琥珀。
- 选中 + 已满：**不填实心**，改为 ink 内描边 + 保留删除线；否则白字删除线语义会丢。
- 已满的删除线用 `text-decoration: line-through`；小程序端 `text` 支持，真机需回归一次。
- 吉日金点放在格子右上角，不占用底部状态点；金点直径 8rpx，不与日号圆重叠。
- 格子 88rpx 高、约 94rpx 宽；点击热区就是整格，不做二次放大（避免相邻格热区重叠）。
- 月历**不显示农历小字**：35–42 个农历字会让网格密度翻倍，农历只在已选日期行出现。
- 月份行数 5/6 自然变化；切月用 240ms 交叉淡入，不做固定 6 行留白（避免 5 行月份出现空白行）。

### 4.2 可预约状态

**口径**：`available_count` = 当前地区 + 类型下，该日可接单的老师人数。不是「剩余档数」，文案统一用「位」。

| 状态 | 触发 | 圆点 | 主文案 | 副文案 | 色调 |
|---|---|---|---|---|---|
| 充足 | `count >= 5` | 实心绿 | `8 位可约` | `档期充足` | success |
| 较紧 | `2 <= count <= 4` | 实心琥珀 | `3 位可约` | `档期较紧` | warning |
| 仅 1 位 | `count === 1` | 实心琥珀 | `仅 1 位可约` | `建议尽快确认` | warning |
| 已满 | `count === 0`（已知） | 空心中性 | `当日档期已满` | `可看相邻日期` | neutral |
| 未知 | 无数据/请求失败 | 灰色虚线圆 | `档期信息待更新` | `重新获取` | neutral |
| 未选地区 | `region === null` | 无 | `选择服务地区后查看可约人数` | `去选择 ›` | neutral |

**文案纪律**

- 不用「仅剩 1 档」：那是单人单日的剩余档数（`remaining`），全局页是「1 位老师可约」，单位必须用「位」。
- 不用「0 位可约」：已满直接说「当日档期已满」，比数字更可读，也不制造「没人」的歧义。
- 未知不写 0、不写已满；「不知道」和「没有」是两件事（与 v2 §9.5 的 `remaining: null` 同一原则）。

### 4.3 年月快速切换（替代原日期筛选）

原「全部 / 吉日 / 周末」三枚日期筛选 chip 已移除：它们是纯视图强调，不参与查询参数，却带一个默认选中态 `all`，容易让用户误以为日期被过滤。日期导航现在只保留三个入口：

| 入口 | 行为 | 视觉 |
|---|---|---|
| **月份标题 + `down-arrow`** | 点击打开原生 `picker mode="date" fields="month"`，可选 `start = 最早可订月` 到 `end = 最晚可查月` | `11月` 右侧 20rpx `down-arrow`，`--c-ink-3` |
| `‹` / `›` | 上一个月 / 下一个月；到边界时停在最早可订月 / 最晚可查月 | 56×56rpx 热区，`--c-ink-2` |
| `本月` | 回到可订月并选中最早可订日 | `--fs-21` `--c-brand-text` |

**切换后的同步**（三个入口共用 `jumpToMonth`）：视图年月 → 选中日期（目标月第一个可订日）→ `monthCalendar` → 选中日可约人数，全部一起更新；如果选中日已在目标月，则保留选中日，只刷新日历。

**为什么移除筛选**：默认「全部」是一个隐式状态；「吉日/周末」只改变透明度，不改变结果，保留了也没有决策价值。移除后少一行、少一套 state，首屏高度让给月历。

### 4.4 条件 chips

| chip | 未选 | 已选 | 点击 |

| 服务地区（必选） | `* 选择地区`，虚线边，`--c-ink-3` | `* 杭州·西湖区`，实线边，`--c-ink`；**不带 `×`** | 开地区 sheet；必选，不能清空 |

| 风格偏好 | `先选类型`（未选类型）/ `风格不限`（已选类型） | `大气、中式` 或 `已选 3 项`；带 `×` | 开风格 sheet；未选类型时 toast + 高亮类型 chip |
| 搜索 | 圆形 `⌕` 56rpx | 展开 88rpx 输入行，`取消` 在右 | 展开输入；**输入即筛选（300ms 防抖）**，无需回车；`×` 清空并撤销，`取消` 关闭并撤销 |

## 5. 主要操作流程

### 流程 A · 有档期（主路径）

1. 进入页面 → 月份定位当前月，默认选中**最早可订日**（今天 + `advance_days`，默认 3 天）；今天与提前期内日期不可选，今天格显示「今」。
2. 若缓存里有地区/类型/风格 → 自动恢复；聚合档期请求返回 → 日历出现绿点，状态行显示「8 位可约」。
3. 用户点 11.13 → 选中态 150ms 过渡，状态行局部 loading（不闪整卡）→ 显示当日人数。
4. 用户点「吉日」→ 非吉日降饱和；点 11.28 → 自动回「全部」并选中。
5. 点 CTA → 跳 `staff-list?from=query&date=2026-11-13&...`；列表页只读摘要 + 排序。

### 流程 B · 无档期

1. 点一个已满日期（如 11.28）→ 日号删除线 + 空心点，状态行显示「当日档期已满」。
2. 状态行下方给出相邻可约日：`11.27 周五 · 3 位可约`、`11.29 周日 · 8 位可约`。
3. 点相邻日 chip → 直接切换选中；或点 CTA「看看相邻可约日」→ 自动选最近的一个。
4. 仍想沟通 → 状态行右侧 `联系客服协调` 文字链，进客服页。

### 流程 C · 未选地区（首次进入）

1. 日历只显示吉日/提前期/已过，不显示可约绿点（没有地区就没有口径）。
2. 状态行：「选择服务地区后查看可约人数」+「去选择 ›」。
3. 地区 chip 虚线 + `*` + `选择地区`；CTA 文案「选择服务地区」。
4. 点 CTA 或 chip → 地区 sheet；选完 → 自动拉聚合档期 → 绿点与人数出现，CTA 变「查看 N 位可约人员」。

### 流程 D · 换月 / 年月快切

1. 点月份标题 → 原生年-月选择器；选完直接跳到该月。点 `‹` `›` 逐月切换，到边界停住。
2. 切月/跳月后自动选中该月第一个可约日；当月则选**最早可订日**（今天 + `advance_days`），状态同步；不需要「先点日期再等状态」。
3. 视图更新时旧网格 40% 透明 + 顶部 2rpx 金色进度线；新数据回来后交叉淡入。
4. 「本月」→ 回到可订月并选中最早可订日；今天永远不是默认选中项。

### 流程 E · 搜索（输入即筛选）

1. 点 `⌕` → 条件行下方展开 88rpx 输入行，自动聚焦，右侧「取消」。
2. **输入即筛选，无需回车**：300ms 防抖后把输入写入 `form.keyword`，重拉选中日可约人数；输入框与状态行同步进入 loading，旧请求用 `seq` 作废。
3. 按回车不强制，但会跳过防抖立即应用；不会自动跳列表。
4. 点输入框内 `×`：清空输入、撤销关键词、恢复完整人数，输入行保留，方便继续输入。
5. 点「取消」：关闭输入行 + 清空 + 撤销筛选 + 恢复完整人数；若防抖还没触发，定时器一并清掉，避免取消后又被旧输入覆盖。
6. 关键词只影响本页的人数/CTA；点 CTA 才带 `keyword` 进 `staff-list`，列表页仍是唯一出人员卡的地方。

### 6.2 各状态的关键视觉

**有档期**

- 状态行：`●` 实心绿 12rpx + 数字 `8`（serif 33rpx）+ `位可约`（21rpx）+ `· 档期充足`（20rpx `--c-ink-3`）。
- CTA 数字与状态行一致；两处数字必须来自同一份数据，不允许一个 8 一个 9。

**今天 / 提前期**

- 今天到 `minSelectable - 1`：日号 45% 透明、无点、不可点；今天格底部 7–8px 的「今」字，颜色 `--c-ink-2`，不加圆环。
- 图例右侧显示「最早可订 11.13」；它解释 10–12 为什么不可选，比逐格加锁图标更安静。
- 该日不显示可约/已满/吉日以外的状态点；吉日金点仍可显示（日期属性与可订性无关）。

**无档期**

- 状态行：空心圆 12rpx（1rpx `--c-ink-3`）+ `当日档期已满`（27rpx `--c-ink-2`）。
- 相邻日 chips：`11.27 周五 · 3 位可约`，高 48rpx，`--c-brand-bg` 底、`--c-brand-text` 文字；最多 2 枚，超出折叠为「更多日期 ›」。
- CTA 仍是 ink：不要把「已满」做成灰色禁用按钮——用户还有「换日期」这条路。

**加载中**

- 首屏：月份头 + 星期行先出；网格用 `--c-surface-2` 的 28×16rpx 圆角块（每格一个），1.2s shimmer；状态行两行骨架；CTA 禁用。
- 换月：保留旧网格，整块 `opacity: .4`，月份头下方 2rpx 金色进度线（`--c-brand`），数据回来后 240ms 淡入。
- 选日：只有状态行换成两行骨架，日期格子保持可点；请求 200ms 防抖，旧请求 abort。

**空数据**

- 不用红色、不用「失败」措辞；状态行中性圆点 + `档期信息待更新` + `重新获取` 文字链。
- 日历仍显示吉日、提前期、已过；没有任何可约点。
- CTA 保留「查看该日人员」，因为列表页可能仍能返回结果；不能因为概览失败就阻断主链路。
- 若整月确定无档期（不是未知），文案换成「本月暂无可预约档期」+「看看下个月」，这是**已知的空**，与未知区分。

**未选地区**

- 状态行文案是引导，不是错误：`选择服务地区后查看可约人数`；`去选择 ›` 用 `--c-brand-text`。
- CTA 文案直接变成「选择服务地区」，点击开 sheet；这比「查询」+toast 更直接。
- 日历不显示可约点；否则不同地区的点会混在一起，误导。

### 6.3 空数据 vs 无档期（必须区分）

| | 空数据 | 无档期 |
|---|---|---|
| 含义 | 不知道 / 数据未同步 | 明确知道 0 位 |
| 日历 | 无点 | 删除线 + 空心点 |
| 状态行 | `档期信息待更新` | `当日档期已满` |
| 色调 | 中性 | 中性（不是错误） |
| CTA | `查看该日人员` | `看看相邻可约日` |
| 是否可以显示 0 | **不可以** | 可以（文案不写 0） |

## 7. 响应式与屏幕适配

### 7.1 断点策略

全站只有一条 `@media (min-width: 600px)`：容器 `max-width: 600px` 居中。本页不新增断点、不做平板双栏、不做第二套字号。

| 屏宽 | 表现 |
|---|---|
| 320px | 7 列仍一行；日号 29rpx ≈ 12.4px；条件 chips 横滑；CTA 全宽；无横向溢出 |
| 360/375px | 基准；卡片内宽约 330px；7 列每列约 47px；CTA 完整 |
| 390/414px | 卡片更舒展；月历格仍 88rpx 高，不拉高 |
| ≥600px | 页面 600px 居中；卡片随容器；月历不变成两列；字号不放大 |

### 7.2 320px 的具体处理

- 页面左右 gutter 从 42rpx 收到 30rpx？不：`--page-gutter` 保持不变，卡片外边距 30rpx 已足够；7 列每列约 `(320-60-52)/7 ≈ 29.7px`，日号 12.4px 可容纳两位数字。
- 条件 chips 一定横滑，`overflow-x: auto` + 隐藏滚动条 + 右侧 24rpx 内边距；不换行、不压缩字号。
- 图例三项 + 「最早可订 11.13」注记在 320 下排一行；放不下时注记换到第二行，不缩字号、不删注记。
- 今天「今」字在 320 下 6.5–7px，仅作辅助；锁定语义主要靠 45% 透明、不可点与注记，不依赖这个小字。
- CTA 文案在 320 下可能超长：`查看 8 位可约人员` 9 字 × 16px ≈ 144px，卡片内宽 260px，安全；「看看相邻可约日」7 字更短。
- 禁止横向滚动整个页面；只有 chips 行允许内部横滑。

### 7.3 高度与安全区

- `page-shell tabbar` 已提供 `padding-bottom: calc(var(--tabbar-h) + safe-bottom + 24rpx)`，页面不再自己加。
- 卡片底部到 tabbar 至少 24rpx；CTA 不吸底。
- iPhone SE（320×568）：允许 CTA 在首屏下方 60–80px；不为了塞下 CTA 压缩月历到 5 行以下。
- 横屏 / 平板：容器居中，左右留白；不拉伸月历格。

### 7.4 6 行月份

- 2026 年 11 月 30 天、1 日周日 → 5 行；12 月 31 天、1 日周二 → 5 行；部分月份 6 行。
- 切月行数变化时卡片高度变化 88rpx；用网格区交叉淡入 + 卡片高度过渡（若实现成本高，接受 88rpx 跳动，不做固定 6 行留白）。
- 验收时至少检查一个 6 行月份（如 2027 年 1 月：31 天、1 日周五 → 6 行）。

| 每日吉日/农历/节假日 | `schedule.monthCalendar` | 有，但从未接线；本方案接入 |
| 每日全站可约人数 | 无 | **已新增聚合接口**（§10.2，本次已实现） |
| 单人每日是否可约 | `schedule.staffSchedule` | 有，但只适合单人页 |
| 指定日期的可约人数 | `staff/lists?date=` 的 `total` | 可算，但会拉全量 ID 逐个 `isAvailable()`，N+1，不能用于每日网格 |

### 10.2 已实现：`schedule.availabilityOverview`

```
GET /schedule/availabilityOverview
  start_date=2026-11-01
  end_date=2026-11-30
  province_code=330000
  city_code=330100
  district_code=330106
  category_id=3            // 可选
  tag_ids=1,2              // 可选
  keyword=张               // 可选
```

返回：

```json
{
  "start_date": "2026-11-01",
  "end_date": "2026-11-30",
  "days": [
    { "date": "2026-11-11", "available_count": 1 },
    { "date": "2026-11-12", "available_count": 0 }
  ]
}
```

- **只返回事实（人数）**，不返回 status：前端按 `0 = full / 1 = limited / ≥2 = available` 统一推导，选中日与整月共用同一套阈值，避免两处口径。
- 未选到区县时 `days: []`（没有地区就没有可约口径），前端保持无点 = 未知，不补 0。
- 缓存键 = `date_range + 地区 + category_id + tag_ids + keyword`；前端内存缓存 60s。
- 单次区间 ≤ 62 天（后端硬保护）；返回按日期升序。
- 性能：`ScheduleAvailabilityService::countByDates()` 一次预取人员规则、档期记录、每日占用名额，再在内存里逐人逐日判定；查询数从 3×N×M 降到约 6 次。
- 口径与 `/staff/lists?date=` 的 `count` **完全一致**（同一个 `isAvailable` 语义），所以角标数字就是点进去看到的人数。

### 10.3 过渡方案（接口未就绪时）

| 阶段 | 月历 | 状态行 | CTA | 当前 |
|---|---|---|---|---|
| P1（聚合接口） | 每日绿/琥珀/空心点，来自 `availabilityOverview` | 选中日精确人数，来自 `staff/lists?date=` | 正常 | ✅ 已实现 |
| P0（后端未部署时） | 只有吉日/农历/提前期/已过，无状态点 | 选日后 `getStaffList({ page_size: 1 })` 取 `total` | 正常 | 自动降级 |
| P2（推荐态） | 相邻可约日、整月无可约文案 | 同 P1 | 已满时给相邻日 | ✅ 已实现 |

- 主页面仍**不拉人员列表**，只拉 `page_size=1` 的 `total`；翻月只请求 `monthCalendar` + `availabilityOverview`，不逐日请求。
- 聚合接口失败时 `overviewMap` 清空（未知），页面不会退回「全部已满」。

### 10.4 文案口径与业务规则

- `available_count` 是「位老师」，不是「档」；所有文案用「位」。
- 单人剩余档数 `remaining` 仍只在 `staff-list` 角标使用（「仅剩 1 档」）。
- 未知不显示 0；`status=unknown` 时状态行给「待更新」+ 重试。
- `minSelectable = today + advance_days`：取全局规则 `la_schedule_rule.staff_id = 0`（当前默认 `advance_days = 3`）。今天到 `minSelectable - 1` 不可选；默认选中 `minSelectable`。**UI 不写死 3 天**——业务若只要求禁当日，把 `advance_days` 配成 1 即可。
- 地区是硬必选：`available_count` 必须在 `city_code + district_code` 语境下计算；缺区县时返回 `unknown`，**不允许回落到全国**，也不显示可约点/人数。

### 11.2 状态模型（建议）

```ts
type DayStatus = 'available' | 'limited' | 'full' | 'unknown'
type ViewState = 'loading' | 'ready' | 'error' | 'empty'

interface DayCell {
  date: string            // YYYY-MM-DD
  day: number
  isToday: boolean
  isPast: boolean
  isLocked: boolean       // today <= date < minSelectable（提前期）
  isLucky: boolean
  isHoliday: boolean
  lunar?: string
  status: DayStatus
  availableCount: number | null   // unknown 时为 null，不是 0
}

interface SelectedDay {
  date: string
  status: DayStatus
  availableCount: number | null
  neighbors: { date: string; label: string; count: number }[]
}
```

- `availableCount` 为 `null` 表示未知；模板里所有 `0` 判断必须先排除 `null`。
- 请求竞态：每次请求带 `requestId`，只接受最后一次；切月/切日都要 abort 或忽略旧响应。

## 附：与 v2 方案的差异（评审用）

| v2 决策 | v3 调整 | 理由 |
|---|---|---|
| 日期是一行「请选择」+ 弹窗 | 内联月历卡 | 日期是查档期的第一决策；弹窗把「看档期」推迟了一步 |
| 日期默认今天、`minDate=today` | 今天不可选，默认**最早可订日**（today + `advance_days`） | 业务要求提前预订；避免默认选中一个必然无档期的日期 |
| 地区必选但仍带 `×` | 地区硬必选、**无 `×`**、未选不出可约点/人数 | 地区是档期口径的一部分，不是可清空的筛选 |
| 主页面零请求 | 只增加 1 个**聚合档期**请求 | 仍然不请求人员列表；但「有没有档期」必须在主页面回答，否则这页只是表单 |
| 近期吉日独立卡 | 并入月历（金点 + 吉日筛选 + 已选 tag） | 去掉重复的日期列表，减少一屏高度 |
| 5 行纵向筛选 | 1 行 chips（仍一条件一入口） | 把首屏让给月历；行为和 sheet 完全不变 |
| 无 loading/空态/错误态 | 4 个主状态 + 2 个降级态 | 有了聚合请求就必须设计状态；未知与已满严格区分 |
| 不显示人数 | 显示「可约人数」聚合值 | 用「位」不用「档」；不涉及人员卡、不分页、不排序 |

v2 的底线仍然保留：**主页面不出人员卡、不出列表、不出排序、不做吸底 CTA、条件只有一个真源**。
