## 2. 页面与组件地图（`newuniapp/src/`）

- 配置：`newuniapp/src/pages.json`（338 行），自定义 tabBar（4 项：首页 / 订单 / 消息 / 我的），5 个分包，29 页需登录。
- 主包 11 页：`index` 首页、`order` 订单列表、`message` 消息列表、`message/detail`、`search` 搜索、`user` 我的、`login` 登录、`agreement`、`customer-service`、`about`、`webview`。
- `pkg-catalog` 6 页：`query` 查档期（表单）、`staff-list` 人员列表、`staff-detail` 人员详情、`booking` 预约（1150 行，3 步 + 报价）、`article-detail`、`case-list`。
- `pkg-user` 3 页：`profile` 个人资料、`settings` 设置、`favorite` 收藏。
- `pkg-order` 5 页：`detail` 订单详情、`review/list`、`review/publish`、`waitlist`、`payment-result`（success/fail/pending 三态）。
- `pkg-service` 15 页：`aftersale/index` 枢纽 + 工单/投诉/回访各「列表-创建-详情」+ `questionnaire/detail` 新人问卷 + `change/*` 变更记录/改期/暂停/加项。
- `pkg-staff` 2 页：`order-list`、`schedule` 月历档期。
- 主链路：`index` → `query` → `staff-list` → `staff-detail` → `booking` → 订单详情 → `payment-result` → `order`；个人中心 → 订单/评价/候补/收藏/资料/设置/售后/问卷/服务人员中心；消息 → 详情（`composables/useNotificationRouter.ts` 为消息路由唯一来源）。
- 基础组件（`newuniapp/src/components/`，10 个，零 hex 硬编码）：`app-tabbar`、`nav-bar`、`base-button`、`base-card`、`base-input`、`base-empty`、`base-skeleton`、`section-header`、`status-tag`、`price`。
- 组件库：`vk-uview-ui@1.3.12`（不引入新框架），业务实际只用 `u-icon`（92 处）、`u-parse`、`u-loading`；`uni.scss` 已把 30+ `$u-*` 桥接到 `var(--c-*)`。

## 4. 现状问题清单（重设计要解决的）

1. **字重单薄**：`newuniapp` 业务代码只有 `font-weight: 500`（92 处），无 600/700，标题层级仅靠字号，信息层级扁平；行高 1.4/1.5/1.6/1.7/1 五档混用。
2. **状态色可访问性临界**：`neutral` 4.48:1 逼近 AA 4.5:1；`--c-ink-3 #756f66` 在小字号下需复核；浅底状态标签对比度需实测。
3. **规范文档漂移**：`rebuild-plan/04-功能与页面设计.md:312-355` 的 token 草案与现行 `tokens.css` 冲突（如 `--c-ink-3 #9A948B` vs `#756f66`、`--c-gold` vs `--c-brand`、`--shadow-card 有阴影` vs `none`、success `#607361` vs `#48644b`），须由本次规范裁决并回写。
4. **组件缺口 6 类**：`Steps`（booking 内联 `.steps`）、`FormField/Form`（各页私有 `.picker`/`.row`，`base-field` 暂缓）、`LoadMore`（7+ 页重复 `.loadmore__text`）、`ResultPage`（结果页未组件化）、`Toast` 统一层（387 处 `showError` + 60 处 `uni.showToast` 双轨）、`Navbar` 状态/安全区契约。
5. **状态反馈不一致**：`booking.vue` 同页两套失败 UI（手写 `.fallback` + `base-empty status="error"`）；`payment-result` 三个操作按钮无主次层级且用历史别名 `variant="brand"`；`order.vue` 等页错误态伪装成空态（存量端问题，新端需防回归）。
6. **加载/成功/失败/空态**：骨架屏 28 处、`base-empty` 45 处、`request/index.ts` 有 `loadingCount` 引用计数全局遮罩；`request/error.ts` 已定义 network/401/403/5xx 与 `retryStrategy`，`base-empty` 有 `errorKind` 四分类（network/business/permission/unknown）；但状态文案分散在页面，无 SSOT。
7. **触控与适配**：`base-button` md=88rpx、sm=60rpx 用 `::before` 扩到 88rpx 热区；`section-header`/`base-input` 88rpx；95 处 `hover-class`；`nav-bar` 状态栏 + 固定 44px + 占位；`base-input` 有 `cursor-spacing`；但业务代码几乎不直接用 `env(safe-area-inset-bottom)`，fixed 底栏安全区需复核；无大字模式/夜间模式（明确不做）。
8. **图标**：`u-icon` 92 处，尺寸已收敛为 24/32/40/48/96rpx；`size` 单位是 rpx（历史 89 处曾按 px 语义误用，视觉仅标称一半，已修）；`base-empty` 用 uView 语境图标；`static/images/tabbar/` 6 张 PNG + 默认头像；无 SVG。
9. **视觉回归重点页**：`index`（hero 560rpx 在 320px 窄屏占近半屏、分类被挤出折线、搜索胶囊浮层与自定义导航耦合）、`user`（hero 渐变 + 倒计时卡、三角色枢纽）、`order`（卡片高度、金额与状态标签基线、长标题两行截断）、`staff-list`（筛选吸顶、1rpx 描边、价格档位、星标）、`staff-detail`（信息层级最复杂）、`booking`（3 步 + 常驻摘要 + 实时报价）、`pkg-order/detail`（状态头 + 金额三段 + 底部固定操作栏）、`payment-result`（金额 64rpx、三态）、`schedule`（月历色点状态语义）。
10. **存量端迁移注意**：`uniapp` 3572 处 hex 硬编码 / 20+ 字号档 / 14 圆角档 / 字重 900 泛滥 / 运行时主题死链路 / 5 套样式来源，若未来迁移须全量换 token，不可照搬其视觉。

## 5. 用户诉求（验收总纲）

- 覆盖所有主要页面与通用组件：首页、核心功能页、详情页、表单与反馈页、个人中心、导航栏、按钮、卡片、图标等。
- 明确新的整体视觉方向；统一色彩、字体层级、间距、圆角、分割线、图标与组件样式。
- 优化信息层级、留白、视觉重点、加载状态、成功与失败反馈、空状态和异常提示。
- 保留现有功能逻辑、主要操作路径与核心内容。
- 不同屏幕尺寸下文字可读、触控区域合理、状态区分清晰。
- 交付：完整视觉规范 + 逐页改造说明 + 可落地的组件样式调整清单 + 可检查的验收要点。
