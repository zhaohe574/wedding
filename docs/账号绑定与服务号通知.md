# 账号绑定与服务号通知

## 本次解决的问题

服务人员原先存在两套独立的用户关联：档案记录用户，后台账号另行绑定用户。自动建档没有补齐后台关联，编辑用户也不同步，导致工作台身份和通知接收人不一致。本次将关系变更收敛到统一事务入口。

原服务号页面混合了关注、微信绑定和后台身份关联，且把未知关注状态显示成未关注。本次移除后台自助关联，按实际关注和绑定状态引导。

原站内提醒按文案去重，内部提醒缺少业务目标。业务通知现使用事件名称、实例编号、接收用户和身份生成唯一标识，渠道投递另外去重。服务号入队表示待发送，不表示微信已送达。

## 账号关系与操作

- 一个平台用户最多关联一个后台账号和一个服务人员档案。后台账号可同时具有服务人员、顾问等角色；角色的数据范围仍独立校验。
- 服务人员新增时必须绑定平台用户并开通后台账号。新账号沿用手机号账号及初始密码，首次登录强制修改。选择已有后台账号需要独立的账号绑定管理权限，不改动原密码。
- 资料编辑不能换绑。授权管理员在账号绑定区域搜索用户并填写原因，进行绑定、换绑或解绑。换绑仅代表同一个人更换小程序账号。
- 换绑同步后台与人员档案，撤销旧工作通知及后台会话，作废后台关联会话，记录操作审计。历史订单、结算、客户仍属于原业务档案；历史消息不会转给新用户。
- 解绑服务人员会同时停用工作入口。普通客户身份不受影响。恢复工作入口前必须建立一致关系。
- 后台密码重置仍使用关联用户手机号，同时强制改密并撤销旧会话。手机号不用于推断身份或自动认领已有账号。
- 工作人员个人设置只展示关联状态。旧自助提交、确认和撤销接口返回“账号关联由授权管理员统一管理”。

## 服务号关注流程

提醒已改为业务操作前按需检查：独立登录完成、预约、付款及相关业务提交时提醒，提供“本次跳过”和“今天不再提醒”，均可继续操作。仅点击“查看绑定方法”才跳转设置。页面展示时不再自动领取首次引导；原首次引导记录只为旧客户端兼容保留。具体规则与触发矩阵见[业务操作服务号提醒](业务操作服务号提醒.md)。

1. 新用户本人关注服务号，点击欢迎消息中的“绑定账号，接收提醒”。欢迎内容保留，追加专属小程序入口。
2. 已关注用户点击服务号菜单“绑定账号”，或发送保留关键词“绑定账号”，获取本人专属入口。
3. 进入小程序，登录、完善资料或绑定手机号后回到邀请页；展示当前昵称、脱敏手机号和通知用途。
4. 点击一次“确认绑定并开启通知”完成绑定，不追加确认弹窗。持有邀请不等于已证明微信身份，请勿使用他人转发的入口。
5. 普通“服务号通知”入口只展示状态、服务号名称／微信号和上述说明，不展示绑定按钮。完成关注与绑定仅表示接收资格，实际送达仍取决于渠道配置、模板和业务权限。

邀请由服务号事件生成，绑定微信 OpenID，十分钟有效。同一微信在有效期内复用待确认邀请，凭据为不可猜测的随机值，链接不包含用户编号或手机号。登录后的状态查询只读；确认时事务锁定账号、粉丝和邀请，双方有其他绑定均拒绝覆盖。同一已完成关系重复确认成功，其他账号不能消费。新页面彻底移除二维码、口令和轮询，返回页面或手动刷新时查询，到期撤销确认资格并提示回服务号重新获取。

未知关注状态显示“待确认”。扫码和关注不会自动关联平台账号。取消关注保留微信绑定，重新关注后恢复接收资格；显式解绑需本人确认。恢复关注不补发历史跳过的通知。

后台配置展示正式小程序 AppID、固定页面和入口检查，菜单编辑器提供“绑定账号”动作，发布为微信 click 事件，不能使用公共静态链接冒充身份邀请。不依赖开放平台或 UnionID。服务号关联权限与消息内小程序链接能力由指定账号真机验收，后台人工确认不代表程序已向微信自动核验。

## 通知场景矩阵

| 事项 | 接收人 | 渠道与目标 |
|---|---|---|
| 后台权限开通 | 档案关联后台账号对应用户 | 站内＋服务号，提示前往后台 |
| 下单、确认、支付、完成、取消 | 订单本人、相关服务人员 | 站内＋服务号，分别进入客户或服务人员订单 |
| 改期、附加项变更、暂停与恢复 | 订单本人、相关服务人员 | 站内＋服务号，变更详情或服务人员订单 |
| 档期即将开始、暂停即将到期 | 订单本人、相关服务人员 | 站内＋服务号；日期或暂停到期日参与实例标识 |
| 候补释放、候补失效 | 候补本人 | 站内＋服务号，候补事项 |
| 退款状态 | 订单本人、现有规则指定的服务人员 | 站内＋服务号；不同退款记录独立 |
| 售后工单 | 工单本人、明确分配或配置的后台人员 | 站内＋服务号；后台专属事项提示到后台处理 |
| 结算状态及平台补收 | 结算所属服务人员 | 站内＋服务号，结算详情 |
| 咨询、客户流失提醒 | 当前负责客户的顾问 | 站内＋服务号，提示前往后台 |
| 新人问卷 | 问卷任务所属用户 | 站内＋服务号，问卷详情 |
| 活动报名、支付、退款 | 报名本人 | 站内＋服务号，报名详情 |
| 关注、点赞、评论、人工公告 | 原业务明确的接收人 | 仅站内 |

后台“业务事件”展示接收账号缺失、权限变化、处理失败等原因；“发送日志”展示服务号实际投递状态。事件已处理不等同于服务号已送达。瞬时投递错误沿用现有重试机制；事件处理错误最多自动重试三次，管理员可以对仍有权限的失败事件重新提交。

发送、重试和工作消息读取都校验当前身份与业务归属。取消服务关系后停止后续提醒，但取消结果可发送给原相关服务人员。已撤销的旧工作消息不因后来重新绑定而恢复展示。

## 接口与字段

| 接口 | 用途与参数 |
|---|---|
| `GET /adminapi/auth.admin/bindingDetail` | `admin_id`，返回后台账号、用户昵称、脱敏手机号与服务号状态 |
| `POST /adminapi/auth.admin/bindingSave` | `admin_id`、`user_id`、可选 `staff_id`、必填 `reason`；用户为零表示解绑 |
| `GET /adminapi/auth.admin/bindingEntry` | 当前登录人员只读查看自身关联 |
| `GET /api/wechat/oaSubscribeStatus` | 只读查询关注、绑定、候选状态、会话有效期及渠道可用状态 |
| `POST /api/wechat/oaInvitationStatus` | 请求体 invitation，只读返回 state、can_confirm、expires_time、message、binding |
| `POST /api/wechat/oaInvitationConfirm` | 请求体 invitation，本人一次确认绑定，凭据禁止写入请求日志 |
| 旧 Entry、QrCode、Confirm 接口 | 仅在新版发布前兼容；启用邀请开关后停用并提示新版流程 |
| `POST /api/wechat/oaSubscribeUnbind` | 解除本人微信绑定 |
| `POST /api/wechat/oaGuideClaim` | 原子领取首次引导，返回 `show` |
| `GET /adminapi/notification.oaNotification/eventList` | 业务事件分页列表，使用 `page_no`、`page_size` |
| `POST /adminapi/notification.oaNotification/eventRetry` | `id`，重新提交仍具业务权限的处理失败事件 |

服务号状态保留 `follow_status`、`bound`、`can_receive`，增加 `candidate_ready`、`session_expired`、`channel_available`、`official_name`、`official_account`、`official_qr_url`。通知保留原分页和分类字段，增加 `event_key`、`audience`、`business_type`、`business_id`。

数据库新增 `account_binding_audit` 和 `notification_event`。站内消息增加身份、业务目标及唯一事件标识；服务人员关联字段支持空值，并建立唯一约束。平台用户增加首次关注引导时间。

## 迁移与发布

本次邀请流程按以下顺序切换：

1. 备份并执行 `php server/database/migrations/20260915_oa_invitation.php` 只读预检，再加 `--apply` 增加会话 source 和来源索引；默认 miniapp，历史数据保留。
2. 部署兼容后端和后台，新入口开关保持关闭。此时旧版小程序仍能使用原写接口，新页面源码已删除旧流程。
3. 上传、审核并发布新版小程序，使用指定 iOS、Android 账号验证消息链接能力、冷启动、登录回跳和已登录进入。
4. 在后台确认正式 AppID 关联及真机验收后启用邀请入口，并按原菜单发布流程增加“绑定账号”，不覆盖其他菜单。启用时作废旧待绑定会话并停用旧写接口。
5. 观察正式关注回调、邀请确认和通知资格，不批量补发历史消息。未完成微信发布及真机验收时不得提前开启入口。

以下为此前账号关系迁移说明：

先停止业务写入和通知任务，备份数据库，再执行只读报告：

```powershell
php server/database/migrations/20260915_account_notifications.php
```

此命令只读取关联关系、输出安全补齐项和冲突项，不修改数据库。冲突包括重复占用、关联双方不一致以及启用档案缺少有效账号；已解绑停用档案可保留。

确认冲突已处理后，在维护窗口执行：

```powershell
php server/database/migrations/20260915_account_notifications.php --apply
cd server
php think sync_admin_permissions
```

迁移仅补齐已有明确档案关系，不按手机号匹配。新增权限只登记，不自动授予岗位；由管理员分配“管理账号绑定”权限。部署匹配版本的后台和小程序后，恢复 `send_oa_notifications`，该任务同时处理业务事件和服务号投递。历史消息不迁移接收人，不批量补发历史服务号通知。

迁移后发生回滚时应先停止任务，并保留新增数据用于排查；旧版本无法理解新的绑定及事件模型，不应仅回退前端代码。维护窗口需使用部署前备份与配套版本进行一致恢复。
