# 新人调查问卷全链路产品流程与验收标准

更新时间：2026-05-23  
角色定位：产品经理  
范围：服务人员发送给用户的“新人问卷/调查问卷”，覆盖后台服务人员与管理员配置、订单触发、发送提醒、小程序接收填写、答案回看、状态流转与异常处理。

> 工作区提示：2026-05-23 当前仓库存在问卷代码/架构文档并行改动，本 PRD 以已读取代码为依据标注“当前工作区事实”和“待确认项”；最终验收以合并后的实现与 QA 测试为准。

## 1. 业务目标与成功指标

### 1.1 业务目标

1. 服务人员在婚礼服务前系统化收集新人基础资料、关系故事、仪式偏好、避讳内容等信息，减少线下反复沟通。
2. 用户在小程序内收到明确待办并完成一次有效填写，服务人员与管理员可在后台按订单、客户、服务人员回看答案。
3. 问卷模板支持草稿、发布、版本化与题目快照，保证已发任务和已提交答案可解释、可追溯。
4. 即使站内通知/订阅消息不可达，用户仍可从订单详情、支付结果页或问卷列表进入待填任务。

### 1.2 成功指标

- 订单进入待服务后，有可用问卷模板的主服务人员订单，问卷任务创建成功率 ≥ 99%。
- 已推送待填任务用户可见率 100%，入口包括站内通知、订单详情、支付结果页、问卷列表。
- 问卷提交成功后，重复提交不产生第二份答案，答案唯一约束命中率 100%。
- 管理员/服务人员可在任务详情中看到订单、用户、服务人员、版本号、题目快照、答案和提交时间。
- 失败态具备可恢复路径：详情获取失败可重试或返回订单/列表，提交失败提示具体必填项或不可提交原因。

## 2. 角色与核心场景

| --- | --- | --- |

| 用户/新人 | 在订单待服务后收到待办，填写一次并可查看历史答案 | 小程序站内通知、订单详情、支付结果页、新人问卷列表 |

## 4. 推荐端到端流程

### 4.1 模板配置与发布

1. 服务人员或管理员进入问卷配置页。
2. 选择基础题库题目或手动新增题目，设置题型、选项、必填、排序、问卷标题和隐私提示。
3. 保存草稿：只影响草稿，不影响已发布版本。
4. 发布新版：生成不可变 `version_id/version_no` 与完整题目快照；新任务默认使用当前发布版本。
5. 停用模板：停用后不再为新订单创建任务；已有待填任务按任务状态继续处理，由管理员手动取消或保留。

### 4.2 订单触发与任务创建

1. 订单支付成功并进入待服务状态后，系统识别主服务人员。
2. 若主服务人员存在启用且已发布问卷版本，则创建一条任务，绑定 `order_id/order_item_id/user_id/staff_id/questionnaire_id/version_id/version_no/questions_snapshot`。
3. 同一订单只能存在一条有效新人问卷任务，防止重复待办。
4. 若无主服务人员、无启用模板、无发布版本，系统不阻塞订单主流程，但应记录日志并在后台运营巡检中可见。

### 4.3 发送、补发与用户接收

1. 自动推送模式：任务创建后立即发送站内通知；手动模式：任务创建后为待推送，服务人员/管理员点击“发送问卷”。
2. 发送成功或补发均更新 `send_count/last_send_time`；首次发送写入 `send_time`。
3. 用户可从以下入口进入：
   - 站内通知：跳转问卷详情。
   - 订单详情：展示待填写问卷卡片。
   - 支付结果页：支付完成后展示待填写问卷行动项。
   - 新人问卷列表：展示本人任务并按全部/待填写/已填写筛选。
4. 补发不创建新任务，只对原任务增加提醒；已填写/已取消任务不得补发。
5. 发送失败、用户未订阅或消息不可达，不应影响任务本身；产品目标是任务仍可从订单详情/问卷列表进入。当前代码仅用户列表过滤已推送任务，需研发修复或明确“不推送则不可见”的业务规则。

### 4.4 用户填写与提交

1. 用户打开详情时校验登录态、任务归属与状态。
2. 待填写任务展示题目、必填标识、隐私提示和提交按钮。
3. 用户提交时，前端应先定位未填必填项；后端再次校验必填、题型、长度和选项合法性。
4. 提交成功后任务变为已填写，保存答案与题目快照，详情页切换为只读历史答案。
5. 重复点击或网络重试：只允许一份答案，后续请求可幂等成功但不得覆盖历史答案，页面展示已提交只读态。

### 4.5 状态流转、超时与撤回

| 状态 | 含义 | 允许动作 | 下一状态 |
| --- | --- | --- | --- |
| 待推送 + 待填写 | 已创建但用户未收到提醒 | 发送、取消/撤回、后台查看 | 待填写已推送、已取消 |
| 已推送 + 待填写 | 用户可填写 | 补发、提交、取消/撤回、后台查看 | 已填写、已取消 |
| 已填写 | 用户已提交 | 查看答案、导出/复制、后台查看 | 稳定态 |
| 已取消 | 管理员/服务人员撤回或订单终止 | 查看取消原因 | 稳定态 |

产品要求：

- 超时：产品建议短期可用“未填时长 + 运营补发/取消”处理；若采用当前工作区新增的 `已过期` 状态，必须补齐 `expire_time/viewed_time` 数据库字段、定时/访问触发逻辑、用户文案和后台筛选。
- 撤回：应补充管理员/服务人员取消任务入口，记录取消人、取消时间、取消原因；取消后用户详情不可提交并显示原因。
- 订单取消/退款/服务人员变更：应评估是否自动取消旧任务或转移/重建任务；当前代码未体现自动处理。

## 5. 数据与文案要求

### 5.1 问卷模板与题目

- 模板字段：标题、描述、隐私提示、服务人员、状态、推送模式、草稿题目、当前发布版本。
- 题目字段：题目 ID、题型、标题、占位提示、选项、是否必填、分类、排序。
- 版本字段：`version_id/version_no/title/description/questions/create_time`，发布后不可修改。
- 题型范围：文本、长文本、单选、多选、评分。

### 5.2 任务、答案与关联

- 任务必须绑定：`task_id/task_sn/order_id/order_item_id/user_id/staff_id/questionnaire_id/version_id/version_no/questions_snapshot/status/send_status/send_count/send_time/last_send_time`；若启用查看/过期状态，还需 `viewed_time/expire_time`。
- 答案必须保存：`task_id/order_id/user_id/staff_id/questionnaire_id/version_id/version_no/questions_snapshot/answers/create_time`。
- 订单关联用于履约视角，`user_id` 用于客户身份绑定；后台客户视图需能按 `user_id` 或手机号关联问卷历史。
- 一个订单默认一条新人问卷任务；补发复用原任务，不静默生成多个待填任务。

### 5.3 隐私提示与通知文案

- 问卷页顶部需展示隐私提示：`你填写的信息仅用于本订单婚礼策划与服务沟通，服务人员和平台管理员可查看。请勿填写身份证号、银行卡号等非必要敏感信息。`
- 站内通知标题：`请填写新人问卷`。
- 站内通知内容建议：`订单{order_sn}的婚礼仪式资料问卷已准备好，请补充新人信息，方便{staff_name}完善仪式策划。`
- 补发确认文案：`本次只会提醒客户填写当前问卷任务，不会创建新任务。`
- 已提交文案：`问卷已提交，可查看历史答案。如需修改请联系服务人员。`
- 已取消文案：`该问卷已撤回/取消，如有疑问请联系服务人员。`

## 6. 用户故事与优先级

| 优先级 | 用户故事 | 验收要点 |
| --- | --- | --- |
| P0 | 作为用户，我希望订单支付后能在小程序看到待填问卷，以便及时补充婚礼资料 | 订单待服务后任务创建；入口可见；点击可打开详情。 |
| P0 | 作为用户，我希望问卷只能成功提交一次，以免误操作覆盖答案 | 重复提交不新增答案；详情变只读。 |
| P0 | 作为服务人员，我希望按自己负责的订单查看问卷答案，以便准备服务 | 服务人员中心任务列表与详情显示答案、订单、用户。 |
| P0 | 作为管理员，我希望全量查看和补发问卷，以便排查未填写任务 | 后台任务列表筛选待填/已填/已取消、发送状态、关键词。 |
| P1 | 作为管理员，我希望模板发布后有版本记录，以便历史答案可解释 | 新任务绑定版本；答案保存题目快照；历史展示不受题库删除影响。 |
| P1 | 作为用户，我希望通知失败时仍能从订单详情进入问卷 | 不依赖站内通知成功；订单详情按 `order_id` 查待填任务。 |
| P1 | 作为服务人员，我希望撤回错误发送的问卷 | 取消入口、原因记录、用户不可提交。 |
| P2 | 作为运营，我希望看到未填时长和补发次数 | 列表支持未填时长、发送次数排序或筛选。 |

## 7. 可执行验收清单

### 7.1 模板与版本

- [ ] 新建/编辑草稿时，未点击发布不影响当前发布版本。
- [ ] 发布 v1 后创建订单 A 问卷任务；再发布 v2 后，订单 A 的待填任务继续展示创建时 v1 快照，新订单 B 展示 v2。
- [ ] 删除/禁用基础题库题目后，已提交答案仍能显示原题目标题、题型、答案。
- [ ] 单选/多选题少于两个选项时，后台保存或发布失败并提示原因。
- [ ] 必填题为空时，用户提交失败并提示具体题目。

### 7.2 任务创建与发送

- [ ] 订单支付成功并进入待服务，存在主服务人员和已发布启用模板时，生成任务且 `order_id` 唯一。
- [ ] 无主服务人员/无模板/无发布版本时，订单主流程不受阻，系统记录可排查日志。
- [ ] 自动推送模式创建后 `send_status=已推送`，`send_count=1`，站内通知可跳转详情。
- [ ] 手动推送模式创建后后台可看到待推送任务，点击发送后用户可见。
- [ ] 对同一任务补发只增加 `send_count/last_send_time`，不新增任务。
- [ ] 已填写/已取消任务点击发送失败并提示“当前问卷已提交或不可发送”。

### 7.3 用户填写与入口

- [ ] 支付结果页出现待填问卷行动项，点击进入详情。
- [ ] 订单详情出现待填问卷卡片，点击进入详情。
- [ ] 新人问卷列表可按全部/待填写/已填写筛选，并能进入详情。
- [ ] 详情页展示标题、描述、隐私提示、订单号、服务人员、状态、题目和必填标识。
- [ ] 接口失败/任务不存在/鉴权失效时，页面提供重试、重新登录或返回订单/列表路径，不只停留在 toast。
- [ ] 提交成功后刷新详情，按钮消失，答案只读展示。

### 7.4 状态、重复与异常

- [ ] 同一任务并发提交两次，只产生一条 `la_couple_questionnaire_answer`，任务状态为已填写。
- [ ] 已提交任务再次提交不得新增或覆盖答案；返回口径需统一为“明确失败”或“幂等成功并展示已提交态”。
- [ ] 已取消任务不可提交，详情展示取消原因。
- [ ] 发送失败或用户拒绝订阅不影响填写主流程；若任务应主动可见，则列表/订单详情仍能查到。
- [ ] 订单取消/退款后待填问卷处理规则明确：自动取消或运营人工取消，两者之一必须落地。
- [ ] 后台分页、筛选、详情、发送操作不出现运行时错误；重点验证服务人员中心分页 `taskPager`。 

### 7.5 后台与客户视图

- [ ] 管理员任务列表展示任务编号、订单、用户、服务人员、问卷标题、状态、发送状态、发送次数、提交时间。
- [ ] 管理员任务详情展示版本号、题目快照、答案、订单信息、客户信息。
- [ ] 服务人员只能查看/发送自己名下任务；管理员可查看全量任务。
- [ ] CRM/客户视图可通过 `user_id` 或绑定手机号关联到订单和问卷历史。
- [ ] 权限菜单包含问卷列表、配置问卷、基础题库、问卷任务、发送问卷等动作权限。

## 8. 当前差距与整改建议

| 优先级 | 差距 | 影响 | 建议责任 |
| --- | --- | --- | --- |
| P0 | 小程序问卷详情失败态只有 toast，无页面级重试/返回 | 任务不存在、登录失效、接口失败时用户无明确恢复路径 | 前端：补页面错误态、重试、返回订单/列表、重新登录。 |
| P0 | 用户列表只查已推送任务，与“通知失败仍可主动进入”目标不一致 | 发送失败或待推送任务用户不可见 | 产品/后端确认：若要主动可见，应移除列表 `send_status=已推送` 限制或订单详情提供未推送可见策略。 |
| P1 | 撤回/取消接口和取消原因字段未形成完整闭环 | 错发问卷无法产品化闭环 | 后端/前端：补取消接口、权限、原因、状态文案；若只支持过期，也需说明不可手动撤回。 |
| P1 | 过期/未填时长运营视图仍需增强 | 运营难以批量跟进未填写 | 后台：按创建时间/最近发送时间/过期时间展示未填时长，并支持状态筛选导出。 |
| P1 | 通知只有站内消息，未见微信订阅消息结果记录 | 发送不可达难以判断 | 后端：记录发送渠道、失败原因；前端/小程序按需申请订阅。 |
| P1 | 问卷页未展示隐私提示 | 用户不知道资料用途和可见范围 | 前端/产品文案：详情页增加隐私提示。 |
| P2 | 订单取消/退款/主服务人员变更后的问卷处理未明确 | 可能出现无效待办或错误服务人员查看 | 产品/后端：明确自动取消、重建或人工处理 SOP。 |

## 9. 上线风险清单

1. **版本修正风险**：当前口径为创建时冻结快照，服务人员发布新版不会修正已创建任务；错题需通过取消/过期旧任务并创建新任务处理。
2. **可见性风险**：未推送任务在用户列表不可见；若站内通知发送失败，用户可能找不到问卷。
3. **错误态风险**：详情页接口失败只有 toast，弱网或登录失效时用户可能认为没有问卷。
4. **撤回缺口**：错发问卷缺少取消入口，可能造成用户填写无效信息。
5. **隐私合规风险**：问卷收集私人故事、家庭成员、避讳等信息，需明确用途、可见范围与敏感信息提示。
6. **权限风险**：服务人员中心必须严格按 `staff_id` 限制任务查看和发送，防止跨员工查看客户答案。
7. **后台运行时风险**：QA 已发现服务人员中心问卷分页 `taskPager` const + v-model 风险，可能影响服务人员查看任务；管理员任务页增强后仍需单独验证服务人员中心。
