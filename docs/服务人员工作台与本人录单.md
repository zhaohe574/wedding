# 服务人员工作台与本人录单

## 使用流程

工作台顶部“服务号通知”与通知中心复用整卡组件。常用操作提供手动录单、订单管理、档期管理和结算，之后展示待办、近期订单、数据概览及原管理入口。

手动录单路径为 `packages/pages/staff_order_create/staff_order_create`。

1. 填写客户与服务信息。完整手机号精确查询后，明确选择客户；无账号可用临时联系人，不自动创建或认领账号。
2. 选择本人套餐及附加服务，查看服务端地区价、定金与尾款。不能选择协作人员、改价或优惠。
3. 核对摘要与付款安排，按需提交凭证。提交前展示现有服务号提醒，两种跳过均继续；主动查看绑定方法时表单留在原页面，返回后再次提交。

临时联系人仅支持线下收款。关联客户可选择线上待付款或线下收款。建单后进入本人订单详情，返回工作台时刷新订单数据。

## 工作身份与接口边界

有效用户、启用的后台账号、有效服务人员档案必须具有一致的明确关联。预览、建单、客户查询和收款提交均重新验证身份；建单及收款提交期间锁定身份关系。

主人员由服务端确定。其他人员编号、客户编号、价格、优惠及支付状态不作为授权来源。客户选择使用随机凭据，绑定操作用户和档案，30 分钟有效；客户查询每后台账号每分钟最多 30 次。相关凭据按日志隐私规则脱敏。

后台与小程序共用 `ManualOrderService` 的套餐、地区价、金额拆分及建单逻辑。小程序通过 `StaffManualOrderService` 使用受限参数；后台原直接登记已付款行为不由新小程序接口开放。

## 收款申请与审核

| 场景 | 金额 | 结果 |
| --- | --- | --- |
| 未付款订单提交定金 | 订单定金快照 | 审核通过后记实收并锁档，保留尾款 |
| 未付款订单提交全款 | 全部应收 | 审核通过后进入待服务 |
| 服务完成后提交尾款 | 剩余尾款快照 | 审核通过后完成付款和订单状态 |
| 驳回 | 不入账 | 保留原因及原凭证，可重新提交 |
| 档期冲突 | 不伪造到账 | 回滚支付、账本与锁档，保留待审核及处理原因 |

收款归属默认为“人员代收”，可选择“平台收款”。人员代收不写为平台收入，结算沿用既有实收归属规则。后台订单详情展示历史申请、阶段、金额、凭证、归属和处理原因，使用原 `auditVoucher` 权限与整单范围验证；禁止审核本人提交的申请。

待审核期间，在线支付、旧凭证提交、后台直接确认收款、重复申请及修改应收受到限制。超时任务和支付抢档处理不自动取消具有待审核收款的订单。

## 数据与幂等

- 订单来源新增 `4`，表示“服务人员录入”；`creator_user_id` 记录录单账号。
- `staff_submit_key` 唯一约束与提交内容摘要防止网络重试重复建单。
- `order_receipt_request` 独立保存每次收款申请。提交标识唯一；生成列 `pending_order_id` 的唯一约束保证每单最多一条待审申请。
- 审核事务锁定订单与申请，重新核对付款阶段和余额。重复审核返回原付款记录。
- 报价变化仅返回新摘要，不创建订单，需要重新确认。
- 建单与审核事务内写入通知事件。服务号投递失败不改变业务结果，不补发历史通知。

## 通知场景

| 事件 | 接收人 | 渠道与跳转 |
| --- | --- | --- |
| 关联客户订单创建 | 明确关联的客户 | 站内消息与现有订单服务号场景，客户订单详情 |
| 收款申请提交 | 配置的审核管理员；未配置时为启用的超级管理员 | 站内消息与工作人员内部提醒，提示前往后台 |
| 收款审核结果 | 当前明确关联的本人服务人员 | 站内消息与工作人员订单提醒，本人订单详情 |
| 付款审核通过 | 已关联客户及订单服务人员 | 复用付款成功通知规则 |

审核接收人配置键为 `order.receipt_audit_admin_ids`。缺少有效接收账号时仍保留事件及跳过原因。通知资格受绑定、关注和渠道配置影响，不承诺必定送达。
