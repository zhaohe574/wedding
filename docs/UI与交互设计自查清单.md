## 一、版式与视觉降噪（界面变乱的 4 个根源）

来源：菜心视觉设计《UI 界面越做越乱？4 个根源找到了》

| # | 变乱根源 | 优化原则 | 改造要点与正反对比 |
| :- | :--- | :--- | :--- |
| **1** | **元素与背景割裂** | **有一部分与背景融合** | 避免在纯白底上堆满硬描边白底卡片；可在顶部增加柔和渐变，并将主视觉区或顶部数据卡片改为半透明/通透质感，与背景融出层次。 |
| **2** | **单体元素不统一** | **单体元素做到精致统一** | 同组导航或功能图标严禁线性/面性/大圆凸起混搭；统一线宽、圆角、尺寸语言并补齐文字标签，仅用主题色区分激活态。 |
| **3** | **布局缺乏节奏** | **打破机械重复网格** | 避免连续多行全是 `3 列 + 3 列 + 3 列` 的机械九宫格方框；改用「头图整合数据 + 进度条通栏卡片 + 纵向列表」错开版式疏密节奏。 |
| **4** | **修饰琐碎重复** | **去掉无用装饰噪点** | 砍掉散落的色块胶囊、多余的嵌套外框与装饰小点；放大核心标题拉出字号层级，只保留关键交互入口，靠留白引导视线。 |

## 二、立竿见影的 5 个 CSS / UI 质感细节

来源：费纸张《5 个小细节让 AI 设计的界面看着更舒服》

1. **等宽数字（防数字跳动）**
   倒计时、价格、统计指标等会变化或对齐的数字，使用等宽数字特性：
   ```css
   font-variant-numeric: tabular-nums;
   ```
2. **同心圆角（嵌套圆弧和谐）**
   卡片内部嵌套子元素/按钮时，遵循公式计算圆角：
   `外圆角半径 = 内圆角半径 + 内外间距（padding）`
3. **错开入场（Stagger）**
   避免整块内容一次性整体淡入；图标、标题、正文、按钮按 **`100ms` 间隔**阶梯依次入场。
4. **平衡标题换行（防孤立尾词）**
   多行标题使用平衡换行，避免最后一行孤零零掉一个词：
   ```css
   h1 {
     text-wrap: balance;
   }
   ```
5. **多层柔和阴影代替生硬边框**
   用低透明度多层 `box-shadow` 替代生硬的 `1px solid #e4e4e7` 灰边框，使卡片边缘更自然融入背景：
   ```css
   box-shadow:
     0 0 0 1px rgb(0 0 0 / .06),
     0 1px 2px -1px rgb(0 0 0 / .06),
     0 2px 4px rgb(0 0 0 / .04);
   ```

## 三、4 个视觉对齐技巧与 AI 检查提示词

来源：费纸张《Vibe 知识大赏 | 4 个视觉对齐技巧让界面更协调》——**对齐要听眼睛的，数学居中 ≠ 视觉居中。**

1. **图标视觉重心**：例如播放三角形放进圆形容器时，应按三角形的**视觉重心**对齐（通常需向尖端方向微调，而非几何外框居中）。
2. **图文按钮留白**：带前置图标的按钮（如 `+ 新建文件`），图标侧视觉份量较轻，**有图标一侧的内边距要略小于纯文字一侧**（案例参考：左 `27` / 右 `34`，视觉上才左右平衡）。
3. **圆形视觉大小（视觉溢出）**：圆形与方形并排或同组排版时，圆形尺寸需**略微超出**方形才能获得一致的视觉体量（案例参考：方块 `170` vs 圆形 `182`）。
4. **引号悬挂**：引用段落开头的 `“` 悬挂到左边界外侧，让正文首字严格垂直对齐。

### 可直接复制给 AI 的视觉对齐检查提示词

```text
检查这个界面的视觉对齐，
保留现有布局与交互。

逐项检查图标重心、按钮留白、
圆形视觉大小与引号悬挂。

给出最小修改和理由；
图标偏移优先在 SVG 内修正。
```

## 四、可用性与防误触规范

### 4.1 移动端热区与触觉反馈

来源：Ludi《为什么你总点不中那个按钮？》

大屏上 `16px` 的精致图标，落到真机上要面对 `44px` 宽的大拇指——点不中往往是热区过小而非用户手抖。

- **视觉与热区分离**：图标视觉可以是 `16px`，但可点击热区应 **`40px` 起步**（推荐 `44px–48px`），**底线不低于 `28px`**。
- **消灭「中间死区」**：相邻两个可点击热区之间不要留出空缝，避免用户点在缝隙里无响应。
- **防止手势打架**：在可滑动区域（横向滚动/轮播/列表）旁边的点击热区预留 **`20dp` 安全距离**，避免滑动手势抢走点击事件。
- **触觉安全感**：手指按下时会遮挡小图标视线，关键操作可搭配 **Taptic 震动反馈**让用户确认已经点到。

### 4.2 PC 端悬停子菜单「预测锥（Safe Triangle）」

来源：费纸张《用预测锥提示词，让 AI 优化菜单切换交互细节》

多级悬停菜单中，鼠标斜向移动去点击已展开的子菜单时，容易划过其他主菜单项导致误切换；单纯加延迟又会让正常横向/纵向切菜单显得迟钝。用**预测锥（安全三角形）**判定移动意图即可兼顾顺滑与防误触。

#### 可直接复制给 AI 的预测锥提示词

```text
给我们的悬停子菜单加上预测锥。

子菜单打开时，用鼠标刚才的位置和子菜单近侧边缘的两个角，画出一个三角形。如果鼠标当前位置在三角形内，说明它正朝子菜单移动：保持子菜单打开，不触发沿途其他菜单项的悬停切换。如果鼠标移出三角形，立即切换。如果它停在三角形内，等 300 毫秒再切换。

保持键盘和触控操作不变。
```

## 五、微交互与动效术语词典（AI 精准点菜表）

给 AI 提动效需求时，避免使用「加点高级动画」等模糊表述，直接指定**具体交互名称 + 物理行为/缓动参数**。

### 5.1 12 个基础 App 微交互（CoverAI）

| # | 交互名称 | 核心交互描述 / 提示词要点 |
| :- | :--- | :--- |
| 1 | **按压回弹** | 按下时缩小到 `96%`；松手时用弹簧动画先放大略超过原尺寸，再回到 `100%`。 |
| 2 | **弹性开关** | 开关切换时，圆点先被拉成胶囊状，再缩回圆形。 |
| 3 | **波纹跟手** | 点击波纹从**手指落点下方**散开，而非从按钮正中心散开。 |
| 4 | **点赞炸一下** | 点赞操作时出现小烟花粒子反馈，克制使用，避免过度。 |
| 5 | **勾选画出来** | 勾选操作时一笔描出对勾，而非瞬间闪现。 |
| 6 | **液态滑块** | 滑块拖动时，轨道颜色、圆钮、数值同步移动反馈。 |
| 7 | **数字滚动** | 数字变化滚动时逐渐减速停止，避免生硬急刹车。 |
| 8 | **骨架屏** | 骨架屏高度与真实内容严格一致，数据填充时页面不发生跳动。 |
| 9 | **卡片翻面** | 3D 翻面时，确保背面文字不透底且不镜像反转。 |
| 10 | **汉堡变叉** | 汉堡菜单变形为 `×` 时，保持线条粗细与视觉连贯。 |
| 11 | **卡片堆叠** | 最上面卡片划走后，顺滑露出下面卡片边缘形成层次。 |
| 12 | **底部抽屉** | 上拉时先在半屏位置停靠吸附，再由用户决定拉满或关闭。 |

| # | 动效名称 | 物理类比 | 效果要点 |

| 1 | **磁吸** | 磁铁吸铁片 | 处理距离——图标靠近目标格（如 `30px` 吸附范围）时被吸附。 |
| 2 | **液态形变** | 扯软糖 | 卡片拖动时产生拉伸形变，松手后弹性回原形。 |

### 5.3 16 种常见 UI 动效中英术语表（小刷AI全栈）

| # | 英文术语 | 中文名 | 效果与适用场景 |
| :- | :--- | :--- | :--- |
| 01 | `Spotlight` | 鼠标聚光灯 | 鼠标移动时卡片产生局部高光明暗变化（产品/功能卡片） |
| 02 | `Scroll Reveal` | 滚动显现 | 内容随页面滚动逐渐显现（长页面） |
| 03 | `Border Beam` | 边缘流光 | 光沿卡片边框循环流动（推荐套餐、会员卡、重点功能） |
| 04 | `Magnetic Button` | 磁吸按钮 | 鼠标靠近时按钮像被磁铁吸引轻微偏移（首页核心按钮） |
| 05 | `Scrollytelling` | 滚动叙事 | 滚动时区域固定、内容同步切换（品牌官网产品介绍） |
| 06 | `3D Tilt` | 3D 倾斜 | 鼠标移动时卡片轻微 3D 旋转（产品展示、会员卡、作品集） |
| 07 | `Text Scramble` | 文字解码 | 文字先变成随机字符再逐个还原（信息解码/科技感文案） |
| 08 | `Shimmer` | 流光扫过 | 柔和高光快速扫过元素表面（骨架屏加载、重点按钮） |
| 09 | `Parallax Scrolling` | 视差滚动 | 前景与背景以不同速度移动（大幅背景图、多层画面） |
| 10 | `Count Up` | 数字递增 | 数字快速滚动递增到目标数值（数据看板、指标、倒计时） |
| 11 | `Hover Lift` | 悬停上浮 | 鼠标悬停时卡片轻微上浮（重点功能引导） |
| 12 | `Typewriter` | 打字机效果 | 文字逐字出现（AI 对话界面、动态文案） |
| 13 | `Stagger Animation` | 交错动画 | 元素按顺序依次错峰进入画面（卡片列表） |
| 14 | `Marquee` | 跑马灯 | 内容水平无缝滚动（合作品牌 LOGO、用户评价墙） |
| 15 | `Spring Animation` | 弹簧动画 | 运动到终点略超过再轻轻回弹（点赞反馈、按钮点击、弹窗） |
| 16 | `Easing` | 缓动函数 | 控制运动加减速曲线，日常交互优先使用 `Ease Out` 缓动 |

**动效落地 3 条底线原则**：
1. **克制不拖沓**：交互响应时间短促干脆，不阻碍核心操作。
2. **优先高性能属性**：尽量只动画化 `transform` 与 `opacity`，避免频繁触发布局重排（reflow）。
3. **尊重系统设置**：响应 `prefers-reduced-motion` 减弱动效偏好。

## 六、深色模式 4 步规范与 AI 提示词

来源：费纸张《四步做好不刺眼的深色模式》——**深色模式不是简单地把浅色主题反转过来。**

| # | 核心步骤 | 常见误区 | 推荐做法与色值参考 |
| :- | :--- | :--- | :--- |
| **1** | **别用纯黑** | 纯黑 `#000000` 配白字容易显得发光、模糊、刺眼 | 基础背景改用近黑深灰，例如 `#121418` |
| **2** | **柔化白色** | 直接用 `#FFFFFF` 纯白字对比度过高 | 主文字用柔和灰白 `#E6E8EC`（在 `#121418` 上约 `15:1`）；次要文字用更暗灰色，对比度至少 `4.5:1`（WCAG AA） |
| **3** | **明暗表现层级** | 深色背景上阴影不明显，卡片与底色易糊在一起 | 遵循「层级越高，表面越亮」：`背景 #121418` → `卡片 #1B1E24` → `浮层 #252931`，并叠加淡淡的 `1px` 边框 |
| **4** | **柔化色彩** | 沿用浅色高饱和品牌色（如 `#2F5BEA` 在深底仅 `3.3:1`，未达 AA） | 换成更浅、更柔和的色调（如 `#8FB0FF`，达 `8.6:1`），确保满足 WCAG AA `4.5:1` 要求 |

### 可直接复制给 AI 的深色主题提示词

```text
重新设计这个应用的深色主题，不要只是反转浅色主题

1. 别用纯黑：背景使用近黑的深灰，例如 #121418，而不是 #000000

2. 柔化白色：主文字使用柔和的灰白，例如 #E6E8EC（在 #121418 上约为 15:1）；次要文字用更暗的灰色，对比度至少 4.5:1

3. 用明暗表现层级：表面层级越高，颜色越亮（#121418 -> #1B1E24 -> #252931）；添加淡淡的 1px 边框，不要只依赖阴影

4. 柔化色彩：将高饱和的品牌色和强调色换成更浅、更柔和的色调，确保在对应深色表面上达到 WCAG AA 的 4.5:1 对比度要求

把深色色值统一放进主题变量，保持浅色主题不变
```

## 七、页面开发 / 走查速查清单

- [ ] **结构降噪**：是否存在连续多排相同 `N 列` 方框？能否通过渐变融合、通栏卡片或纵向列表拉开节奏？
- [ ] **装饰克制**：是否去掉了无意义的胶囊背景、嵌套边框和小装饰点，靠字号层级与留白区分主次？
- [ ] **样式细节**：数字是否开启 `tabular-nums`？嵌套圆角是否满足 `外 = 内 + padding`？标题是否加了 `text-wrap: balance`？边框能否换成柔和多层阴影？
- [ ] **视觉对齐**：三角形/不对称图标是否对齐视觉重心？图文按钮两侧留白是否视觉平衡？圆形与方形并排时是否做了视觉溢出补偿？
- [ ] **热区与防误触**：移动端小图标点击热区是否 `≥ 40px`（底线 `28px`）？相邻热区是否无死区？可滑区旁是否留足 `20dp`？PC 悬停子菜单是否考虑预测锥？
- [ ] **动效性能**：卡片/列表入场是否做了 `100ms` 错开？骨架屏高度是否与真实内容一致？动画是否仅使用高性能属性并兼容 `prefers-reduced-motion`？
- [ ] **深色模式**：是否避免纯黑 `#000000` 与刺眼纯白？表面层级是否遵循「越靠前越亮」并配淡淡 `1px` 边框？次要文字与强调色在深底上是否达到 `≥ 4.5:1`（WCAG AA）？
