# 部署配置与验收

## 运行环境与安装

使用 PHP 8.0 及以上、MySQL 8、Node.js 20 和 Composer 2。PHP 需要 `pdo_mysql`、`mbstring`、`bcmath`、`curl`、`openssl`、`fileinfo`、`dom`、`zip`、`gd`、`imagick`；默认 Redis 缓存还需 Redis 服务及 PHP Redis 扩展。ImageMagick 需要 SVG 渲染能力，中文字体及其许可证保留在 `server/app/common/resource/fonts`。

1. 在 `server` 执行 `composer install --prefer-dist --no-interaction`，在 `admin`、`uniapp`、`pc` 分别执行 `npm ci`。依赖版本以锁文件为准。
2. 各前端从 `.env.example` 建立本机 `.env`，配置后端域名。后台和 PC 同域部署可留空，小程序必须配置已备案的 HTTPS 请求域名；示例 `api.example.com` 只是占位值。旧 `.env.development`、`.env.production` 会覆盖同名变量；当前工作区的物理清理受阻，重装时必须排除这些旧配置，详见[变更记录](变更记录.md)。
3. Web 根目录设置为 `server/public`，配置 ThinkPHP 路由重写及可写的 `server/runtime`、`server/public/uploads`。访问 `/install/install.php`，选择空数据库并设置管理员账号。安装器使用 `db/like.sql`，支持自定义前缀，拒绝覆盖非空数据库。
4. 安装器从 `server/.example.env` 生成 `server/.env` 和 `server/config/install.lock`，保存随机密码盐。安装后按环境调整缓存；本机无 Redis 时可设 `CACHE.DRIVER=file`。生产设 `APP_DEBUG=false`、`DATABASE.DEBUG=false`。不要单独导入 SQL 后跳过安装器的管理员初始化。
5. 执行后台和 PC 的 `npm run build`，分别发布至 `server/public/gelinshe0318` 和 `server/public/pc`。小程序执行 `npm run build:mp-weixin:check`，用微信开发者工具导入 `uniapp/dist/build/mp-weixin`。后台入口为 `/gelinshe0318/`，PC 为 `/pc/`。

## 微信与通知配置

微信账号、支付证书、模板、存储及短信配置通过后台保存到数据库，不从 `.env` 读取。

- 微信小程序：后台配置 AppID、AppSecret，填写 `uniapp/src/manifest.json` 的 `mp-weixin.appid`；两处必须一致。微信平台配置请求、上传、下载合法域名。

  当前项目正式 AppID 为 `wx1e62d0d40f3c3a38`。构建会拒绝空值、游客 AppID 及非法格式；格式检查不能替代与后端配置逐项核对。微信开发者工具导入 `uniapp/dist/dev/mp-weixin` 或 `uniapp/dist/build/mp-weixin` 后，在项目详情确认 AppID 一致，并使用有该小程序开发权限的微信账号。原项目若以游客模式打开，关闭后重新导入，不要继续使用旧登录码。游客请求的来源包含 `servicewechat.com/touristappid`，其登录码不能用于正式小程序的 `code2Session`（用临时登录码换取微信登录身份）接口。
- 服务号：配置 AppID、AppSecret、Token 和 EncodingAESKey，将后台显示的回调地址配置到微信平台；安全模式使用 AES 密钥验签解密。服务号关联业务小程序，后台开通服务号通知。
- 通知模板：为现有场景填写服务号获批的模板 ID 和字段映射后启用。默认模板均关闭且无真实 ID；缺失配置、未关注或未绑定会记录原因，不影响业务付款和查看。
- 身份关联：后台账号与小程序账号验证关联后，再由小程序生成绑定码，服务号提交并回小程序确认。关注和绑定独立保存，取消关注只停止推送。
- 支付：后台配置微信商户号、API v3 密钥和商户证书，商户关联同一个业务小程序；按业务需要开启线下全款与尾款。商家转账还需微信平台开通对应产品和场景。
- 调度：操作系统每分钟执行 `php /项目绝对路径/server/think crontab`。安装基线包含支付查单关单、退款查询、服务号队列、活动释放、提醒和结算任务；后台任务页应无错误状态。

业务通知场景映射如下，模板跳转必须指向现有小程序页面。

| 业务 | 场景 |
| --- | --- |
| 客户预约、收款、履约、退款、暂停 | `order_update` |
| 改期、售后、问卷 | `change_result`、`ticket_update`、`questionnaire_update` |
| 候补、活动、结算 | `waitlist_release`、`waitlist_expired`、`activity_update`、`settlement_update` |
| 服务人员订单、档期、暂停、退款、售后、改期 | `staff_order`、`staff_schedule`、`staff_pause`、`staff_refund`、`staff_aftersale`、`staff_change` |
| 顾问跟进、售后分配等后台专属事项 | `staff_internal`，小程序查看通知摘要，原后台处理 |

## 自动检查

2026-09-14 升级部署前需阅读[线上部署记录](线上部署记录-20260914.md)。旧库先运行 `php database/migrations/20260914_release_upgrade.php` 只读预检，在备份和维护窗口内加 `--apply` 补齐结构，再执行 `php think sync_admin_permissions`。新增权限由超级管理员按岗位分配，不自动扩大角色授权。迁移兼容现有 MySQL 5.7，新部署仍推荐 MySQL 8。Redis 故障时档期锁操作拒绝执行，不再退化为普通文件缓存锁。

在独立本机 MySQL 实例运行测试，禁止指向业务数据库或远端数据库。测试要求端口不是 `3306`，使用 `root` 创建随机测试库并在结束后删除。

```powershell
$env:WEDDING_TEST_MYSQL_PORT = '13367'
npm run qa:all
```

以上命令在项目根目录运行。测试库有密码时通过 `WEDDING_TEST_MYSQL_PASSWORD` 提供；PHP 不在 PATH 时通过 `QA_PHP_BINARY` 指定。总检查包含三组契约、后台与小程序类型检查、三个前端构建、小程序包体、PHP 语法以及安装、支付、并发通知和海报回归。CI 同样先安装依赖并使用配置示例。

发布迁移回归还要求检出目录不含真实的 `server/.env`，防止部署脚本加载业务连接。迁移检查覆盖只读预检、增量结构、旧会话保留、重复执行及失败退出码。

## 实机验收

必须使用有效微信账号联调真实付款、退款、商家转账和服务号推送，模拟测试不替代实机验收。

- 验证首次绑定、取关、重关注、跨账号冲突、会话过期、重复回调、队列重试和各角色访问权限。
- 验证定金、锁档、履约后尾款、线下审核驳回、部分退款、原路退款和转账待确认至到账；对照微信交易单与平台流水。
- 对比海报编辑预览与服务端导出，检查中文字体、二维码扫码、脱敏信息、小程序保存图片及历史重建。
- 后台图片工具检查 JPEG、PNG、WebP 导出、尺寸和裁剪旋转；抠图与视频压缩检查第三方外链。

最终交付要求仅保留源码、必要素材、配置示例、依赖锁文件、检查脚本、核心文档和许可证。当前依赖、构建包、上传数据、运行日志及真实配置仍有未完成的物理清理，具体结果见[变更记录](变更记录.md)。

## 验收范围

- Admin 页面壳一致性：核心 CRM 页面使用统一筛选、表格和权限壳。
- PC 展示优化：只保留品牌、案例、资讯和联系展示，不进入预约或支付。
- 移动端组件治理：小程序只构建微信小程序目标，主包执行包体检查。
- CRM P1 验收：客户、跟进、顾问、流失预警四条链路闭环。
- 状态机与 API 契约：共享支付阶段、应收实收、服务号绑定和问卷状态定义。
