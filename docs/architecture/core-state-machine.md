# 核心状态机

## 订单、付款与尾款

主流程为待确认（0）→待支付（1）→首笔到账并锁档后的待服务（2）→服务中（3）。服务完成时，尾款未收则回到待支付（1），同时保存 `complete_time`；尾款结清后才进入已完成（4）并生成结算。尾款待收不能套用首笔未付款的超时取消规则。

| 对象 | 状态值 | 约束 |
| --- | --- | --- |
| 付款流水 | 0 待支付、1 已支付、2 已退款、3 支付失败 | 微信回调与主动查单共用验签后结果处理；重复结果不得重复入账、锁档或通知 |
| 线下凭证 | 0 待审核、1 已通过、2 已拒绝 | 提交凭证不代表到账；拒绝后可重交，审核必须校验权限与剩余应收 |
| 退款主单 | 0 待审核、1 审核通过、2 退款中、3 已退款、4 已拒绝、5 退款失败 | 按原付款流水拆分，累计金额不得超过可退金额；失败重试前核对渠道结果 |
| 退款子项 | 0 待执行、1 处理中、2 已完成、3 失败 | 微信原路退；线下必须登记实际退款凭证，各子项结果汇总到主单 |
| 结算转账 | 0 待发起、1 转账中、2 待用户确认、3 已到账、4 转账失败、5 已关闭 | 已发起和待确认都不能记为到账，到账结果幂等入账 |

定金走微信；启用线下收款时全款与尾款走线下，否则走微信。已创建付款流水和审核中的凭证保留原渠道。锁档失败或订单取消后迟到的微信实收必须记账并进入补偿退款，不恢复已取消订单；退款占用与结算占用互斥。

## 服务号绑定与接收资格

`follow_status` 表示未知、已关注或已取消关注，`bound` 表示账号是否已关联，`can_receive` 同时要求关注和有效绑定。取关后 `bound` 保持不变，`can_receive` 变为假；重新关注后重新核验接收资格。

绑定码和二维码复用限时会话，服务号提交后仍需原小程序账号确认。会话原子消费，拒绝过期、重复消费和跨账号抢绑。通知队列发送前重新校验接收人权限与模板配置，失败原因留痕，不阻断订单和付款。

## 新人问卷任务

| 状态值 | 状态 | 允许流转 |
| --- | --- | --- |
| 0 | 待提交 | 1 已提交，2 已取消，3 已查看，4 已过期 |
| 3 | 已查看 | 1 已提交，2 已取消，4 已过期 |
| 1 | 已提交 | 终态 |
| 2 | 已取消 | 终态 |
| 4 | 已过期 | 终态 |

已提交任务重复提交可幂等返回成功但不得覆盖历史答案。已取消或已过期任务不可填写，接口需要返回明确失败原因。

问卷模板兼容策略：任务创建时冻结问卷版本和题目快照，提交时使用任务上的题目快照清洗答案并再次保存到答案记录；发布新版本不得改写已创建任务的版本快照。

过期与撤回能力：当前系统以 `STATUS_EXPIRED` 表示已过期，以 `STATUS_CANCELLED` 表示撤回或取消问卷任务；如果后续增加独立撤回接口，必须同步更新模型、OpenAPI、状态机和验收脚本。
