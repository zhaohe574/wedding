# 项目问题修复记录

## 本轮范围

以 2026 年 9 月 14 日代码审查发现的问题为修复范围：权限默认放行、客户查询隔离、投诉禁用、财务统计、任务失败传递、锁服务降级、资讯容错、类型检查和回归检查覆盖、共享类型约束。保留工作区已有修改。

新增产品功能（异常处理台、订单时间线、CRM 待办等）作为后续功能建设，不与缺陷修复混为已完成事项。

## 修复步骤

1. 收紧后台权限，并提供专用的线下建单客户查询。
2. 补齐投诉处理动作、财务统计口径和定时任务错误处理。
3. 修复锁服务故障处理、资讯详情错误态和页面检查覆盖。
4. 完善共享类型及统一检查入口，运行隔离环境回归。
5. 记录验证结果、部署事项和仍需真实微信环境验收的边界。

## 状态

已完成本轮可复现缺陷的代码修复。新增产品功能、核心巨型文件的架构拆分及历史依赖目录清理仍属于后续工程，不宣称已完成。

## 修复结果

- 后台未登记接口默认拒绝，基础公共接口采用明确清单；辅助查询按所属权限映射，新旧前缀保持兼容。安装基线与升级脚本补登记 90 个操作权限，不自动授予现有角色。
- 线下建单改为完整手机号精确查询，只返回客户选择所需字段；服务人员提交订单时校验当前账号近期查询记录，防止绕过查询直接猜测用户编号。
- 投诉禁用在事务内停用服务人员及关联后台账号，失败回滚；登录中间件即时检查停用状态，已缓存登录凭据也会失效。存量订单由管理员继续处理。
- 财务均值按同一期内的平台实收除以去重收款订单数计算，人员代收不进入分子或分母。
- 调度器读取真实退出码，任务统一返回零成功、非零失败；数据库命名锁防止重叠执行，修复最后执行时间被模型格式化后的比较问题。退款查询失败和通知任务异常能留下错误记录。
- Redis 原子锁不可用时拒绝获取，不再使用普通缓存伪装互斥锁；通知单轮派发有批次上限。
- 资讯详情、列表和协议页补充错误恢复；修复小程序漏检页面的类型错误和无效链接处理。
- 三端类型检查通过，PC 检查工具版本进入锁文件；小程序检查覆盖全部已注册页面所在目录，后台移除页面排除项。PC 格式警告清零。
- 共享支付阶段和线下收款参数收紧类型；根级检查和持续集成加入素材隔离及项目审查数据库回归。
- 增加后台与 PC 的 `build:check`，验证构建不再执行复制覆盖站点目录的发布脚本。

## 上线步骤

先备份业务数据库，再在维护窗口部署后端并运行：

```sh
php think sync_admin_permissions
```

在 `server` 目录执行。旧版数据库须先按[线上部署记录](线上部署记录-20260914.md)补齐增量结构。命令支持当前数据库表前缀，重复执行不会重复登记权限；由超级管理员在角色管理中为对应岗位分配新增操作。没有分配的操作会被拒绝，这是权限收紧后的预期行为。

随后发布后台与小程序，确保两端同时切换到专用客户查询接口。生产环境配置可用的 Redis；故障时档期锁操作会明确失败。真实微信支付、退款、转账和服务号推送仍需实机验收。

## 保留事项

本机 PHP 的 Imagick 编译版本与加载的 ImageMagick 版本不同；字体与海报回归通过，但生产环境仍应统一版本。Node.js 24 运行旧版 Nuxt 有弃用提示，项目部署继续使用文档约定的 Node.js 20。历史依赖包含升级提示，未进行跨主版本升级，也未删除用户已有的 vendor 修改。
