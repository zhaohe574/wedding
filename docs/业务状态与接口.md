# 业务状态与接口

支付主链路为“报价→订单→付款→首笔到账锁档→履约→尾款→退款或结算”。微信回调和主动查单共用校验、幂等和补偿入口；迟到付款保留实收并进入补偿退款。

服务号状态分开返回 `follow_status`、`bound` 和 `can_receive`。取消关注只停止通知，不解除账号绑定。绑定码由小程序创建，服务号提交后回小程序确认，绑定会话限时、限次并原子消费。

小程序接口位于 `/api`，后台接口位于 `/adminapi`，均通过 `token` 请求头鉴权；微信回调独立验签。核心定义见 [OpenAPI](contracts/openapi-core.yaml)，共享类型见 `shared/contracts/core.ts`；其余字段以当前控制器和验证器为准。

| 阶段 | 关键接口与行为 |
| --- | --- |
| 选人报价与订单 | `/order/preview`、`/order/create`、`/order/detail`；提交金额由服务端复核 |
| 付款与结果恢复 | `/pay/payWay`、`/pay/prepay`、`/pay/payStatus`；支付来源为 `order` 或 `staff_settlement_repay` |
| 线下收款 | `/order/uploadVoucher`；后台 `/ops.order/auditVoucher`、`/ops.order/confirmOfflinePay`，凭证提交不代表到账 |
| 履约与尾款 | 后台开始服务、完成服务；尾款未收保留应收，结清后完成并进入结算 |
| 退款 | `/order/applyRefund`、`/order/refundDetail`；后台按原流水执行退款，微信原路退、线下登记实际付款凭证 |
| 账号关联 | 后台 `/auth.admin/bindingEntry` → 小程序 `/wechat/claimAdminBinding` → 后台 `/auth.admin/bindingConfirm` |
| 服务号绑定 | `/wechat/oaSubscribeEntry`、`oaSubscribeQrCode`、`oaSubscribeConfirm`；状态查询 `oaSubscribeStatus`，显式解绑 `oaSubscribeUnbind` |

`pay_amount` 是应收，`paid_amount` 是实收；`balance_amount` 和 `balance_paid` 表示尾款。通用支付接口 `pay_way=2` 表示微信；订单流水模型的微信值为 `1`、线下值为 `4`，不得跨模型直接比较。`payment_channel` 为 `1` 线上、`2` 线下。

`current_pay_stage=balance_after_service` 表示等待履约完成后收尾款。订单进入尾款待收时不会按首笔未付款订单自动取消；付款流水未关闭或凭证审核中时，修改线下收款开关不切换该笔付款渠道。

首笔实收后锁档。微信回调及主动查单共用结果处理；并发抢档失败或取消后迟到付款保持实收流水，登记异常并进入补偿退款，订单不恢复。退款申请按原流水拆分并占用可退额度，结算与退款互斥；结算区分已发起、待用户确认和到账。
