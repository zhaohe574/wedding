# 业务操作前的服务号提醒

## 交互规则

关键操作在表单和业务资格校验后、请求提交前检查服务号绑定。未绑定显示“开启服务号提醒”；已绑定但取消关注显示“重新关注，恢复微信提醒”；关注状态未知时提示确认状态，不误报取消关注。已关注且绑定不提醒，渠道暂不可用不要求重复绑定。

底部“本次跳过”“今天不再提醒”均继续当前操作。正文中的“查看绑定方法”由用户主动点击，打开服务号通知页并暂停本次提交，返回后保留填写内容，需再次点击提交。关闭或点遮罩视为本次跳过；支持页面返回拦截的平台先关闭弹窗，页面实际离开时取消原提交，绝不在隐藏页面继续下单或付款。

## 触发矩阵

| 场景 | 检查位置 |
|---|---|
| 独立登录、补手机号完成登录 | 账号信息加载完成后、普通回跳前 |
| 登录用于继续业务 | 不重复提醒，恢复后的提交点统一检查 |
| 预约下单 | 确认页校验通过后、创建订单前 |
| 候补 | 选择有效人员和套餐后、加入候补前 |
| 活动报名 | 报名信息校验后、创建报名记录前 |
| 订单及活动支付 | 统一支付组件校验后、创建预支付单前；弹窗结束后复核超时 |
| 改期、加项、暂停 | 申请表校验后、业务请求前 |
| 退款、售后、客户问卷 | 业务提交前 |

当前小程序没有客户恢复履约的提交入口，恢复由后台处理，本次不新增客户恢复权限。浏览、互动、普通资料编辑和工作人员日常编辑不接入。旧的首次安全落点自动弹窗已从页面容器移除，旧后端领取接口仅兼容已有客户端。

## 状态与故障处理

- 共用页面弹窗和业务提醒服务，调用结果为继续或暂停；不在通用请求层拦截业务。
- 同时只允许一个提醒，已有提交锁保护重复点击。页面离开、账号切换和旧响应到达均不提交旧业务。
- 状态读取及静默保存请求设置两秒超时、无自动重试，不因提醒错误跳转登录或弹网络错误。查询失败直接继续操作，不伪造已绑定状态。
- 当天跳过截止于北京时间次日零点，按平台账号跨设备保存。客户端按用户编号缓存，保存失败时本机当天仍生效，其他设备以服务端结果为准。
- 待确认服务号邀请优先继续原流程，不插入提醒；拉起支付后不再弹窗。

## 接口与迁移

`GET /api/wechat/oaSubscribeStatus` 增加 `reminder_snoozed_today` 和 `reminder_skip_until`，保留原字段。

`POST /api/wechat/oaReminderSkipToday` 无需请求体，只操作当前登录用户。截止时间由服务端确定，重复保存幂等，不接受客户端用户编号或日期。

新增 `user.oa_reminder_skip_until`，默认零。安装 SQL 和增量迁移一致，先执行只读预检，再执行带 `--apply` 的命令：

```text
php server/database/migrations/20260915_oa_reminder.php
php server/database/migrations/20260915_oa_reminder.php --apply
```

第一条仅检查，第二条新增缺失字段；重复执行不重置已有偏好，不修改绑定、邀请开关或通知投递。

## 验收

隔离数据库验证账号隔离、重复保存、北京时间零点截止、过期恢复、只读迁移与重复迁移。小程序验证两种跳过、查询超时、迟到响应、离页和换号、保存失败、登录合并及主动查看设置暂停提交；保留此前邀请和返回路径测试。实际微信支付、原生返回键与弹窗层级需要 iOS、Android 真机验收，模拟测试不代表真机结果。

后端兼容发布完成后，需上传并发布 `uniapp/dist/build/mp-weixin` 新构建，小程序弹窗不会随 SSH 部署更新。
