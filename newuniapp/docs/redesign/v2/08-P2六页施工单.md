4. **5 种题型统一到 `form-field`** —— ⛔ **2026-11 裁决：整条撤回，本页不迁**

   > **原条目是从两条错误事实推出来的，照它做会同时踩中三种假保证，所以不是"排期问题"，是"方向问题"。**

   **原条目的两处事实错误（A2 类：把批次共性当页面事实）**
   - 原文「`form-field` 已支持 `input` / `textarea` / `radio` / `rating` 四种」→ **`radio` 没有渲染分支**。`form-field.vue` 的 `type` 联合里有 `'radio'`，但 `v-if` 链只覆盖 `input|textarea` / `picker` / `rating` / `upload`，传 `type="radio"` 会渲染成一片空白（编译通过、运行时无控件）。
   - 原文「`textarea`→`type="textarea"`」→ **`form-field.vue:112-115` 自己的注释写着**：`type="textarea"` 是**空壳**，会渲染成单行 input（`base-input` 没有 textarea 类型）。照做等于把多行题降级成单行 —— 语义降级，用户看不见但事实已经错。

   **为什么不迁（不是排期问题）**
   - `form-field` 根节点 `.ff` 是 `display:flex; align-items:center; border-bottom:1rpx solid var(--c-control-border)` —— 它是**行级单值字段**，给「姓名 [___]」用的。
   - 本页是**一张卡里 10 道动态题**，题号走 `--font-serif` + `--c-brand-text`（唯一的层级线索），题间靠 `& + &` 分割线。
   - 硬迁要付三笔账：① 题号得拼进 `label` 字符串 → 丢掉衬线和金色；② 每题一条 `border-bottom` → 和自己的分割线打架，双层横线；③ 接口 `text|textarea|single|multiple|rating` 要映射成组件 `input|textarea|radio|checkbox|rating`，映射层本身就是新的漂移源。
   - **结论：本页维持自绘题块（`.q__input` / `.q__textarea` / `.opt` / `.q__rating`），控件一格不动。**

   **连带处置：`form-field` 的假承诺要收，不是补分支**
   - `radio` / `checkbox` 有类型无分支 → 全仓 grep 确认**无人传**（`type="radio"` / `type="checkbox"` / `:options=` 零命中；`message.vue:80` 的 `:options` 属于 `tn-swipe-action-item`，无关）。
   - 处置：从 `type` 联合里删掉 `'radio' | 'checkbox'`，注释改成「未实现，请走插槽」。以后谁想用，**TS 当场报错**，而不是运行时静默空白。这是去掉假承诺，不是加能力，不属于组件扩展。
   - 验证：`grep -c "'radio' | 'checkbox'" src/components/form-field/form-field.vue` → **0**

5. **提交按钮补三态**（`02 §6.1` 口径）—— ✅ 已落地
   - **现状（改造前）**：单一「提交」，无「还差 N 题」态、无提交中锁定
   - **已实现**：必填未完成 → `ghost`「还差 N 题」（可点，点了 `uni.pageScrollTo` 滚到第一道未完成题，顶部留 60px 上下文避免被导航栏压住）；完成 → `ink`「提交问卷」；提交中 → 「提交中…」并 `:loading` 锁定

6. **【新增 2026-11】进度条在「全选填」问卷下会显示 `已完成 0 / 0`**
   - **问题**：`requiredTotal = questions.filter(q => q.required === 1).length`。若后台配置的问卷**没有必填题**，分母为 0 → 顶部恒显示「已完成 0 / 0」。这不是边界幻想，问卷配置是后台可改的。

     - 反面做法（不要选）：改成 `questions.length` 当分母 —— 那会让「已完成」和「还差 N 题」用两个不同的分母，用户会算出两套结论。
