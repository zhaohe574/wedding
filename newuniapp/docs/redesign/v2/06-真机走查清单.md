## 为什么这些必须在真机做

本批次所有改动，我这边能验证到的极限是**编译产物层**：

```
app-toast.wxss          → 1093 字节，.toast{position:fixed...} + @keyframes 在包内
app.wxss                → 242035 字节，.tn-overlay / 字体 base64 / --tn-color 均在包内
search.wxss             → .tabs__item:before{top:-16rpx;bottom:-16rpx} 在包内
```

**「规则进了包」不等于「看起来对」**：定位、层级、动画、键盘顶起、字号在真机上的实际观感，只有设备能判断。以下每条都是产物层无法闭环的。

## 已知风险（真机上可能撞到，先记在这里）

### R1 · `icon.wxss` 的纯 CDN `@font-face` 会覆盖 base64

- `app.wxss` 里有 base64 的 `@font-face`（`font-family: tuniaoFont`）；
- `node_modules/.../icon/src/icon.wxss` 里**还有一份同名的纯 CDN 声明**（36.6KB，指 alicdn）；
- **后加载的会覆盖先加载的** —— 也就是说即使 base64 进了包，运行时仍可能走 CDN。
- **后果**：A3（飞行模式验图标）可能不通过，**不是因为 base64 没进包，而是被覆盖了**。
- **修法**：清理 `icon.wxss` 那份重复声明。这是构建配置变更，不在本批范围，等走查结论一起定。

### R2 · 主包体积 1005.6 KB / 1.4 MB

其中 `app.wxss` 242035 字节（236 KB，约 15%），**182743 字节是图标字体 base64**。这是让图标离线可用的代价。R1 修掉后能省 36.6KB。
