# 10 · 移动端页面装修与开屏广告

> 目标：后台「移动端装修」与小程序渲染**共用同一份数据模型**，
> 后台能配的组件 === 小程序能画的组件；并新增开屏广告页，由后台配置驱动。

---

## 1. 三端数据流

```
后台装修编辑器 (admin/src/views/decoration/pages/index.vue)
    │  读 DECORATE_PAGES 决定有哪几页、每页哪些组件
    │  保存 POST /adminapi/experience.decorate.page/save
    ▼
la_decorate_page (id, type, name, data: JSON 字符串, meta)
    │
    ├─ GET /api/index/decorate?id=6   → SplashAdDecorateService::normalizePage()   → 开屏
    ├─ GET /api/v2/home              → IndexLogic::normalizeHomePageData()        → 首页
    └─ GET /api/index/index          → 同上（v2 未上线时的降级路径）
    ▼
小程序 (newuniapp)
    parseDecoratePage() → widgets[] → 按 name 渲染
```

**唯一事实源**：`shared/contracts/decorate.ts`
- 页面结构（`DECORATE_PAGES`）
- 组件白名单（每页 `widgets[]`）
- 开屏 / 弹窗字段与归一化、展示判定

服务端 PHP 不能 import TS，因此 `SplashAdDecorateService.php` 是**镜像**，
由 `npm run decorate:check` 在本地/CI 比对字段集合（见 §7）。

## 2. 页面结构与组件白名单

| 页面 id | 名称 | 组件（顺序即默认渲染顺序） | 支持 page-meta |
| --- | --- | --- | --- |
| 1 | 首页装修 | `banner` `home-brand` `home-service-categories` `home-flow` `home-popup-ad` | 是 |
| 2 | 个人中心 | `user-info` `wedding-countdown` `quick-entry` | 否（标题 / 背景固定） |
| 3 | 客服设置 | `customer-service` | 否 |
| 6 | 开屏广告页 | `splash-ad` | 否 |

**改动前后对比**

| | 改动前 | 改动后 |
| --- | --- | --- |
| 页面清单 | 硬编码 `pagesTypeEnum` + 3 份 `*_WIDGET_NAMES` | 读 `DECORATE_PAGES` |
| 组件面板 | 手写 20+ 个组件，多数小程序不认 | 由契约 `flatMap` 生成，只含真实支持的组件 |
| 加载后裁剪 | 无（历史组件原样存回） | 按该页白名单过滤 |
| 保存前补齐 | 按数字字面量 `if (activeMenu === '1')` | 按 `page.key` 分派 |
| 预览页类型 | 硬编码 `{'1':'home',...}` | 由 `DECORATE_PAGES` 生成 |

> 现在后台新增一个组件，必须先在 `DECORATE_PAGES` 里登记；小程序没实现的组件不会出现在面板里。

## 3. 开屏广告字段（`splash-ad`）

| 字段 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `enabled` | 0\|1 | 0 | 总开关，关闭时小程序直接进首页 |
| `image` | string | '' | 主素材，全屏竖版，建议 750×1624；为空即使开启也不展示 |
| `logo_image` | string | '' | 品牌标识，透明 PNG，叠在主图上方居中 |
| `auto_enter_enabled` | 0\|1 | 1 | 到点是否自动进首页 |
| `auto_seconds` | 1–10 | 3 | 展示时长（秒） |
| `skip_mode` | `countdown`\|`always`\|`never` | `countdown` | 主按钮可点击时机（字段名沿用历史命名；按钮始终显示） |
| `skip_delay` | 0–10 | 0 | `countdown` 模式下第几秒变为可点击；服务端夹到 ≤ `auto_seconds` |
| `button_text` | string | 点击进入 | 主按钮文案（≤12 字） |
| `frequency` | `every_time`\|`session`\|`daily`\|`once`\|`interval_days` | `session` | 展示频次 |
| `max_daily_count` | 0–99 | 0 | 每日上限（0 = 不限），与频次叠加生效 |
| `interval_days` | 1–365 | 7 | `interval_days` 模式的间隔天数 |
| `start_time` / `end_time` | `YYYY-MM-DD HH:mm:ss` | '' | 生效时间窗，空 = 立即/长期 |

**兼容**：历史值 `first_visit` → `once`、`every_home_entry` → `every_time`，
旧配置不会被归一化成默认值。

## 4. 展示判定（三端同一套纯函数）

`shouldShowSplash(content, state, now)` 按顺序判：

1. `enabled !== 1` 或 `image` 为空 → 不展示；
2. 未到 `start_time` / 已过 `end_time` → 不展示；
3. 频次主规则：
   - `session` 本次进程已展示 → 否
   - `daily` 今天已展示 → 否
   - `once` 累计 ≥1 → 否
   - `interval_days` 距上次不足 N 天 → 否
   - `every_time` 恒通过
4. `max_daily_count > 0` 且今日已达上限 → 否。

**状态存储**

| 字段 | 位置 | 说明 |
| --- | --- | --- |
| `lastShownAt` / `totalCount` / `lastShownDate` / `todayCount` | `uni.setStorageSync('splash_state')` | 跨启动保留 |
| `sessionShown` | 模块变量 | 进程内有效，杀进程即重置 |

**曝光口径**：广告真正渲染出来记一次（不是点击才记）。

## 5. 小程序实现

### 5.1 为什么开屏层挂在首页，而不是独立 `pages[0]`

初版把开屏做成独立页并排在 `pages[0]`。实测第二次冷启动（命中缓存、不展示广告）会走
「非 Tab 开屏页 → `switchTab` 首页」，在自定义 tabBar 下首页 JS 要等约 **10 秒**才开始执行：
`switchTab` 发出后 9.85 秒才出现首页 `setup`，而首页代码执行到数据返回只用了 113ms。

因此改为：**首页保持 `pages[0]`，开屏作为首页最上层的 fixed 组件**（`components/splash-screen`）。

- 首页代码、首屏数据与开屏判定同时开始，没有第二次页面装载；
- 开屏是 fixed 全屏层，不会出现「首页先露出、广告再盖上」的视觉闪烁；
- 不展示时只销毁一个组件，不做任何页面跳转；
- 有缓存同步判定；首次安装最多等 800ms；分享 / 扫码进入首页按场景值跳过开屏（原约定不变）。

`pages/splash/splash` 仅保留为兼容入口，正常冷启动不再经过它。

### 5.2 文件

| 文件 | 职责 |
| --- | --- |
| `src/components/splash-screen/splash-screen.vue` | 开屏层：素材、倒计时、主按钮（出现时机）、关闭进首页 |
| `src/pages/splash/splash.vue` | 兼容页壳，仅用于旧链接 / 调试直达 |
| `src/utils/splash.ts` | 配置缓存、频次状态、判定、曝光记账、冷启动入口认领 |
| `src/pages/index/index.vue` | 冷启动挂载开屏层，首页数据并行加载 |
| `src/pages.json` | 首页为第一页；开屏兼容页注册但不在启动链路 |

### 5.3 交互细节

- **没有右上角「跳过」**：跳过与「立即进入」是同一个动作，统一收口到底部主按钮；
- **主按钮一直显示**，只有「可点击 / 不可点击」两种状态；可点击时机沿用原跳过逻辑：
  `countdown` = 第 `skip_delay` 秒后可点、`always` = 立即可点、
  `never` = 一直不可点（只等自动进入）；`never` + 关闭自动进入时兜底立即可点，避免无出口；
- 不可点击时按钮置灰并显示「N 秒后可进入」；`never` 模式显示「N 秒后自动进入」；
  可点击时显示 `button_text`，自动进入开启时右侧再显示剩余秒数；
- 主图与主按钮点击都只做「关闭开屏、进入首页」，不再支持跳转目标；
  主图点击层在主按钮可点击后才生效，避免绕过「第几秒可点击」的限制；
- 计时器在「不自动进入」时也运行：`skip_mode=countdown` 的「第几秒可点击」依赖它，
  只是到 0 不自动关闭；
- 主图 `@error` → 退回品牌底（墨黑渐变 + 印章 + 品牌名），不出现裂图；
  品牌底仍保留主按钮，避免「不自动进入 + 不可点击」时没有出口；
- 素材地址：`GET /index/decorate` 会把 `image` / `logo_image` 补成绝对地址再下发
  （开屏在 `/index/config` 之前渲染，前端此时拿不到 `domain`）；后台详情仍存相对路径；
- 主按钮实心米白胶囊 + 墨字，与全站 CTA 同一套对比度逻辑。

## 6. 首页弹窗广告（`home-popup-ad`）

改动前后：后台早就能配、服务端也归一化了，但**小程序从没实现过** —— 配了等于没配。

现在补齐：

| 文件 | 职责 |
| --- | --- |
| `src/components/home-popup-ad/home-popup-ad.vue` | 弹窗本体（图片/文字/图文、关闭、CTA） |
| `src/utils/promo.ts` | 独立 storage key 的频次状态（不与开屏共用，否则互相吃掉次数） |
| `src/pages/index/index.vue` | `findWidget(page, 'home-popup-ad')` → 挂载，并把 `homeShowKey` 传下去 |

判定走 `shouldShowHomePopup()`，与开屏共用状态结构与 `dateKey/parseDateTime` 工具。

**三个容易踩的点（已处理）**

1. **「每次进入首页」不能只靠 onMounted**
   tab 页切换不会重新挂载组件，只判定一次的话该频次实际只生效一次。
   `index.vue` 在 `onShow` 里自增 `homeShowKey` 传给组件，组件 `watch` 它重新判定。

2. **曝光口径**（对应后台 `close_counts_as_shown`）
   - `= 1`（默认）：弹窗**展示即计一次**；
   - `= 0`：关闭不计，只有点主按钮才计。
   实现上 `reveal()` 按开关决定是否计数，`onCta()` 兜底计数，`counted` 保证同一次展示只记一遍。

3. **不能和隐私弹窗叠加**
   首次启动隐私授权弹窗会先弹；`evaluate()` 检测到 `privacyVisible` 为真时直接返回，
   等它关闭后由 `watch(privacyVisible)` 补一次判定。

**类型渲染**：`type='image'` 不渲染文字、`'text'` 不渲染图、`'image_text'` 两者都渲染。

## 7. 验证

### 7.1 自动化

```bash
cd newuniapp
npm run type-check        # 类型
npm run decorate:check    # 三端契约比对（字段集合 / 首页组件 / 开屏页 ID）
npm run pages:check       # 路由（应显示 56 页）
npm run header:check      # 头部一致性
npm run build:mp-weixin && npm run validate:dist
```

`decorate:check` 校验三项：
1. `SplashAdContent` 字段集合 === PHP `normalizeContent()` 返回键集合（当前 14 个）；
2. 首页组件白名单 === `IndexLogic::HOME_WIDGET_ORDER` === `DecoratePageLogic::HOME_WIDGET_ORDER`（5 个）；
3. 开屏页 `PAGE_ID` 一致（6）。

### 7.2 后台走查

1. 进入「页面装修」→ 左侧应只有 4 页，每页标注组件数；
2. 开屏广告页右侧属性面板：素材 / 展示与主按钮 / 展示频次 三块齐全；
3. 底部蓝条实时显示「预计效果：展示 3 秒后自动进入 · 按钮常显、立即可点击 · 每会话一次」；
4. 画布底部始终显示主按钮，按可点击时机切换置灰/可点状态，状态徽标显示「启用中 / 未启用 / 缺主图」。

### 7.3 真机走查

| 场景 | 预期 |
| --- | --- |
| 未启用 | 冷启动直接进首页，不出现开屏 |
| 已启用 + 有素材 | 首屏展示广告，倒计时到点自动进首页 |
| `skip_mode=countdown, skip_delay=2` | 按钮一直显示，前 2 秒置灰显示「2s 后可进入」，第 2 秒变为可点击 |
| `skip_mode=never` | 按钮一直显示但不可点击，显示「N 秒后自动进入」；关闭自动进入时兜底立即可点 |
| 点主图 / 主按钮 | 关闭开屏，露出首页 |
| 断网冷启动 | 用上次缓存的配置；无缓存则直接进首页，不卡住 |
| 主图 404 | 退回品牌底，不裂图，主按钮仍可点 |
| `frequency=daily` | 当天第二次冷启动不再展示 |
| `max_daily_count=1` + `every_time` | 当天第 2 次起不再展示 |

## 8. 已知边界

| 项 | 说明 |
| --- | --- |
| 页面 id 固定 | 1/2/3/6 与 `la_decorate_page` 历史数据绑定，不能改；改 id 要同步迁移 SQL |
| `pages[0]` 变更 | 开屏成为入口页；若后续要「免开屏直接进首页」，需在后台关闭开关（会走一次 `reLaunch`） |

| `uniapp/` 旧包 | 未改动，开屏与弹窗仅在新包实现 |

### 9.4 缓存与版本同步

- **小程序端无装修缓存**：`/v2/home`、`/index/decorate` 每次都实时请求，后台保存后**下一次进页面即生效**。
- **开屏有本地缓存**（`splash_config`）：为的是首帧同步判定。后台改完素材，
  需要**下一次冷启动**才换图（本页会静默刷新缓存）。这是设计取舍，不是 bug。
- **无 schema 版本号**：`page.data` 是裸数组，字段语义变更后旧配置只能靠服务端 `normalize*` 吸收。
  当前靠「服务端归一 + 前端默认值」兜住；若后续要做破坏性改字段，需在 `data` 外层加版本号并写迁移。

## 10. 后台预览：自绘同构版（2026-11-11）

> 不加载 H5、不复用小程序构建产物，在后台内部重新实现一套**结构同构**的预览。
> 目标是「改什么能看到什么、版式骨架与真机一致」，不是像素级仿真。

### 10.1 核心功能（必须覆盖）

| 页面 | 组件 | 预览里必须体现的配置项 |
| --- | --- | --- |
| 首页 (1) | `banner` | 只有一张主图 + 图片上的文字：宣传语与颜色、主标题（按 `\n` 分行，最多 4 行）、服务范围、主/次按钮文案；5 个分项显示开关；文字颜色（标题色 / 服务范围色，留空用设计稿默认）。**高度 / 背景 / 链接不可配；字号 / 对齐 / 位置由设计稿固定** |
| 首页 (1) | `home-brand` | 「显示本区块」+ `stats[]` 固定 3 格的数值 / 说明 → 数据条；三格全空或关闭时整块不渲染 |
| 首页 (1) | `home-service-categories` | 「显示本区块」+ `data[].title` / `image` / `link` / `is_show` → 四宫格；不限制条数，但建议 4 个；关闭时不回落内置四条 |
| 首页 (1) | `home-flow` | 区块开关、区块标题、步骤 `tag/title/desc/is_show` 与顺序 → 底部时间轴；无步骤时真机整块不渲染 |
| 首页 (1) | `home-popup-ad` | 启用开关、图片、标题、正文、按钮文案、背景色 → 卡片 + 点开盖屏 |
| 开屏 (6) | `splash-ad` | 主图、Logo、展示时长、主按钮可点击时机、按钮文案 → 全屏 + 倒计时 + 常显主按钮（可点击/不可点击） |

页面结构、组件清单、顺序全部来自 `shared/contracts/decorate` 的 `DECORATE_PAGES`，后台不再维护第二份。

### 10.2 可接受的差异（明确不追平）

| # | 差异 | 原因 |
| --- | --- | --- |
| 1 | 字体用后台所在系统的字体栈，不做 webfont | 微信 WebView 与浏览器字形渲染本就不同，追求一致收益极低 |
| 2 | 图片用 `object-fit: cover`，与小程序 `aspectFill` 的裁剪基准略有差异 | 容器尺寸换算后取整不同，肉眼几乎不可辨 |
| 3 | 弹窗默认以**卡片**展示，点「预览弹窗效果」才盖屏 | 真机弹窗会盖住整屏，预览里一直盖住就没法编辑其他组件 |
| 4 | 本期推荐 / 近期吉日画成中性骨架 | 这些来自接口，不属于装修配置；且两者无数据时真机整块不渲染（含标题），画真实内容反而误导「能配」 |
| 5 | 不模拟微信胶囊、状态栏时间信号、吸底栏 | 与装修配置无关的宿主 UI |
| 6 | 所有点击不跳转；开屏倒计时到 0 只停表 | 预览不产生业务行为 |
| 7 | 客服设置只显示「未接入」占位 | 客服页尚未接装修；个人中心已提供完整版式预览 |

### 10.3 必须保持一致（不可漂移）

| # | 约束 | 落点 |
| --- | --- | --- |
| 1 | **尺寸口径**：`1rpx = 0.5px`（375 宽），所有排版数字直接抄小程序源码 | `preview-tokens.scss` 的 `rpx()` → `calc(N * var(--pv-rpx))` |
| 2 | **颜色 / 字号 / 圆角**：与 `tokens.css` 同值 | 同上，改一边必须改另一边 |
| 3 | **数据结构**：预览直接读编辑态的 `pageData` 对象，不复制、不转换 | `preview.vue` 透传，`home-preview` 按 `widget.name` 取 `content` |
| 4 | **组件识别方式**：按 `name` 取组件，与小程序 `findWidget(page, name)` 一致 | `indexOf(name)` / `contentOf(name)` |
| 5 | **字段语义**：`enabled=0` 时数据条 / 四宫格 / 服务承诺 / 弹窗隐藏；首屏是「回落内置主图与默认文案」而非隐藏；`is_show=0`、`stats` 全空同样不展示 | 与真机同规则，不做「预览可见、真机不可见」 |
| 6 | **编辑与保存**：props / emits 不变，选中、上下移、删除、显隐、添加组件行为不变 | `pages/preview.vue` 对外接口与改造前完全一致 |

### 10.6 已知局限

- 预览只覆盖**装修驱动**的内容，接口内容（推荐位、吉日）不请求真实数据；
