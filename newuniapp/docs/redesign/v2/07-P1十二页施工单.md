## 2. 成对条目（改一处不生效）

> 这类改动的共同点：**只做一半不报错、也不生效**，代码里"看起来做了"。
> 每条四行：现状 / 目标① / 目标② / 验证（两处都要核）。
> 判断方法：问一句"这个改动是不是还有别的地方要同步"——10 秒，比漏一次返工便宜。

### P1 下拉刷新

```
现状：pages.json 无 enablePullDownRefresh；页面无 onPullDownRefresh
      （12 页实测全部为 0，其中 7 页应加、5 页必须不加）
目标①：pages.json 对应页面加 "enablePullDownRefresh": true
目标②：页面加 onPullDownRefresh，完成后调 uni.stopPullDownRefresh()
依据：02 §7
验证：两个文件都要 grep 到 —— 只验一个等于没验
      只配 pages.json = 下拉有动画但什么都不发生
      只写生命周期 = 完全没反应（没配就是没开）
范围：加 —— review/list、ticket-list、complaint-list、change/list（列表页）
             ticket-detail、complaint-detail、change/detail（详情页，类比 02 §7 的「10 订单详情 ✅」）
      不加 —— 5 个表单页，见 F1
```

### P2 吸底改 `bottom-bar`

```
现状（通式）：手写 padding-bottom: calc(164rpx|160rpx + var(--safe-bottom))
              —— 两种值并存，是两批写的；本页具体是哪个值见 §3 页内事实
              吸底容器有两种写法：class="action-bar" 与 class="submit"
目标①：删除该手写占位
目标②：page-shell 加 :bottom-bar="true"
依据：bottom-bar 自带 --bottom-bar-h，page-shell 负责预留高度；两处都改才不多不少
验证：该页 grep 无 calc(160|164rpx + safe)；且 page-shell 有 :bottom-bar="true"
风险（不对称）：
      只做①→ 底栏遮住最后一行，用户点不到，**会报**
      只做②→ 底部多一截约 160rpx 空白，用户只觉得"有点空"，**不会报**
附带：本批改完，160/164 两个历史值自然归一，不需另开任务
范围：9 页 —— 见 §3 各页事实
```

### P3 `form-field` 接入

```
现状：form-field 全站 0 引用（零验证）
      已有 labelWidth（默认 140rpx，可用 --ff-label-w 覆盖）
      无 layout / stack —— 标签与控件强制同一行 flex
      本批 5 个表单页最长的标签是「证明材料（选填，最多 10 张）」14 字，
      --fs-md 下约 390rpx；加宽到 390 后 textarea / upload 的控件区只剩约 300rpx
目标①：给 form-field 加 layout="stack"（标签在上、控件满宽）

      短标签 + input/picker → 默认 row
      长标签（≥8 字）、textarea、upload、rating → stack
依据：01 §7.6 表单行规格
验证：组件有 stack **且**页面按类型用了它 —— 两处都核
风险：只做②时 layout="stack" 会被 Vue 当普通 attribute 渲染到 DOM 上，
      **不报错、不警告、不生效**，代码里"看起来做了"
范围：review/publish、complaint-create、apply-date、apply-pause、apply-addon
```
