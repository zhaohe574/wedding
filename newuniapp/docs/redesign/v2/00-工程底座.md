### 3.1 挂载点为什么是 vite 插件

| 方案 | 结论 |
| --- | --- |
| `main.ts` 里 `import './styles/x.scss'` | ❌ uni-app 不把它编进 `app.wxss`，页面变量全悬空 |
| `App.vue <style>` | ❌ 同上 |
| `src/styles/index.scss` | ❌ 只对 H5 生效 |
| **`vite.config.ts` 的 `inject-global-wxss`** | ✅ 唯一可靠；已改为 **dev + build 双模式** |

`app.wxss` 拼装顺序（`writeBundle`，幂等，靠 `--c-bg:` 判定）：

```
tokens.css  →  tn-theme.scss  →  globals.scss  →  tn-icon base64 字体  →  原 app.wxss
```

> 关键修复：原来 `apply: 'build'`，意味着 `uni -p mp-weixin`（dev）下 `app.wxss` 只有 7.9 KB、
> 一个 `--c-*` 都没有 —— 三位工程师本地开发会看到完全无样式的页面。已实测 dev 产物 199 KB 令牌齐全。
> 另：原代码 `import('sass').compile` 在 sass 1.54（CJS）下是 undefined，一直静默回退到陈旧

## 5. 尺寸换算口径（390px 设计稿 → rpx）

系数 **1.923**（750 / 390）。**新写样式一律 rpx，不落 px**（唯一例外：需要与原生胶囊/`boundingClientRect`
对齐的 `px` 值，如 nav-bar 的状态栏高度、sticky 的 `top`）。

### 5.1 常用值换算表

| 用途 | 设计稿 px | rpx | 落地写法 |
| --- | --- | --- | --- |
| 页面左右边距 | 22 | 42 | `padding: 0 var(--sp-4)`（32rpx，与 7 档间距对齐，**不要写 42rpx**） |
| 卡片圆角 | 16 | 31 | `var(--r-md)` = 32rpx |
| 面板/弹层圆角 | 20–23 | 38–44 | `var(--r-lg)` = 40rpx |
| 主按钮高 | 44–48 | 85–92 | `base-button size="md"` = 88rpx / `lg` = 104rpx |
| tabbar 胶囊高 | 58 | 112 | `--tabbar-h` = 132rpx（含 20rpx 顶留白） |
| tab 图标 | 19 | 37 | `--fs-xl` = 38rpx（tabbar 已用） |
| 大标题 | 22 | 42 | `--fs-2xl` = 48rpx / `--fs-xl` = 38rpx |
| 区块标题 | 16 | 31 | `--fs-lg` = 32rpx |
| 正文 | 14.5 | 28 | `--fs-md` = 28rpx |
| 次级正文 | 13 | 25 | `--fs-xs` = 24rpx |
| 说明文字 | 11.5 | 22 | `--fs-xs` = 24rpx |
| 小标/角标 | 10.5 | 20 | `--fs-xs` = 24rpx |
| 极小说明 | 9.5 | 18 | `--fs-xs` = 24rpx |

**字号有下限，不是硬换算**：设计稿 < 13px 的字号（20/18rpx）低于全站可读底线
（`--fs-xs` = `max(24rpx, 12px)`），**一律取 `--fs-xs`**。
换算表给的是几何意图，不是授权你写 18rpx 的字 —— `redesign-zero-check` 的 R6 规则会拦。

### 5.2 间距七档（不要自创）

`--sp-1 8` / `--sp-2 16` / `--sp-3 24` / `--sp-4 32` / `--sp-5 48` / `--sp-6 64` / `--sp-7 96`（rpx）。
组内间距 `16`、组间 `32`、区块 `96`。设计稿的 22px 边距落到 `--sp-4`(32rpx)，视觉差 10rpx，可接受。

## 6. tabBar 四段与路由

### 6.1 结构

```

pages/feed/feed     动态    │ 主包，tabBar.list 四项
pages/query/query   查档期  │

pages/message/message 消息    ← 不再是 tab，从「我的」进入（navigateTo）
```

`link.ts` 的 `TAB_PAGES` 与 `IMPLEMENTED` 已同步；这四页必须用 `uni.switchTab`，
`navigateTo` 打开 tab 页会**静默失败**。

已修的连带改动：

| 文件 | 改动 |
| --- | --- |
| `utils/link.ts` | `TAB_PAGES` 换四项；`LEGACY_PATH_MAP` 指向新路径；`IMPLEMENTED` 增删 |
| `pages/index/index.vue`、`pkg-catalog/staff-list`、`staff-detail`、`pkg-order/waitlist` | 跳查档期路径改 `/pages/query/query`（**仅路径字面量，未动逻辑**） |
| `pages/order/order.vue`、`pages/message/message.vue` | 移除 `<app-tabbar>` |
| `pages/user/user.vue` | 我的订单 `switchTab` → `navigateTo` |
| `pkg-catalog/booking`、`pkg-order/payment-result` | 去订单列表 `switchTab` → `navigateTo` / `reLaunch` |

> ⚠️ 上面 5 个页面文件属于前端四组，架构只改了一行路径字面量（路由迁移的必要连带），
> 未触碰任何逻辑/样式/template 结构。若后续重写覆盖属正常。

### 6.2 tab 页状态的「最小可行方案」

两个事实能省掉一堆状态管理代码：

1. **tab 页实例常驻**：`switchTab` 不销毁页面，`ref` 与滚动位置天然保留 → **不需要 store、不需要持久化**；
2. **`switchTab` 不接受 query**：想「带着条件进 tab」只能靠共享状态。

于是只有两条：

- 页面内筛选/滚动：**用页面自己的 `ref`**，`onShow` 里判断要不要刷新（`onLoad` 只跑一次）；
- 跨页带条件进 tab：`src/stores/tabQuery.ts` 的 `setQuery(tab, params)` / `consumeQuery(tab)`（取完即清）。

> 反例：把列表数据、分页游标塞进 pinia —— 那是第二个后端，且 tab 页之间互相污染。

### 6.3 D3：自绘 tabbar 的白屏怎么压

| 手段 | 做法 |
| --- | --- |
| 骨架先行 | 4 个 tab 页首屏都先渲染 `base-skeleton`，接口回来再换内容（**不是** loading 转圈） |
| tabbar 不抖 | `app-tabbar` 用 `position: fixed; bottom: 0` + `padding-bottom: calc(8rpx + var(--safe-bottom))`；**页面容器负责留白**（`--tabbar-h`），滚动时 bar 不参与布局，不产生重排 |
| 切换不重建 | `switchTab` + 实例常驻，第二次进入是热启动 |
| 预下载 | `preloadRule`：首页/动态→pkg-catalog，查档期→pkg-catalog（all），我的→pkg-order+pkg-user |

实测结论：自定义 tabbar 本身不引入额外白屏（它挂在页面内，随页面渲染）；真正可感延迟来自
**首屏数据**，靠骨架屏而不是从原生 tabbar 换回来解决。

### 6.4 吸顶统一能力（05 主持人详情三页签）

**统一做法（不要各写一遍）**：`src/components/sticky-holder/sticky-holder.vue`

为什么要封装：`position: sticky` 在 `scroll-view` 内不生效；页面级 sticky 在部分 WebView 会被原生导航栏盖住。

```
页面 onPageScroll(e) → :scroll-top="e.scrollTop"
组件 onMounted 量一次自身距页面顶部的距离 → 越过阈值吸顶 → 渲染等高空位（内容不跳）
```

| props | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `scrollTop` | number | 必填 | 来自页面 `onPageScroll`（px），组件不自己监听 |
| `top` | number | `0` | 吸顶停留位置（px），一般传导航总高 |
| `zIndex` | number | `60` | 需低于 nav-bar(99) 与 tabbar(100) |

暴露 `remeasure()`：内容高度变化（页签换行）后调用。

## 7. 图标方案（D6 定稿）

**全站只用一个图标族：tn-icon（图鸟 iconfont，base64 内联）。自绘 SVG 只给不可着色图形。**

| 方案 | 体积 | 首屏 | 风险 | 结论 |
| --- | --- | --- | --- | --- |
| tn-icon **base64** | 110 KB 字体 / **182 KB base64 wxss** | 即时 | 无网络依赖 | ✅ **采用** |
| tn-icon **远程** | 36 KB wxss | 首帧可能空白 | 需 https + 域名白名单；部分 Android 不加载；协议相对 URL 在小程序 wxss 非法 | ❌ |
| 自绘 SVG | 3 KB | 即时 | 与字体图标两套图形语言 | ❌ 仅保留印章这类不可着色图形 |

**为什么值 182 KB**：图鸟有 **26 个组件内部写死 `TnIcon`**（popup 关闭、calendar 箭头、checkbox 勾、
switch、search-box、notice-bar…）。缺字体 = 空白方块，不报错、验收脚本查不出、用户一眼看见。
另外**图标丢失比 180 KB 更贵** —— 这是 D6 的裁决口径。

**tabbar 的落地变化（D6 之后）**：原先 8 个 base64 SVG 已删除，改为 `<tn-icon>`：
`home` / `moments` / `calendar` / `my`，选中态**不换图标只换色**（`--c-ink-3` → `--c-brand-soft`）
+ 外层墨黑胶囊。代价：主包多出 `node-modules/@tuniao/.../icon` 编译产物 **43.2 KB**。

**回收开关**：若最终确认 0 使用图鸟组件，删 `vite.config.ts` 里 `readTnIconCss()` 一行即回收 182 KB（图标族方案随之作废）。

**布局规范（冻结）**

| 项 | 规范值 | 说明 |
| --- | --- | --- |
| 状态栏占位 | `height: {statusBarHeight}px` | 用 px 不用 rpx。`statusBarHeight` 本身已是物理 px，转 rpx 会在非 375px 屏引入舍入误差 |
| 标题条高度 | **`44px`（固定 px）** | `88rpx` 在 375px 宽 = 44px，但在 414px 宽 = 48.6px，会「导航条变高」。**禁止用 rpx 写条高** |
| 左右区水平内边距 | `var(--sp-3)` | 由 `.nav__bar` 的 padding 统一承担 |
| 左区宽度 | **不设固定宽度，由内容撑开**；有返回键时 `88rpx`，只有 `#left` slot 时由 slot 自身宽度撑开，都没有则宽度 0 | 见 §5.3（02 文档）：不能用 `$slots` 判断，只能靠 CSS |
| 右区宽度 | `min-width: 88rpx`（不写死 `width`） | 右侧可能是文字动作（「全部已读」），写死会把文字挤换行 |
| 动作热区 | 左右动作 `≥ 88rpx × 88rpx` | 44×44px 可点下限 |
| 标题定位 | **`position: absolute; left: 50%; transform: translateX(-50%); width: 100%`** | 标题必须相对**屏幕**居中，不能相对「扣掉左右区之后的剩余空间」居中。`width:100%` 不能省，否则 `left:50%` 会让可用宽度只剩半屏 |
| 标题宽度上限 | `max-width: calc(100% - var(--nav-reserve, 0px) - var(--nav-reserve, 0px))` | 对称兜住两侧。**统一用两次减法，不写 `2 * var(...)`**——但理由是「写法统一、避免与 `var()` 混写时的心智负担」，**不是兼容性**：`calc(2 * 10px)` 属 CSS Values 3（§8.1.2「At `*`, check that at least one side is `<number>`」），IE9 起即支持；Values 4 新增的是两个长度相乘（`calc(10px * 5px)`，结果是无意义的 px²）。⚠️ **这条曾被我误判为「兼容性红线」并写进规范，已撤回**——如果你在别处（或旧版本本文档）看到「calc 不能写乘号 / 需要 Chrome 111」之类说法，**以 W3C CSS Values 3 §8.1.2 为准**。留这句是为了让下一个人遇到这个 myth 时知道它已被证伪过，不必重新「发现」一次 |
| 两个 reserve 值不同 | `action = win - padRight - capsuleLeft`（右区 margin）；`title = win - capsuleLeft`（标题对称上限） | 两者相差一个 `padRight`。**若拿 `action` 当对称上限**，标题盒右边缘会比胶囊左边界多出 `padRight`（375px 屏 12px），长标题最后几个字钻到胶囊底下。375px 屏：`action=82`、`title=94` → 标题盒 94..281，正好贴边不越界 |
| 标题长度上限 | `capsuleAvoid` + 右侧动作同时存在时，**标题 ≤ 8 个全角字符** | 标题盒 94..281（187px）与右区动作盒 237..281 有 **44px 重叠区**，动作区 `z-index:2` 压在上层。**`ellipsis` 救不了这个场景**——省略号在盒边界（281）截断，而重叠区在盒**内部**（237..281），被盖住的字既不会出省略号也不会消失，用户看到的是**断字**。所以后端下发标题的页面必须在页面侧截断，不能指望组件兜底。当前命中此约束的只有 2 屏：`staff-detail`（分享图标，标题取 `staff.name`）、`message`（「全部已读」文字，标题「通知与提醒」80px），均安全 |
| 后端标题的页面侧截断 | 页面 `computed` 里截断，**不要传原始字符串给 `title`** | 组件无法判断「这个标题会不会被动作区盖住」，只有页面知道自己的标题来源。示例：`const navTitle = computed(() => truncate(detail.title_snapshot, 8) ?? '新人问卷')`。**注意区分**：`questionnaire` 属于下面「单侧内缩变量」行的「贴屏幕边」问题（无右侧动作），不是本行的「被图标盖住」，它的修法是补非胶囊页的内缩量（12px），**不是截断** |
| 截断 | `overflow:hidden; white-space:nowrap; text-overflow:ellipsis` + `min-width:0` | 导航标题永不换行 |
| 单侧内缩变量 | **代码当前名 `--nav-reserve`**，由 `barStyle` 写到 `.nav__bar` 行内 | 它承载的语义是「标题单侧总内缩量」，**不是**「胶囊预留」——名不符实，已登记改名为 `--nav-inset`，但要**等 QA 独立验证跑完再动**（此刻改名会让其 grep 直接失效，返工成本 > 命名收益）。取值：**胶囊页** = `windowWidth - capsuleLeft`（=94 @375，见上一行）；**非胶囊页** = `padRight`（`uni.upx2px(24)` = 12）。⚠️ 曾经的实现在非胶囊页取 `0px` → 标题盒 `0..W`，**绕过 `.nav__bar` 的 12px padding**，长标题贴屏幕边（flex 版本有 padding，absolute 版本丢了，属回退）。降级路径：若基础库不支持行内 CSS 自定义属性，变量缺失 → `var(..., 0px)` 取 0 → `max-width` 退化成 `100%`，后果是长标题可能压到胶囊，**不会破坏布局**，属可接受降级 |
| 胶囊避让 | `getMenuButtonBoundingClientRect()` 精算，取不到回退 `var(--nav-capsule-reserve)`（200rpx） | **避让只约束右区，不得改变标题的居中基准**。`--nav-capsule-reserve` 是兜底值（H5 / 非微信端 / API 异常）；真机看到 100px（=200rpx@375）说明精算没生效，那才是 bug |
| 占位块 | 仅 `fixed && isSolidState` 渲染 | `transparent` 与 `scroll-solid` 未过阈值**不能占位**，否则 hero 被凭空推下 `statusBar + 44px` |
| 层级 | `z-index: 99` | `> chip-bar`(50) / `sticky-holder`(50) / `bottom-bar`(90)，`< app-tabbar`(100) |

**变体（`variant` × `tone` 两个正交维度，不设第 4 个枚举）**

| 组合 | 背景 | 描边 | 标题/图标色 |
| --- | --- | --- | --- |
| `solid` | `--c-surface`（`background='page'` 时 `--c-bg`） | `1rpx solid --c-line` | `--c-ink` |
| `transparent` + `tone=dark` | 透明 | 无 | `--c-ink` |
| `transparent` + `tone=light`（沉浸深色） | 透明 | 无 | `--c-on-dark` |
| `scroll-solid` 未过阈值 | 透明 | 无 | 按 `tone` |
| `scroll-solid` 过阈值 | 同 `solid` | 同 `solid` | 强制 `--c-ink` |

过渡：`background-color` / `border-color` / `color` 三项，`var(--dur-base) var(--ease-out)`。

**职责边界（什么不该由头部组件做）**

1. 不监听滚动（`scrollTop` 必须页面传，避免每帧 `setData`）；
2. 不画 tabbar / 吸顶页签（`app-tabbar` / `sticky-holder` 的职责）；
3. 不做 hero 大图与遮罩（页面自己绝对定位）；
4. 不做搜索框、分段器、头像、步骤条（属于内容区首块）；
5. 不做登录态判断与权限拦截（路由守卫的职责）；
6. 不重写返回链路（默认只有一条：栈深 >1 → `navigateBack`，否则回首页 tab）；
7. 不接管 `safe-area-bottom`；
8. 不接受任意 `class` / `style` 透传（会绕过 token 治理）；
9. 不渲染微信胶囊（系统绘制，组件只避让）。

**= UX 文档里的 `action-bar`**（同一个东西，别再建第二个）。全站 14 屏复用。

### 9.3 D5 金额契约（写进组件层的硬约束）

1. 页面**只消费服务端返回的 `amountDue`**（以及 `deposit` / `balance`），禁止 `*0.3` 这类比例运算；
2. 支付前断言 `deposit + balance === amountDue`，不等则**阻断并上报**（`report('api_error')`），不允许"先付再说"；
3. `price` 组件的 `content` 只接服务端字段或服务端字段的格式化结果，**不接受前端算出来的值**；
4. 展示统一走 `formatMoney`，页面禁止 `toFixed`。

## 11. 与 API 层的边界（来自 API 专家的 7 条事实，UI 侧必须遵守）

1. **单 token，无 refresh**：401 的动作是「清 token + 跳登录」，没有队列、没有重放。图鸟若自带
   拦截器重试/刷新必须关掉，否则会出现双重登录跳转。token 存储键是 `app_token`，**任何 storage 封装都不要碰它**。
2. **不要绕过 `src/request`**：信封解包、26 个 errorCode 映射、GET 重试、并发去重、loading 引用计数、
   `Idempotency-Key` 都在里面。图鸟组件需要请求时注入我们的 `request`。
3. **分页不用图鸟 / z-paging 自带分页**：后端 4 种分页形态由 `normalizePage` 归一，统一等 `usePagedList`。
4. **v2 熔断是全局的**（已知坑）：`/v2` 命中 404 会把 `v2Available` 设成会话内不可恢复；
   `api/order.ts` 的报价路径写错（`/v2/booking/preview` 应为 `/v2/bookingPreview`）会连带打掉
   v2/home、v2/me、v2/staff、v2/order。**联调时页面突然退化成一堆 v1 请求，先怀疑这个**，重启小程序再验。
5. **类型直接用** `@/api/types` 的 `StaffCardVO / PackageVO / OrderListItemVO / LoadPhase`；
   缺口字段是 optional 且带 F-xx/G-xx 编号，**不要打 `!` 或塞默认值假装有数据**。
6. **订单动作只认服务端 `actions` / `action_reasons`**，不按状态数字推导按钮；支付成功只认 `payStatus` 轮询。
7. **两条登录路径共用同一个 token**（`mnpLogin` 微信一键 / `login/account` 手机验证码），字段名不同；
   `is_new_user=1` 的补资料流程只在微信路径有。手机号入口的开关读 `GET /index/config` 的
   `login.login_way`，**不要硬编码**；验证码登录**不会自动注册**（设计稿 21 屏那句文案与后端行为相反）。

> `src/request/**`、`src/api/**` 由 API 专家维护，架构**不改**。这里只登记 UI 侧的消费约束。

## 12. 遗留风险

### R1 · 图鸟组件 ↔ 图标字体隐式耦合（高）
字体已接（D6）。风险转为：任何人"省体积"删掉 `readTnIconCss()`，26 个图鸟组件的内部图标会集体变空白方块。
验收时对用 tn 组件的页面检查「×」「›」「✓」三类图标。

### R2 · `--fs-xs: max(24rpx, 12px)` 未真机验证（中）
WebView 内核普遍支持，Skyline/老 X5 有差异。需 iPhone SE(320px) + 一台 Android 验正文/标签；
不支持时按 `tokens.css` 里「方案 B」注释切媒体查询（勿两套同开）。

### R3 · 全局样式靠构建期注入（中）
有人把 `vite.config.ts` 恢复成模板版，页面不报错但全站丢令牌。防呆已做（scss 编译失败抛错中断）。

### R4 · 衬线字体在 Android 回退（低）
`--font-serif` 是系统栈。价格/日期不能只靠 serif 表达层级，必须有字号差或标签兜底。

### R5 · tab 带参边界（低）
带条件进查档期必须走 `tabQueryStore`，别用 `setStorageSync`（跨会话残留）。

### R6 · 页面私有组件膨胀（低，持续恶化）
`src/components/` 由架构维护，新组件必须先进 §9 的契约表。

### R7 · 配图素材带 AI 水印（**阻塞，需决策**）
8 张原图右下角均有 `AI生成 WorkBuddy` 水印，且为 AI 生成。压缩无法消除。对外发布前必须换真实拍摄素材。

### R8 · 主包已用 64%（中）
936.6 KB / 1.4 MB。再进约 290 KB 就会撞主理人 1.2 MB 红线。新增静态资源或大依赖前先跑
`node scripts/validate-mp-weixin-main-size.js`。

### R9 · 闸门脚本与图鸟图标集（已修）
`scripts/check-pages.mjs` 的图标名校验原先只认 uview 图标集，页面迁到 `<tn-icon>` 后会把
`my` / `moments` / `check` 误报成「图标不存在」。已把图鸟图标集纳入白名单（两套之一存在即放行）。

## 13. 给前端工程师的 12 条硬提醒

1. tab 页用 `<page-shell :tabbar="true" current="/pages/...">`，`current` 必须与 `pages.json` **完全一致**，否则不高亮。
2. 吸底栏用 `bottom-bar` + `page-shell` 的 `bottomBar`，不要自己写 `position: fixed; bottom: 0`。
3. 颜色只用 `var(--c-*)`，字号只用 `var(--fs-*)`，间距只用 `var(--sp-*)`，圆角只用 `var(--r-*)`。写死会在 `redesign-zero-check` / `redesign-ac-check` 里被抓。
4. **设计稿 CSS 变量名不能直接用**：认 §4 映射表。`--gold-2` 用 `--c-brand-soft`，`--clay` 已驳回（用 `--c-brand-text`）。
5. **字号有下限**：设计稿 < 13px 的字号一律 `--fs-xs`（24rpx），换算表不是授权你写 18rpx。
6. 金色 `--c-brand` 不能做正文色（对米白 2.25:1）；文字用 `--c-brand-text`。
7. 标签选择器一律 `chip-group`（两档），不要第 3 种 chip。
8. 吸顶用 `sticky-holder` + 页面 `onPageScroll`，不要 `position: sticky`。
9. 金额用 `price` 且只传服务端字段（D5）；不要 `toFixed`。
10. 协议勾选用 `agreement-check`（D4）：默认未勾、按钮不置灰、错误红字在行下。
11. 配图用 `@/config/images` 的 `IMG.*`，不要写 `/static/images/xxx.jpg` 字面量。
12. 新增页面：先建 `.vue`，再找架构登记 `pages.json`（独占文件）。提交前跑
    `npx uni build -p mp-weixin && node scripts/validate-mp-weixin-main-size.js && node scripts/check-pages.mjs`。
